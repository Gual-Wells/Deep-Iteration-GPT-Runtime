# DIGR Codex Stable 1.5 — 执行协议

当前原始调用、实际用户决定和冻结的 `P_run` 贯穿一项任务。[STARTUP](STARTUP.md) 定义获取和恢复入口。此前任务沿各自的发布版本恢复，当前仓库的重新获取不改写执行 pin。

[原语宪法](CONSTITUTION.md) 适用于整个执行及 DIGR 自身更新。

## 理解委托，形成 U0

按 [FOUNDATION](FOUNDATION.md) 研究实际用途、成品、粒度、已有基础和决定结果的困难。用户已明确给出的取舍直接采用。确实影响成品或主要投入、且没有既定决定的分歧，给出具体选择再询问；可独立完成的工作继续。只在需要时做代表性试作。用户原话、方案解释、费用决定、内容授权与实际执行分别有真实来源。

* 同一未结束任务中的补充、纠正、追问和恢复沿原 `P_run`。精确 `DO:` 或 `DO：` 直接接入当前任务。当前原始输入命中 DIGR 路由的补充仍须真实获取仓库，然后按原任务处置。
* 目标、结果或实质路线改变时更新 U0，把新委托落到受影响的产物、依赖和下一动作。未改变的已授权工作继续；旧决定留作出处。明确暂停、恢复、停止或取消按用户实际范围生效。
* [PERMISSIONS](PERMISSIONS.md) 定义授权和限制准入。模型计划和历史建议不会自行成为硬前置。已结束任务需要新的有效调用才能再次建立工作。

正式生效正数 [F](PARAMETERS.md#f-公开社区项目先研) 时，Main 先把它绑定到有待选定的方案或制作路线，及早进入公开社区，研究足量高评价、有特色的项目，并把所学用于受影响的取舍。需求核对、可逆比较和无依赖的工作照常进行。多条主线共用项目记录，任务总数去重，实际采用与缺口随相关决定呈现。

F 达额后，受影响候选的具体借法继续参与生产。实际生产者取得与本线当前产物有关的原件、构造与条件，在相关候选、反馈和恢复中继续使用、重研或放弃，并落实到产物和判断。共享计数不等于各线共享采用方案，独立初次形成与同一候选续作按 COLLABORATION 区分。保存记录与宣布借鉴各有用途，不能代替实际作用；按 PARAMETERS 与现有 S/N/V 衔接，不另建内化评分或常驻项目队伍。

## 主动寻找值得投入的机会

Main 依据用户用途、原件和已有候选，主动找能给交付带来更好判断或作品的独立意见和原生研究。在方向还可改变时，如果已有一项具体发现及相称的探索办法，优先迈出有边界的一步。说清这一步可能改善什么、为什么能触及它。开放探索可以从材料中有潜力的细节开始，具体改变随工作显现。

取得新材料、意见或候选后，以当前未决问题判断下一步的贡献。请教看 Claude 在实际角色里能带来什么，调参看原生还可承担什么。已有工作足以回答时，把所得用于成品并收束相应投入。在现有的前置、INIT、再入或主线处理时简明说明实际理由。当前用户决定、角色、预算和时限各按原有范围生效。

## 组织原生研究与生产

确认委托后，Main 按 [PARAMETERS](PARAMETERS.md) 参考所选档位与实际工作，在正式 INIT 前推断各线完整的生效配置。未选档位时参考 Default。用户显式声明的参数与实际限制按其范围生效。Main 说明参数取舍并对事实、执行与整体交付负责。按 [COLLABORATION](COLLABORATION.md) 组织真实分开的 D/V、必要的再入和多条完整 Main。保留中心主张、理由与实际后果。工具和代理数量只证明各自发生的行为。

[METHOD](METHOD.md) 定义分析成立、实验使用和工程检查的条件。[CHARACTER](CHARACTER.md) 展开研究、制作与解释的质量要求。按用户用途研究有竞争力的完整候选，让有力的反例和实际原件改变判断及制作。

Codex 继承当前实际模型与推理设置。预计是超巨量批量任务时，Main 可在整体验收结构明确且批次可独立核验的情况下考虑多档协作。大部头辅学书可把整书结构、代表章及总校验与规格稳定的分批加工分开。是否这样做取决于实际收益。旧 Allot 只由旧 pin 续用。

## 采用 Claude 的两层参与

| 调用 | 可采用的角色 | 费用依据 |
| --- | --- | --- |
| `DIGR：任务` | 第一层，在能影响成品的取舍定案前安排一次独立首发。可按实际需要开展议会研究。 | 当前选择直接授予额度内使用。第一层每任务累计上限为 0.20 美元。 |
| `DIGR：：任务` | 第一层与第二层，按实际委托及需要采用。 | 当前选择直接授予额度内使用。第一层每任务累计 0.20 美元，第二层累计 1.00 美元，各层独立记账。 |

当前用户选择、任务作用域、真实钱包及用户给出的更窄限额共同约束发送。额度内直接使用，发送前按实际价格预留保守上界。ASCII 与全角冒号等价。旧 DIGRC／DIGRP 拼写作为兼容输入，采用相同分隔规则。普通补充继承当前选择，完整新头部或当前明确意思可以调整。停止、撤回或限额立即生效，切换入口沿同一任务账目继续。

1. **第一层 [子议会](COUNCIL.md)**。原生初议与 Claude 子议会形成独立材料。Claude 可以重划问题，发现会改变判断的细节，或者委托 Codex 取原件、核对、复算和试作。同一 Claude 成员取得实际结果后继续判断。达到各自阶段终点后，原生议会读原文、再议并自主确定路线。Main 忠实传递材料、落实结果并处理返回。
2. **第二层 [内容指导或制作](CONSULT.md)**。按实质委托区分指导和正式产出。仅请 Claude 对目标、粒度、结构或路线给指导时，将有效指导落实到相关取舍。Claude 受托完成可验收结果时，Main 在首次正式请求前实际派发同一对象的原生 L3 产出责任。原生与 Claude 各交一份独立、同范围的可用结果，两份齐备后都交给 Claude 作该对象的实质终裁。Main 依当前要求、事实和资源落实裁决并核对实际交付。Sonnet 实际承担完整论文读物时，同时接入同 pin 的[论文增量](../paper/PROTOCOL.md)。

### 单冒号任务的独立首发

本版新任务在当前选择为单冒号时，Main 形成 U0 后就主动找可能实质改变交付的开放取舍，并在定案前沿已有许可发起一次首发。带着有潜力的问题就可以请教，Claude 可以帮助形成可比较的选项。需要先读原件或做可逆试作才能触及取舍时，在具体决策节点启动。取舍已由用户决定或实际前提确定时，沿该决定直接推进。这个责任覆盖只读研究和短任务。

Main 提供真实用途、待定事项、已接受约束和必要原件，同时让原生初议独立推进。Claude 可自行选择决定性的议题、改划问题，先给出足以影响取舍的明确立场，再展开支撑理由。原生议会取得可用原文后实际再议，Main 按当前委托与原件落实并说明成品后果。通过 [COUNCIL](COUNCIL.md) 的入口登记每任务唯一一次独立首发。若首发确实委托原生工作，沿实际请求和结果同线续答，费用计入同一第一层。接续、输入修订和恢复沿用实际记录。

等待限于可被首发改变的决定，原件工作、可逆试作和其他已获授权的工作继续。按真实决定窗口设置期限，议会默认 300 秒。无实质取舍、暂待具体节点、当前余额或权限不足、用户撤回、公开正文缺失或超时，都按实际状态交代并处理相关决定。需要时由原生议会按可用材料作出决定，迟到原文仍可进入相关再议。发现新的实质研究责任时，按普通议会及第一层余量判断。

两层每次实际提交均由 Codex 在本机 [Split](SPLIT.md)，准备足以回答问题的原件，把可由工具完成的生产留在本机。费用预留、一次发送、公开转播及对账按实际角色共用服务。准备、获准、已发和完整公开返回各有不同事实。

双冒号直接许可第二层角色，实际内容委托决定是否启动正式产出。Main 及早识别各层能贡献的具体工作与决定，按实际任务范围和层内余量推进。在真实派发和提交入口执行上述角色区分。共同作用域随当前用户要求冻结，材料变化、角色撤销或停止依实际范围处理。等待候选或终裁只约束依赖该结果的工作。

## 在对话中推进，按真实结果交付

[LIVE](LIVE.md) 是中间流唯一呈现规范。工作单元实际发生时，在 commentary 显示责任、阶段和所得。独立返回和 Main 采用、拒绝或待落实分别可见。外部公开增量按来源及时原文转播。恢复从当前未报告处继续，真实缺报留作缺口。

第二层正式产出按实际发生显示原生派发、双方完整返回、Claude 终裁和 Main 落实的具体后果。准备记录、暂收部分正文及未应用的裁决各保留自身状态。未完成的对象以待决或部分结果呈现；按用户实际决定交付降级结果时保留其来源和决定。

[X 文件交付](DELIVERY.md) 只作用于当前任务选中的最终文件。X、F、C同属正式参数组，并各按任务级责任保存。`X=0` 选择本聊天，`X=1` 选择本人 Gmail；兼容 `(X)` 与 `(X=Gmail)`。任何档位的 X 参考值均为0，外发由实际显式选择启用。无文件时仍可正常返回。发送前保留实际候选和尝试身份，结果未知先读回，保持作用域与内容身份。

本版实际C1的任务，在各项生产与研究责任完成后执行必读 [怀疑审判议会](COURT.md)。法官、书记员、公诉人、被告人、控方律师、辩方律师与监庭黑警从原始要求、前文条件、全过程和当前产品审理。公诉覆盖初始提示词的意图理解及其对提出、维持、执行、判断、默认取舍和忽略的影响。书记员主动收集检索原件，维持证据一致性及长流程公开推理与审判记录。黑警是面向全体一视同仁的暴力威慑与庭审威严来源，不承担正义警察式监督角色。成立问题重新估算完整自定义参数，实际再执行并复审；直到当前判为无罪或执行误差不致罪，书记员完成当前全程案卷后，才进入最终交付与 RETURN。C独立于生产档位；同任务省略C继承，仅真实用户显式C0撤销余下庭审并保留原记录。缺少形式化、测试或实验本身等被本 pin 排除的默认偏好，不能换名成为罪名。X1 的最终候选先审，之后完成实际发送与读回。

真正完成后按 [RETURN](RETURN.md) 把五段报告直接发到对话，处理当前输入和待交付项，结束真实活动，附 [USAGE](USAGE.md) 的任务内 Claude 美元及原生模型／effort／速度和额度观测。只对有明确分母和覆盖的读数作比例或近似；其余留未知。完成返回或用户明确终止收口任务。已有的纸面、知识、个人上下文、英语语音和 ESP 入口见 [WORKBENCH](WORKBENCH.md)，按实际用途与各自契约启用。

每层实际U0之后，按FOUNDATION执行短协议自提醒，重新注意本层LIVE、独立性、公开转播、权限费用及收口/接续。新任务Max默认C1，其余档C0，显式C优先；同任务换档不重设C。完整调用见HELP，正式记录见PARAMETERS。
