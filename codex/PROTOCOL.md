# DIGR Codex Stable 1.1 — 执行协议

当前原始调用、实际用户决定和冻结的 `P_run` 贯穿一项任务。[STARTUP](STARTUP.md) 定义获取和恢复入口。此前任务沿各自的发布版本恢复，当前仓库的重新获取不改写执行 pin。

[原语宪法](CONSTITUTION.md) 适用于整个执行及 DIGR 自身更新。

## 理解委托，形成 U0

按 [FOUNDATION](FOUNDATION.md) 研究实际用途、成品、粒度、已有基础和决定结果的困难。用户已明确给出的取舍直接采用。确实影响成品或主要投入、且没有既定决定的分歧，给出具体选择再询问；可独立完成的工作继续。只在需要时做代表性试作。用户原话、方案解释、费用决定、内容授权与实际执行分别有真实来源。

* 同一未结束任务中的补充、纠正、追问和恢复沿原 `P_run`。精确 `DO:` 或 `DO：` 直接接入当前任务。当前原始输入命中 DIGR 路由的补充仍须真实获取仓库，然后按原任务处置。
* 目标、结果或实质路线改变时更新 U0，把新委托落到受影响的产物、依赖和下一动作。未改变的已授权工作继续；旧决定留作出处。明确暂停、恢复、停止或取消按用户实际范围生效。
* [PERMISSIONS](PERMISSIONS.md) 定义授权和限制准入。模型计划和历史建议不会自行成为硬前置。已结束任务需要新的有效调用才能再次建立工作。

## 组织原生研究与生产

确认委托后，Main 按 [PARAMETERS](PARAMETERS.md) 参考所选档位与实际工作，在正式 INIT 前推断各线完整的生效配置。未选档位时参考 Default。用户显式声明的参数与实际限制按其范围生效。Main 说明参数取舍并对事实、执行与整体交付负责。按 [COLLABORATION](COLLABORATION.md) 组织真实分开的 D/V、必要的再入和多条完整 Main。保留中心主张、理由与实际后果。工具和代理数量只证明各自发生的行为。

[METHOD](METHOD.md) 定义分析成立、实验使用和工程检查的条件。[CHARACTER](CHARACTER.md) 展开研究、制作与解释的质量要求。按用户用途研究有竞争力的完整候选，让有力的反例和实际原件改变判断及制作。

Codex 继承当前实际模型与推理设置。预计是超巨量批量任务时，Main 可在整体验收结构明确且批次可独立核验的情况下考虑多档协作。大部头辅学书可把整书结构、代表章及总校验与规格稳定的分批加工分开。是否这样做取决于实际收益。旧 Allot 只由旧 pin 续用。

## 采用 Claude 的两层参与

| 调用 | 可采用的角色 | 费用依据 |
| --- | --- | --- |
| `DIGR：任务` | 第一层，实际外部研究有价值时可参会。 | 现有共享钱包的真实可用余额及用户当前更窄限制，覆盖即可使用。 |
| `DIGR：：任务` | 第一层与第二层，按实际委托及需要采用。 | 付费前说明拟用角色、任务范围和保守费用上界，取得实际用户决定。同范围有效决定可沿用。 |

ASCII 与全角冒号等价。旧 DIGRC／DIGRP 拼写作为兼容输入，采用相同分隔规则。普通补充继承当前选择，完整新头部或当前明确意思可以调整；停止、撤回或限额立即生效，旧批准不会因重新打开而恢复。

1. **第一层 [子议会](COUNCIL.md)**。原生初议与 Claude 子议会形成独立材料。达到各自阶段终点后，原生议会读原文、再议并自主确定路线。Main 忠实传递材料、落实结果并处理返回。
2. **第二层 [内容指导或制作](CONSULT.md)**。按实质委托区分指导和正式产出。仅请 Claude 对目标、粒度、结构或路线给指导时，将有效指导落实到相关取舍。Claude 受托完成可验收结果时，Main 在首次正式请求前实际派发同一对象的原生 L3 产出责任。原生与 Claude 各交一份独立、同范围的可用结果，两份齐备后都交给 Claude 作该对象的实质终裁。Main 依当前要求、事实和资源落实裁决并核对实际交付。Sonnet 实际承担完整论文读物时，同时接入同 pin 的[论文增量](../paper/PROTOCOL.md)。

两层每次实际提交均由 Codex 在本机 [Split](SPLIT.md)，准备足以回答问题的原件，把可由工具完成的生产留在本机。费用预留、一次发送、公开转播及对账按实际角色共用服务。准备、获准、已发和完整公开返回各有不同事实。

双冒号许可第二层角色，实际内容委托决定是否启动正式产出。Main 必须在真实派发和提交入口执行上述区分。共同作用域随当前用户要求冻结，材料变化、角色撤销或停止依实际范围处理。等待候选或终裁只约束依赖该结果的工作。

## 在对话中推进，按真实结果交付

[LIVE](LIVE.md) 是中间流唯一呈现规范。工作单元实际发生时，在 commentary 显示责任、阶段和所得。独立返回和 Main 采用、拒绝或待落实分别可见。外部公开增量按来源及时原文转播。恢复从当前未报告处继续，真实缺报留作缺口。

第二层正式产出按实际发生显示原生派发、双方完整返回、Claude 终裁和 Main 落实的具体后果。准备记录、暂收部分正文及未应用的裁决各保留自身状态。未完成的对象以待决或部分结果呈现；按用户实际决定交付降级结果时保留其来源和决定。

[X 文件交付](DELIVERY.md) 只作用于当前任务选中的最终文件。`(X)` 与 `(X=Gmail)` 均选择本人 Gmail。无 X 在当前聊天交付；有 X 无文件时仍可正常返回。发送前保留实际候选和尝试身份，结果未知先读回，保持作用域与内容身份。

真正完成后按 [RETURN](RETURN.md) 把五段报告直接发到对话，处理当前输入和待交付项，结束真实活动，附 [USAGE](USAGE.md) 的任务内 Claude 美元及原生模型／effort／速度和额度观测。只对有明确分母和覆盖的读数作比例或近似；其余留未知。完成返回或用户明确终止收口任务。已有的纸面、知识、个人上下文、英语语音和 ESP 入口见 [WORKBENCH](WORKBENCH.md)，按实际用途与各自契约启用。
