# Split：每次 Claude 提交前的本机原生分工

按 [PROTOCOL](PROTOCOL.md) 核对本次角色、当前用户选择和相应的费用许可。每次实际 Claude 推理提交前均在本机运行一次 `Split`。首次、公开上下文续调、内容再入与补料后的提交都适用。第一层为原生议会准备成员研究所需的共同事实与原件，保留其独立性和同线身份。第二层把明确的内容取舍或制作交给 Claude，Codex 完成取材、分工和工程准备。预览及拆分记录只支持本次请求的提交检查。

Split 的智力主体是当前 Codex 原生模型。它以本次准备提交的真实任务为对象，研究怎样让可承担的 token 消耗留在 Codex，同时让 Claude 对本任务最有价值的智力工作充分展开。Python 不替模型作内容判断，也不另调 Claude 来决定怎样节省 Claude。公开分工摘要、实际本机成果与工具绑定共同组成这次函数调用；单独填表不等于完成研究。

## 按当前任务研究与落实

从用户当前用途、纠正、实际原件、既有本机成果、有效公开指导和仍需的决定出发，比较会改变结果的分工。Codex 能取得或完成的检索、提取、去重、事实核验、复算、数据与文件操作、批量变体、工程实现、排版和交付，通常留本机；先完成决定本次 Claude 工作所需的部分，其它有价值的本机工作可继续并行推进。

把 Claude 用在本次真正值得委托的问题：内容构形、重要概念的贯通、强替代、论证、创作声音、稿件或其它由任务材料显示价值的工作。具体分割根据当前作品、材料与往返结果形成，不建立固定能力排行榜，也不以“Codex 会做”取消已有的 Claude 内容关系。技术设计、代码推理、调试思路和实现说明本身可能正是用户要的内容，仍可由 Claude 发展；实际工具操作由 Codex 承担。

子议会成员可以据自己发现的问题请求 Codex 支持。先完成本机工作并保留真实结果，再把当前请求需要的原文片段、复算、试作或失败事实送回原成员。返回应让 Claude 能核对和继续它自己的判断。用范围和往返取舍控制费用，为原成员的实质推理和公开输出留出空间。

本机研究应形成可用选择并进入任务包。不要把全部研究史、日志、内部协议、角色计数、CLI 工单和等价版本让 Claude 重读；也不要先在本机锁死结论、结构和章节后只让 Claude 润色。原生和外部作者独立形成问题、读序、结构和内容。各自可提出新问题、反驳其它候选、请求更多原件或直接成稿，实际产出按 CONSULT 及论文协议比较。

本机有价值的研究成果也不必整份传出。保留能改变本次判断的发现、决定性原段与必要推导，反复摘录、已核过的中间草算和制作说明可留本机；实际需要现成推导或整稿时提供它。以Claude接下来要完成的内容决定传入粒度，不能只追求最短输入，也不把每份本机笔记自动变成附件。

最小充分任务包以质量与约定职责为约束。给真实当前要求、必要原文/图、局部记号、决定性上下文、相关现稿及明确的问题；摘要保留身份，不冒充原文。某次需要完整论文或长稿，就提供它。不得为了更短而丢定义、反例、用户纠正、范围、已有有效指导或 Claude 独立判断所需材料。模型、effort 与有效输出能力不因节省 token 暗降；不以固定比例或调用次数替代任务判断。

原件定位、PDF/OCR提取、正文与Markdown整理、公式转写、图表裁取、文件组装及调用工程由Codex承担。优先提供可读正文与可靠的文字公式；必要图表、不能可靠转写的局部及明确视觉任务再传图。有可提取文字的整篇论文不默认逐页截图交给付费模型。文字提取若损失原式或布局关系，就回到相应原图补足，不能为少token损失原件信息；材料准备不替Claude决定内容与讲法。

公开历史增长也属于分割对象。确需逐字历史时沿原 `--continue-from`；不需要全量重放时，可按同篇/同任务另开交换，明确提供标为本机摘要的有效指导、原稿片段、当前要求与相关原件。旧公开交换保留并引用实际来源，不把摘要称作逐字接续，不跨论文续错上下文。工具不自动删改已有历史。需要新交换时，本机做此选择并准备实际任务包，Split 仍绑定新的完整请求。

借用 DIGR 的原则是认真研究、竞争路线、受材料纠正、落实后果和有据收敛；不在每次调用里递归启动另一套 FOUNDATION、N12/R4/D3/V3、代理或计时体系。投入随本次分割的真实难度决定。已经能说明分工、完成必要本机工作并给出充分任务包，就可提交；不额外要求效果实验或终审批示。

## 一次提交的本机操作

1. Codex 完成本次原生 Split 研究和必要本机工作，准备实际给 Claude 的自然任务、正文和图片。`consult prepare` 保存完整候选请求，不发送。
2. `consult split --root TASK --exchange-id ID` 读取当前候选，返回本次 `binding`、全部公开上下文的字节/图片概况和计划字段。依据实际请求写私有 `split-plan.json`：公开决定与理由、本机已完成工作和结果、Claude 本次价值、上下文取舍。需要引用本机成果时提供实际路径及已观察的 SHA256；没有合适的本机先做工作时明确理由，不造无用工序。
3. `consult call ... --split-plan split-plan.json` 在发送前本机调用一次 `runtime.codex_split.Split`，核对同一任务、当前用户输入、请求、论文作用域与所选本机成果。缺少/过期计划、改变的绑定或成果不能发送；预算、模型、凭据与单次尝试边界继续执行。Split 不联网，不消耗额外付费推理，不把私有计划传给 Claude。
4. `consult inspect` 保留该次 Split 记录与实际推理结果。Main 认真处理 Claude 返回，完成本机后续工作；下一次提交重新研究受影响的分工，绑定下一份请求，不能用本次计划跨请求抵扣。

实际外部公开消息和正文增量到达时，在当前对话按原文及时转播并标明来源；可合并相邻短片段，不等整份完成，不以本机摘要或日志替代。连接状态、尚未完成正文与完整返回分别说明，隐藏思考不属于公开正文。Split不改变这项交互责任。

原生分工与 `consult split` 的绑定预览不同；后者不执行模型研究。`Split` 的通过只说明公开记录与字节身份匹配，不认证分工质量、本机所有工作确实完成、指导已落实或节省了多少 token。语义责任在模型，公开记录不保存隐藏思考。实际服务用量与费用沿原 ledger；字节数不换算为测得 token，未做对照不填写节省率。

推荐把原生判断只写一次：`consult split --root TASK --exchange-id ID --input native-decision.json --out split-plan.json`机械附加当前format/binding并检查所选证据，免手工复制不透明字段；不生成分工理由。输入只含原生决定、本机工作、Claude价值及上下文取舍，不能带旧format/binding。证据相对路径按输入文件所在目录解析并固化为绝对路径；输出换目录不改变身份，已有输出不覆盖。此命令仍不执行Split提交检查，`call`才运行一次该函数。

0.13起的通用协作任务包也自动保留任务原话及当前用户消息的精确公开正文和来源身份，不能仅给含糊的本机转述却绑定一条未传入的纠正。同次或实际重放的上下文已包含相同正文时，以公开正文SHA256引用去重；本机工作问题另有身份。此项不自动整理历史中间决定，仍由本机Split按实际有效关系选入。

调用和私有计划的完整合成示例见 [Split 示例](examples/split/README.md)。日常任务不要求逐文件批准；只有实际用户范围、预算和停止边界继续约束执行。

本层若实际形成、修订或恢复U0，随后执行FOUNDATION短协议自提醒，注意当前公开流、模型条件、内容/工程分工及费用绑定；逐次绑定本身不新增U0。
