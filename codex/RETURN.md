# 默认返回与任务收口

这是每次 EXECUTING 必读的执行语义，不依赖模型事后想起 WORKBENCH。按用户用途交付完整结果，保留一个当前入口。纯研究的论证、选择或说明可以就是成品，不强制造软件或附件。

## 在结果里看见真正改变的东西

先给结果及入口，再用少量公开事实说明关键所得、分歧及后果。收到、决定、落实是不同事实；有依据的拒绝或保留也可以是完整处理。没有落实的采用声明仍是待办。重要限制要直接可读，不能藏在点按详情中。

深执行默认附时间横轴、X_i纵轴的流程总图及可选细读入口；静态图能独立阅读。只有已记录且可比的事实才落到时间轴，U0与正式工作分开；未知时刻、外域时间、未处理结果保持显式未知。记录不足时交付标明 PARTIAL 的选定事实图或简洁文字回退，不能编造整齐的全流程，也不能为作图中断用户工作去建设全量追踪平台。结构示意必须标 illustration，不能冒充本次实录。图细节见 RETURN_VISUAL，渲染入口为 timeline。

图中 N/R/S/D/V/M 是有类型的工作标识，执行者、工作段、候选版本另记。标识延续不等于持续工作，跨度不等于有效 T/t。自举、议会、交流、再入、决定与落实只在实际有依据时标注；材料相关不画成执行因果。移动端提供每行可用的原生选择路径，重叠标记不能以遮挡决定点中了哪项；正常字号显示对象、版本、依据与直接关系。选中偏好绑定数据版本，只恢复展示，不产生调用、同意或执行授权。

不要求所有中间消息都绘图。澄清问题、等待用户决定和进度报告不是完成交付，也不消耗未完成任务的接续资格。明确完成、按约定阶段交付后结束，或停止/取消时才收口；暂停保留待恢复状态而禁止继续执行。

## 先核对当前候选，再结束任务

受管理的新会话把所交付的文字/文件、选定来源、现有 session/line/clock 状态及渲染输入绑定为当前返回快照。复用一份 WORK 与明确选定的事实，不自动采集所有聊天或隐藏推导。先结束真实开放活动，再 seal；核对 status 当前且无未处理闭环问题，才 close。相关输入或产物后来改变时快照为 STALE，重新核对及 seal 后才可交付。无需图时使用明确的文字返回路径。

return seal/status/close 是本地管理入口；READY 只说明选定输入/产物及磁盘工具源码、解析位置仍相符，不证明运行字节码身份、质量、意图、来源真实性或责任达标。close 必须真的终结任务生命周期，旧确认不能使已结束、STOPPED/CANCELLED 或待处理纠错的任务继续 begin/checkpoint。end/recover 始终允许用于安全收尾。0.8新会话用session-2阻止忽略生命周期的旧writer，旧 pin 保持session-1与原工具身份，不静默迁移。

## 准确归因与可接续范围

最终按 PARAMETERS 如实返回参数目标、实际责任、时钟已知部分与缺口。按实际执行片段区分 DIGR、普通轻量、原生 Goal、协议模拟/引用及请求 DIGR 但未实际执行；不能把整个聊天统一标成一个模式，也不能仅凭无前缀断言受过轻量规则约束。单次发布、测试全绿或哈希一致不证明跨项目效果。

有真实宿主事件时引用其接受结果及实际 turn 身份；turn/start 方法名、手填 expectedTurnId 或恢复线程不证明还活跃。没有事件时依据当前未完成任务和实际对话说明接续，不伪称全宿主拦截。Chat 等宿主共享意图、来源、停止与返回原则；没有独立上下文代理、时钟或持久文件时如实报告能力差距，不能把同一模型扮演角色标成 L3，也不能在未获选择时另建一套 Chat 通道。
