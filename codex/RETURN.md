# 返回正文与任务收口

0.16返回自动附USAGE中本任务保存的聚合观测和Consult账目，区分角色、已知美元、未知预留、任务内模型/effort份额与账户窗口百分点。缺数据时显示缺口，不以空白或0冒充测量。当前最终输出与迟到入账的覆盖边界须明确。活跃议会/原生再议责任与异常终态按COUNCIL处理，HTTP结束不能自动认证整体完成。

这是 EXECUTING 必读的执行语义。最终报告直接写在用户可见的response正文，固定五个二级标题和顺序：

1. **结果**：交付答案、判断或成品入口。正文独立可读，关键论据可以就在这里，不为分栏拆断论证。研究解释本身可以是成品。
2. **关键变化**：说明形成的认识、决定及实际后果。研究无基线时不虚构改前/改后；提议、已执行与已观察效果分清。
3. **工作过程**：正文Markdown时间／工作表，选择影响结果的研究、制作、异议、处理与落实。写真实区间、近似或未单列，不抄命令流水账，不为每个参数单位补造分钟。
4. **论证与适用范围**：说明支持判断的关键理由与真正影响结论的条件。理由与必要适用条件已在相关主张旁说明时，本段简短承接即可，不再为填栏补充限制。实际成品的检查在相关操作或状态需要说明时报告，不强制补写实验、效果观察或验证计划。
5. **参数**：按PARAMETERS返回目标／实际、T/t及补点缺口、P_run；责任数量由实际工作判断。

1.5.0及以后pin在参数段同时返回任务级X0或X1、F目标/实际和其生效依据。Max还返回当前庭审判决、实际返工配置与完成事实。

支持 F 的 pin 在参数段返回任务级 `F（目标/实际）`。目标大于零时，在工作表或相关决定旁列出各项目的社区评价与原件链接，以及该项目怎样影响了取舍。未达额时说明缺口、原因及仍属暂定的决定。

段内可自然成文，保留小标题、代码、表格和真实产物链接。短任务每段可以很短，不用空模板、无关检查或重复内容凑段。研究、工程和创作保留各自的论证与表达。

结果与关键变化先陈述结论和实际价值，再发展支持它的理由。分析以问题得到回答、论证足以支持结论为完成依据；缺少实验或现场试用本身不降低已成立判断的地位，也不生成例行免责收尾。保留真正改变结论的反例和未决前提，在相关主张旁说清一次，按PROTOCOL直接表达。

按本次实际采用的层报告工作和成品。第一层说明子议会主要主张、原生再议和如何落实。第二层说明实际指导或作者身份、影响的取舍及进入成品的内容。完成情况以实际交付和已处理的依赖判断。关键内容指导或制作未到达时，说明受影响的部分及已经完成的其他工作。

单冒号采用独立首发时，报告实际获得的公开观点、原生再议和 Main 落实的具体后果，费用随账目另记。发生 Codex 支持委托时，按实际说明成员请求、取得的结果、是否送回，以及 Claude 续答怎样影响交付。有实际发送却无可用立场、只获得截断正文或费用仍未明时，写清真实状态和对应取舍怎样完成。跳过或未能发送的原因可随真实工作过程交代。首发等待随本次决策窗口结束，已登记议会按 [COUNCIL](COUNCIL.md) 处置实际待项。

登记了双边产出时，返回沿用实际原生候选、Claude 候选、裁决及落实凭据。该对象的待决状态只影响相关完成主张，其他工作可以继续和报告。正常收口检查全部登记对象的实际落实或用户明确处置。只有可读裁决和任务记录还未落实时，仍保留待完成状态。

**禁止HTML/iframe/details内嵌页、附件卡、Page、文件截图、整份代码围栏或“请打开文件查看”替代报告正文。** 书、图、网页、代码等任务本来需要的成品可链接或展示；报告保存副本只补充追溯。时间图不再是默认要求，历史timeline工具按明确用途使用，不重新嵌成默认报告。

采用本版 F 持续转化规则时，结合决定结果的关键处说明具体所得如何进入产出，后续怎样继续使用、修订或被排除。F 数字只陈述项目计数，不认证内化或质量；引用、文件与采用声明的数量也不代替实际作用。沿已有工作表和产物说明，不再复制逐轮研究流水账，不补造未发生的后续使用。

## Max 当前庭审

本版实际选择Max的任务按必读COURT在原责任完成后接受全过程与产品庭审。return status/close核对当前需求和产品所对应的实际判决；须再执行、仅有返工计划、未决角色或已失效的旧判决均保留未完成。真实异常终止按实际范围记录，不能视为无罪。X1在最终候选通过后完成发送与读回，再进行正常收口。

法院角色、指控、答辩、监庭与法官理由来自实际研究，工具保存HOST_ASSERTED来源与版本关系。状态字段、文件和工具通过不能替代语义判断。旧pin继续原返回契约。

## 最终文件与X

0.9新任务的返回输入中，`artifacts`声明真正对用户交付的文件；也可用`delivery_files`补充实际成品文件。它不能省掉已声明的文件成果。来源、私有记录与内部材料留在`sources`，不因此自动外发。

X0时本地成品完成即可返回；X1但没有文件也可正常结束，不强制发总结或制造附件。有最终文件且选X1时，所选文件必须由任务共同delivery ledger保留发送前边界并有当前有效的指定渠道读回；多篇论文各用本篇候选ID，父RETURN复用这些实际交付，不再发送一遍。文件更改使旧回执不代表新版。

撤销外发后，本地返回与既往发送结果分别说明；不能把尚未查明的旧发送写成未发或已核验。送达记录不证明用户打开或理解。旧pin及历史论文包维持当时交付契约。

## 共同访时，收尾统计

所有实际参与者含D/V向同一文件追加Begin/End，以run_id、actor、line、phase、category分组。任务只关联文件位置与分组，不携带运行中timer状态；普通记录不以PID、进程锚、单调钟身份或连续性证书为接收门槛。

**T是WORK+SOURCE区间并集，t是SOURCE区间并集。** 并行重叠只计一次，D/V照计；META、排队、等待和空闲不计，等待前结束活动。FOUNDATION与EXECUTION分开；每M统计本线所有参与者，全局再并集，COMMON只进全局不反填各线。

缺End、重复Begin、坏行和倒退时刻局部保留，其它配对照算。新Begin不替旧段闭合，未闭合尾段不延到现在。收尾有可见依据时追加近似补点：指向原Begin，标approximate/basis，分开有效结束时刻与实际补录时刻；无依据留缺口，不覆盖原记录。按事件身份去重。默认只报一对含已接受补点的T/t、补点数与未解缺口数，工作表说明相关近似与依据，不强制两套总值或精度评分。

T/t表示登记覆盖，允许打断和长上下文扰动，不认证每秒活动或完整历史；缺单调钟身份不使它整体无效。硬下限仍保留原意，不改软、不靠等待补足；记录明显不足的范围如实写未验证。

schema-2正文的规范第四字段为`argument_scope`。为读取旧输入，工具仍接受旧字段`verification_limits`和旧标题；同一输入二者互斥。新任务采用本版规范，旧pin及旧分发继续原返回契约，不改写历史回执。

## 保存正文，真正发回

`return seal/status/body/close`保存并核对选定五段Markdown、本任务事实和产物；body直接输出准备发到response的正文。收口时结束真实活动，处理重要未决事项，seal，读取body并直接发在最终对话，close终结生命周期。封存和收尾的少量管理时间不另开生产计时。

共同文件仅以本run的去重投影绑定返回；其它run追加、相同事件重放不使本返回失效，本任务新事实会使其STALE。缺End可带明示缺口收口，不为访时完整另造保障工程。READY只说明所选保存内容当前，不能证明事实真实、责任达标、正文已发送或用户已看到；没有宿主发送事件就不声称机械保证response。

0.8.1起新会话用session-3和schema-2正文；旧pin及旧会话保持原身份与原工具口径，不静默迁移，历史图文路径不作为新版绕行默认。澄清、等待与中途进展不收口；暂停禁止继续相应活动但保留任务，停止/取消优先，不要求先封存报告。未实际完成本RETURN并收口前，补充、纠正和宿主新轮都沿原任务；普通消息处置更新输入锚点，不能沿旧封存返回越过新要求。0.8.2正常CLOSED须引用现有机制核准的当前receipt，裸关闭或任意草稿不构成结束返回。模型仍须实际发送当前正文，工具不认证语义质量或宿主送达。已结束任务不因普通输入或旧确认复活。

按实际片段区分DIGR、普通轻量、Goal和协议模拟。新前缀仍真实获取，原P_run冻结；其他宿主缺独立代理、文件或时钟时如实说明，不能以同模型角色扮演冒充L3。
