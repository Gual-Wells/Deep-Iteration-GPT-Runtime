# 0.18：档位适配、架构兼容与限制准入

## 明确选择及逻辑依据

新任务的Allot默认采用 **GPT-6.2 Sol/max、Standard**，保留用户显式选择6.1 Sol/max。Main、N/R、D/V承担的研究职责不等于某个模型档位：议会增加独立问题、竞争路线和再议关系，不会把单个研究块自动变成可降智力的劳力，也不要求每个角色预占昂贵型号。

两代Sol都在实际宿主支持Max，当前公开Standard费率相同，不能仅凭代际或短答卷token推定Pro套餐优劣。在两者都能承载任务关系、没有用户指定旧代的情况下，沿现行Sol代际主线采用6.2，保持与官方原生agent默认建议一致；已有Claude指导亦支持同价同档、无决定性偏好时采用新代。这里给的是可执行的工程默认，不声称6.2在所有工作上胜过6.1。小样实现结果不承担选型裁决。

DIGR的成本单位是完成一个有用工作块，包括上下文、独立研究、综合与返工，不是孤立的一次输出。Pro预算优先靠取消无价值支路、脚本处理机械操作、保持有效上下文和按问题升级控制；不能把N/R/D/V的实质智力工作统一改成低effort来填预算。额度读数与相对费率分别报告，不把公开credits或API单价当作订阅token容量。[官方套餐及费率](https://learn.chatgpt.com/docs/pricing)；[官方原生子代理建议](https://learn.chatgpt.com/docs/agent-configuration/subagents)。

| 实际工作 | Allot行为 |
| --- | --- |
| Main研究、方案、论证、综合、D/V与整体再议 | 默认6.2 Sol/max；Light等五档不暗改effort。 |
| 明确大批量、重复、非智力且有范围/验收的劳动 | 先用脚本；确需模型才显式降effort，限该批次。 |
| 规格歧义、跨项依赖或质量失败暴露 | 受影响剩余劳动回Max，合格结果保留；旧低档计划不复活。 |
| 具体Max能力缺口或实质失败反馈 | 针对决定性子块选择有针对性的更强模型/明确Ultra，保留失败和来源；不预填Astra席位。 |
| 网络、工具、权限、输入或预算故障 | 修相应条件，不能冒称智力不足来升价。 |

## 架构上的实际兼容

默认属于任务的版本化政策，不从当前宿主目录猜。0.18的省略型号取得固定默认；显式型号保持原选择；缺少默认型号或Max报错。`plan`、`ready`、`inspect`和恢复使用同一有效政策。0.17的隐式及已存政策保留原字段与哈希，更老pin保留既有语义。默认不会切换已运行的Main，也不写全局模型配置；宿主执行事实单独观察。

正式Claude在主观目标与路线形成前介入，foundation绑定同任务完整公开来源。任务UUID与request/角色进入新请求身份；旧记录显式沿已有调用前钱包锚采用，不改旧付费字节。直接用户纠正、已证事实和被原指导覆盖的实施不反复收费或再要完整确认。

## 提高限制的阻断门槛

限制的提出方须说明当前有效来源、具体动作与未满足的必要条件，核对已有授权及替代路线；只阻断受影响范围。助手计划、顾问建议、旧清单和缺少理想测量不自行取得硬要求身份。论证充分即可结束分析，测试只处理具体事实或实现未知。明确用户委托的实证任务仍按其真实范围完成。

规格进入PROTOCOL、PERMISSIONS、FOUNDATION和CONSULT。现有permissions工具提供同一准入判断；0.18 foundation问题默认非阻断，拟blocking须携实际依据，无依据的附加门槛保留为建议。结构检查不能认证语义或替代用户授权；真实停止、预算、权限、原件和pin边界照常由原入口执行。这不是新增审批机构或每步必填表。

## 随同落实的缺陷修复

计量按thread/turn关联真实响应，未覆盖累计残差保留，同强度冲突只悬置相关归属；旧turn的迟到改道不扰动新turn。公开流合并相邻同源正文，维持原始游标、偏移和全文哈希；显式compact ACK只缩短输出。宿主仍须真实显示责任、阶段及原文，代码回放不能证明用户界面已收到。
