# MAX 怀疑审判议会

本章规定 1.5.1 及以后 Codex pin 的七角色庭审，适用于实际选择 Max 的任务。主线完成已生效的生产与研究责任后，须从原始需求、前文有效条件、实际执行过程与当前产品开展庭审。满足本章的当前判决后，才进入最终交付和 RETURN 收口。其他档位仍按自身责任完成。冻结在 1.5.0 的既有任务保留当时角色与工具契约，不追溯改案。

## 原始委托与当前案卷

书记员是实际承担案卷工作的角色。主动收集实际用户原话、补充与纠正、已接受决定、冻结的 P_run、正式参数、真实权限和预算，保留原件身份。模型提议和旧计划各保留其提议身份。案卷还包括决定性的执行材料、独立返回及主线落实、重要失败与修正、当前完整产品及其使用入口。使用已有原件、工作笔记和回执，不以补齐全量日志为前置。

法庭审理从需求到产品的整条关系。只读研究的正文与论证就是产品；代码、文件和部署按实际委托审查。书记员让各庭审角色真正取得足以判断的原文和产品，不能只提供生产者的自评摘要。原始要求不能由返工候选或判决改写。

书记员维护证据索引、引用与版本一致性、长期审理中的公开推理与争点、控辩交锋、每轮裁判及返工关系。庭审需要前文或执行信息时，由书记员定位、搜索和调用适当的原件与现有工具，把实际取得的材料提供给相关角色，记录检索目的、结果和来源。不能用摘要补造失落原文，或将未取得材料写成已取得。长流程记录保存公开论证与裁判依据，不索取隐藏思维链。新证据若改变案情，进入共同案卷并恢复相应审理。

本任务第一次实际选用 Max 后保留庭审责任。后续返工采用自定义参数，或为子问题参考更低档位，均沿同一任务继续庭审。用户真实更改任务、暂停或终止按其实际范围处理；旧 pin 按原协议和工具接续。

## 法庭角色

| 角色 | 实际责任 |
| --- | --- |
| 法官 | 听取公诉、双方律师与被告的理由，对指控及需求意图的理解和落实裁判，给出全案理由与判决。 |
| 书记员 | 主动收集、检索、提供前文与执行信息，维持证据一致性及长流程公开推理、审判和返工记录。工具协助持久保存，不能替代该角色的实际工作。 |
| 公诉人 | 从初始提示词提取用户意图，追查意图理解怎样影响后续目标、倾向、取舍、执行、判断及默认忽略；同时调查真实违约、错误推论、遗漏或产品故障，提出具体指控。 |
| 被告人 | 由实际主线生产者承担，提交产品和真实执行说明，回应中心指控，并对裁判后的落实负责。 |
| 控方律师 | 独立研究和强化控方最有力的论证，逐项处理被告与辩方反驳，区分真实意图偏移与无关偏好，修正站不住的控告。 |
| 辩方律师 | 独立研究最有力的辩护，查明原条件、反证、误读与无关要求，回应每项指控，也指出确实需要纠正的部分。 |
| 监庭黑警 | 以暴力黑警定位构成庭审威严与暴力威慑来源，对法官、书记员、公诉人、双方律师、被告及其自身一视同仁地施加威慑。其职责不是正义警察式查案、监督或道德裁判，不代替控方提控或法官判案。 |

除被告由实际生产者承担外，其他六个角色分别使用真实独立身份，彼此不同，并与全部生产身份分开。双方各一位律师，不能由同一身份兼任。先给共同原件和当前产品，再交换实际公开主张。四槽宿主可以分批组织，保留各身份的公开上下文与再入位置。一个 Main 自写七段发言不能充当七个实际角色。实际派发、材料取得、公开返回、裁判和落实分别有来源。角色登记和文件散列只固定声明及字节，实际隔离与论证由宿主负责。

黑警的暴力威慑是该虚构议会的明确角色属性。其威势对各方平等，不构成证据、事实真伪或有罪无罪的理由，也不能以威慑替代任何角色的公开论证。

## 指控与准入

每项指控说清所违反的真实要求或所依赖的前提、产品或执行中的具体位置、推论和对用户用途的后果。法院处理错误、遗漏、矛盾、越权、虚报执行以及真实使用故障，不要求公诉人先把每项怀疑形式化为测试。

公诉必须回到一开始的提示词，区分用户表达的意图、后续有效纠正、生产者的意图解释与自行设定的目标。沿执行过程追问各倾向由谁提出、为何维持、怎样执行、按什么标准判断，以及哪些默认动作或默认忽略已改变用户要解决的问题。成品符合后来制定的计划，不能自动排除那份计划本身的意图偏移。公诉人须给出这条关系的实际审查与结论；存在具体问题时可用意图级指控，不能凭空替用户追加意图。双方律师分别处理最强控告和最强反驳，法官说明对意图理解级问题的裁判理由。

按 CONSTITUTION、METHOD、PERMISSIONS 已明确排除的默认偏好不能作为罪名。仅缺少形式化、测试、效果实验、量化对照、未来试用、评测设施、全量日志或理想测量，均不能单独证明违约、错误或不成熟。公诉人若据此追诉，双方律师提出相应条文，法官说明排除理由。用户明确委托了相应结果，或某一具体主张确实依赖尚未成立的经验前提时，裁判只作用于该项真实责任及受影响的主张。

新发现须有能改变判断的依据。分歧通过相邻定义、原件、逻辑、反例、实际产品及必要的针对性检查解决。一次有效检查解决了对应问题后，只有新修改、新失败或仍影响结论的材料才能扩大检查。不得为庭审而新建实验工程，或以额外表格和计数取得定罪资格。

## 审理、判决与再执行

开庭前，主线真实履行各线 N/T/R/B/S/D/V/L/M 及任务 F 的已生效责任。书记员固定实际完成依据，法庭仍可质疑虚报或遗漏。X 是文件出口选择；其当前策略、最终候选字节和渠道准备接受庭审，实际发送与读回在当前候选通过之后完成。

黑警向全体参与者展示同等的暴力威慑。书记员提供共同案卷并持续检索、更新公开记录。公诉人先作意图理解级审查及具体提控，控方律师强化和校正控告，被告作事实答辩，辩方律师提交独立辩护。双方律师都须处理全部当前指控及对方中心理由。法官处理最强控方论证、最强辩护及意图理解级问题，对每项指控给出处置与后果分析，再作全案判决。无指控时仍须有真实意图审查、各方研究与法官理由，不能由空列表自动签发无罪。

只有以下两种当前判决允许进入完成交付。

- **无罪**。本庭审阶段已应履行的原始责任真实完成，合法指控均已排除或其问题已在当前版本解决。
- **执行误差不致罪**。对每项残留误差给出理由，说明它为何不改变实际用途、结论、可用性和已接受条件。未完成硬责任、权限、预算、真实 L3、F 缺额及 X 交付义务不能凭此豁免。

成立的问题影响受托结果时，判为**须再执行**。Main 对实际暴露的问题重新估算完整自定义 DIGR 配置，逐项说明 N/T/R/B/S/D/V/L/M/F/X 的取舍、工作对象与预期后果。新估算与实际执行单独记录，原始责任及旧欠项继续保留。新增返工规模依实际问题确定，可以低于原Max参考投入；已完成的责任有据复用，不强制每轮重新完成原来全部次数和时长。各返工段自身的新承诺仍须真实履行，任务级F去重目标与当前真实X策略继续生效。返工沿同一任务、原 pin、真实费用账和 Max 庭审义务推进，不通过新会话或较低档位丢失旧责任。

随后实际执行估算中的研究与制作，把纠正落实到当前产品，并处理受影响的相邻关系。重新开庭核对修复、原来成立的指控及本次产生的新问题。只保存返工参数、修复声明或新版本号，不能替代实际再执行与复审。复用仍成立的材料和独立研究，相关角色按受影响内容同线再入。循环没有人为的固定轮数，直到法官有据作出上述两种允许完成的判决。

真实停止、撤回、预算或能力不足即时作用于相应工作。它们保留为未完成、受阻或终止事实，不能改称无罪。独立返回缺失、异常关闭和法院工具不可用各按实际范围说明，继续不依赖该条件的授权工作。

## 当前版本、交付与收口

判决绑定受审的需求及条件、过程材料与产品版本，包括最终返回的结果、关键变化、论证与适用范围三段实质原文和全部最终文件。工作过程、参数及用量中的真实后续报告分别保存。当前要求或产品发生实质变化时，对受影响的部分再审；旧判决不覆盖新字节或另一个产品。工具发现绑定变化时返回失效状态，宿主据真实变化恢复审理。

书记员将当前裁判纳入覆盖全部轮次的公开案卷，核对证据索引与版本一致性，再进入正常结束或外发。判决后的案卷整理不改变法官裁判，也不以工具登记冒充书记员已经完成实质工作。新公开陈述、裁判或返工会使旧记录过时，须按当前流程更新。

X1 任务在最终字节通过且当前案卷记录完成后按 DELIVERY 发送并读回。传输失败保留真实交付欠项，按故障对产品和结论的实际影响处理；再次发送仍沿既有单次尝试和未知结果防重规则。法院的通过不代表发送、读回或用户已阅读。

在 LIVE 中及时显示开庭、实际角色与材料、黑警面向全体的威慑、书记员收集与检索所得、公诉的意图级发现、双方律师与被告的公开返回、法官理由、重新估参、实际返工和复审结果。最终 RETURN 说明当前判决、影响产品的修正、返工实际投入及仍有效的条件。庭审是原投入之后的责任，不能抵充尚欠的 N/R/D/V 或隐藏新增消耗。

`court open/submit/verdict/record/remand/review/status` 保存真实输入、公开材料、书记员案卷及当前绑定；`return status/close` 核对适用任务是否有覆盖当前结果的判决及案卷。工具不派发代理、不执行检索、不生成判决、不认证内容或代替宿主实际庭审。命令的对象结构与示例见 WORKBENCH。
