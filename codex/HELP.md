一处原生议会负责初议和再议。外部成员均可发起 Codex 支持工作，收到实际结果后继续研究。两层每次提交均有本机 Split、费用预留和公开原文转播。单冒号直接开放第一层，双冒号直接开放两层。外部成员共同占用第一层每任务 0.25 美元及第二层正式内容每任务 1.25 美元。钱包及更窄限额同时约束真实发送。详见 [PROTOCOL](PROTOCOL.md)、[COUNCIL](COUNCIL.md)、[CONSULT](CONSULT.md)、[SPLIT](SPLIT.md)。

Main 主动找 Claude 能影响的开放取舍。Claude 可选择或改划议题并先给出立场，原生议会读原文后再议，由 Main 落实。追加请教要有当前仍值得解决的具体问题。取舍已经确定、超过实际决定窗口或已有材料足够时，原生议会据实际所得推进。

ASCII `:` / `::` 与全角等价。真实获取 Codex 分支、固定同 SHA 协议后解析，双冒号整体消费。三枚以上分隔冒号和空任务无效。完整只读/询问调用也可深执行，操作范围按实际委托。讨论和引用有原来的含义。DIGRC、DIGRP 兼容拼写沿相同角色和费用条件。

Light、Less、Default、More、Max 是五档投入偏好基准，`standard` 兼容为 Light。裸调用以 Default 为参考（N12/R4/D3/V3/L3/M1）。Main 在正式 INIT 前主动考虑能改善交付的加深做法，按真实工作逐项推断。若一次更深入的整体重开可能改变方案，Less 也可以将 R 定得更高。推断值可以越过 Light 或 Max 的参考值，用户逐项声明的值按其适用范围生效。Codex 沿当前模型和推理设置工作。只有预见超巨量批任务才按实际收益考虑多档协作。两层 Claude 的研究与内容工作均另记来源，原生 N/R/D/V/L/M 仍由 Codex 承担。详见 [PARAMETERS](PARAMETERS.md)。

F 是任务级去重项目数，支持 `F=3`、`F(3)` 和 `F（3）`。各档 F 参考分别为0、2、3、4、6，Main在INIT前按实际任务推断并保存正式值，显式F优先。每个项目须有社区高评价的来源、实际研究的项目原件及一项具体取舍记录。缺额按实际报告，受影响的方案保持暂定。[F 的完整规则](PARAMETERS.md#f-公开社区项目先研)。

F 达额不结束已采用内容的持续生产责任。使具体原件、构造与条件进入实际生产者的工作，在相关候选、反馈和恢复中继续使用、重研或放弃。通用规范复述与“已借鉴”声明不能单独充抵；不增加知识卡、评分或每项目代理门槛。

## 完整参数调用

完整命名调用为 `DIGR(N=10,T=90min,R=3,B=0,S(n=2,t=25min,r=1,b=0),D=2,V=2,L=3,M=1,X=0,F=2,C=1,U=0)：任务`。`=`与括号标签同义，例如`N(10)`、`C（1）`；S使用`S(...)`。大写任务参数与小写S子参数分清。数值是目标与选择，实际执行还须履行[每单位责任](PARAMETERS.md#单位责任)。

| 参数 | 类型与调用示例 | 作用与省略规则 |
| --- | --- | --- |
| N | 非负整数；`N=10` | 每条M的实质主线推进数；INIT前结合档位与任务推断。 |
| T | 带单位时长；`T=90min` | 每条M有效WORK/SOURCE并集的时间目标；默认按任务推断软目标，`target=90min`为软、`min=90min`为硬。 |
| R | 非负整数；`R=3` | 每条M重新研究完整候选与路线的次数；按任务推断。 |
| B | 0或1；`B=0` | T为软目标或硬下限；默认软，B1须有正时长。 |
| S | `S(n=2,t=25min,r=1,b=0)` | 每个实际来源工作面的n推进、t来源访时、r重研与b软/硬策略；工作面依真实问题划分。 |
| D | 非负整数；`D=2` | 每条M成熟的独立竞争介入数；按任务推断。 |
| V | 非负整数；`V=2` | 每条M持续发展的独立异质领域数；按任务推断。 |
| L | 固定3；`L=3` | 真实独立原生代理与分开的模型历史、执行循环；各档相同。 |
| M | 正整数；`M=1` | 完整独立主进度数；默认参考1，各线分别承担责任。 |
| X | 0或1；`X=0` | 任务级文件出口：当前聊天或本人Gmail。新任务默认0，同任务省略继承；只有真实显式选择能外发。 |
| F | 非负整数；`F=2` | 任务级去重合格社区项目最低数；各档参考0/2/3/4/6，INIT前须推断保存，显式值优先。 |
| C | 0或1；`C=1` | 任务级庭审开关。新任务Max默认1、其他档默认0；显式C覆盖档位，同任务省略继承。 |
| U | 0或1；`U=1` | 任务级 U0 议会。新任务默认0，同任务省略继承。U1 在第一层权限内启用。 |

S的n/r为非负整数，t须带单位，b为0或1且默认软；各面目标按任务确定。位置输入只保留公共序列`N,T,R,B,S(n,t,r,b),D,V,L`供原生解释，M/X/F/C/U须用标签，推荐全部使用命名形式。解析预览不代替正式INIT。

C1履行同一套完整[COURT](COURT.md)，任何档位适用。实际C0撤销余下庭审，保留既有判决、未决事实与历史，不冒称已无罪；它不撤销生产责任。仅调整档位不会改变同任务C。C不改变单/双冒号、Claude预算、模型/effort、L3或X。重复C、C2、裸C及将C放入S均无效。1.5.x及更旧任务沿原pin语义接续，不追溯改案。

任务以[FOUNDATION](FOUNDATION.md)对齐真实对象与已有决定；明确更改直接落实，常规任务内操作沿既有授权。未按RETURN结束或被明令停止前，后续消息沿当前任务，任务按原 P_run 接续。精确 `DO：` 或 `DO:` 把本条原话接入当前任务。新完整单／双冒号与用户明确更改更新相应许可，其他补充沿用仍适用的决定。暂停与停止按实际范围生效。

执行与更新均遵循[原语宪法](CONSTITUTION.md)，包括证据与主张相称、决定及动作有真实来源，以及同时满足更新要求与稳定性的版本化义务。

X 是正式二元参数，X0在当前聊天交付，显式X1选择本人Gmail；`(X)`／`(X=Gmail)`选择本机配置的本人Gmail，仍用原生连接器发送和读回。没有文件不另造附件，详见[DELIVERY](DELIVERY.md)。

实际C1时，按必读[COURT](COURT.md)组织法官、书记员、公诉人、被告人、控方律师、辩方律师与监庭黑警。公诉追查初始意图在后续理解、目标、取舍、执行、判断和默认忽略中的偏移；双方律师分别独立研究控告与辩护。书记员主动检索、提供原件，维持证据一致性与长程公开审判记录。黑警面向全体平等实施暴力威慑，构成庭审威严，不兼任正义警察式监督。成立问题重新估算完整自定义参数并真实再执行、复审，直到当前无罪或执行误差不致罪、当前案卷记录完成。缺少形式化、测试、实验等被协议排除的默认偏好不能单独定罪。X1最终字节先审，之后完成发送与读回。

## 本机工具

`python -B tools/codex.py consult prepare` 组装实际任务包。第二层用 `--guidance` 或正式对象和阶段参数声明实际目的。`consult split --input native-decision.json --out split-plan.json` 绑定当前计划，`consult call --split-plan …` 通过本机 Split 核对后在真实预算内作一次提交。`consult inspect` 读公开事实，`reconcile-cost` 负责对账。`consult budget-preview` 用于估算，`consult budget-limit` 登记用户给出的更窄限额。`production` 记录实际派发、候选、实际选择及成品后果，论文请求用 `--paper-root` 绑定对应对象。

`profile check`只检本地完整性，`acquire`真实联网取pin；`live work/read/ack` 保存真实阶段和无损公开流，宿主实际转播后再确认显示。 `usage` 返回真实 Claude 美元及 Codex 模型和档位的用量证据。 `paper`、`visits` 和 `return` 保存作用域、事实与接续。它们不代替模型的研究、内容判断或有效指导的落实。完整执行按[PROTOCOL](PROTOCOL.md)及manifest全部核心，操作细节见[WORKBENCH](WORKBENCH.md)。

1.9 的最终正文在参数之后显示「执行报错」，按首次发生顺序附阶段、问题、影响、状态和处理。
