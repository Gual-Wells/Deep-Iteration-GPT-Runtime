# 单位责任的应用演练

下列是用于理解参数的设计案例，不是已经发生的 N/R/D/V 次数，也不是模型效果测量。

| 工作 | 责任判断 | 原因与应达到的范围 |
| --- | --- | --- |
| 搜索、打开、阅读三篇官方资料后各写一段摘要 | 不能直接报 N3 | 三个动作可能共同服务一个问题；要研究出影响判断或产物的推进，才讨论 N |
| 研究 PDF 原页组合与全文重排，拿代表内容比较后改变生产路线 | 可以构成一个 N | 该整体解决了一个交付路线问题；其搜索、试作和取舍不是各一 N |
| 把同一候选分别检查措辞、拼写、文件名、格式 | 不能报 R4 | 局部检查未承担重新研究整套候选与生产路线的责任 |
| 从用户实际学习用途重开编排方案，追查割裂原因并修改选段和排列 | 可以构成一个 R | 有真实候选，重新研究了整体，结果回到方案与成品 |
| 提出“改成原页组装”“加个目录”“少清洗一点”三句话 | 不能报 D3 | 需要成熟的非局部介入及实际研究/试作和主线处理，不是按建议条数计数 |
| 对统一重写前提发起原页组装试作，发现已有文件可直接承担大部分交付并重组流程 | 可以构成一个 D | 介入有实物和路线后果；只有实际执行并回到主线才完成责任 |
| 三个代理都说“请注意资料完整性” | 不能报 V3 | 人数与视角的语义距离、持续性和价值无直接对应 |
| 一条读者依赖视角在选段、样本、成品三个节点持续研究并返回发现 | 一条 V，可以多次贡献 | 单位是持续观察线路，不是三次发言；具体发现还须确实非重复且有用 |
| 把完整主线历史复制给新代理，让它称自己独立思考 | 不能仅据此称 L3 | 还需真实受控信息边界与代理身份、指令、执行和工具生命周期 |
| 深入查明某替代路线不可行，排除高成本误区并有依据保留原方案 | 可以产生有用后果 | 参数不要求每轮都改东西；扎实的否定结论可以帮助交付，空洞的“仍然觉得对”不够 |

岗位研究中的同样原则：一次 N 可以查明“同为 Python 开发，核心工作为何不同”并据此改变分组；一次 R 可以重开整个岗位池是否真正服务毕业目标；一次 D 应实际探索可能改变主线的候选方向；一条 V 应持续研究不同的问题表征，而非固定担任泛化审计员。

## 把身份放进一项完整任务，而非新增角色工作

以下是**设计应用示例**：用户要把所选PDF/EPUB原内容经少量处理后组装为一个带目录的文件，已明确不需要统一样式或手机适配。没有在这里实际派代理、制作读物或产生参数完成数。

| 真正遇到的问题 | 可形成的工作身份与行动 | 不能偷换成什么 |
| --- | --- | --- |
| 原页/原章节块怎样保留并按依赖排列 | N「确定原件选段及阅读顺序」：检查有代表性的实际材料，决定可用路线并形成可读样本 | 先重写成统一教材、补一整套清洗系统；不能因旧计划存在就获得这项授权 |
| 已有方案仍以大量中间层为前提，整套是否值得继续 | R「重开读物生产路线：索引底座是否正在取代拼接交付」：研究完整当前方案、用途和直接组合替代，再综合取舍 | 把目录、文件名、样式各查一遍算R3；或只删几个保障词仍做旧流程 |
| 是否能改变“全部清洗后才能组装”的支配前提 | D「试作直接拼接经少量处理的原文件」：真实独立者拿到原件入口与完整介入问题，实际形成足以决定路线的小样和反例 | 只委派“写一段介绍/一个拼接脚本”，工人完成就补成整项D；脚本未运行也不能称样本可用 |
| 直接组合是否破坏章节间的知识依赖 | V「学习连续性：目录与原文能否支撑跨章理解」：从实际片段持续追究；相关选段或排列改变后，再入同线研究 | 固定当格式检查员；每改文件名全员重读；不经Main自行改主成品 |

Main可以提出“原页路线更有价值”的强假说，独立者仍能用材料反驳它。若比较没有实质收益，保留已有路线；不是每项制作都必须多稿。反之，发现真实依赖缺损时应补入所需内容或调整顺序，而非只说“注意完整”。Main接住中心发现，决定哪项实际改变值得做；不会因为V说学习连续性重要，就自动授权重写原文。

一次非局部比较、返回与Main取舍共同承担D责任，不自动拆成D1＋N1＋R1。若主线随后真正解决另一项有交付意义的问题，例如根据研究补选缺失原页并重排完整内容，才按其实际重量判断新N。编号帮助认出对象，不帮助制造次数。

可见表达可以很具体（仍为示例，不是实况）：

```text
[DIGR D01 RETURN｜直接原页组装→Main｜待处理]
回应当前组装路线；已实际制作的样本支持哪些原内容可以保留、哪里仍需处理；给出样本入口与尚未回答的部分。
[DIGR D01 END｜Main处理原页路线]
Main按实物采用/拒绝哪些中心内容，理由是什么；已改变哪个候选/读物，哪些仍待落实。
[DIGR MAIN→V02.2｜转交相关变化]
新选段与目录改变了哪些依赖，请从原学习连续性问题继续研究；不附其它V完整历史，不要求同意Main。
```

例子中的措辞必须由实际结果替换，不能将“已实际制作”原样复制到没制作的任务。公开说明是工作和后果的摘要，不是自动事实认证。

## 消息变化不制造第二轮初始化

- 进行中用户说“V始终独立，由主线转交质疑”：沿用本任务，改变下一项相关委托与交流；不重置时钟或原工作积累。
- 进行中另一条V返回旧候选研究：说明所答对象，Main判断仍适用的中心结论；不自动作废，也不代称它已认可新版。
- 一项候选实质改变了某V正在使用的前提：把必要差异交回该线继续研究；不按版本号给所有人加一次同步任务。
- 一个新的普通任务没有DIGR前缀：普通轻量交付，不沿用本任务参数、角色或计时。文档里被引用的DIGR样例也不是一条新的用户调用。
- 进行中用户补充再次以DIGR开头：仍真实获取候选协议再分类，原P_run不被新HEAD悄悄替换；路由与继续任务是两件事。
