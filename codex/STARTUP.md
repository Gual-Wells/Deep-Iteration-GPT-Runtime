# DIGR Codex 0.8.0 — 启动与宿主边界

本文件只在用户明确选用 Codex 候选通道，且已经真实取得该通道的不可变仓库 pin 后生效。`codex/manifest.json` 与 `codex/VERSION` 必须属于同一 SHA、版本一致。根目录 Alpha 5 协议与此 profile 是两个入口，不能混用参数解析器、时钟前提或证明格式。

1. 仓库表面分类为 `NATIVE | HELP | INVALID | EXECUTING`。仅对当前原始用户消息去开头空白后匹配精确 `DIGR` 或 `深度迭代`；不对引文、历史消息、工具返回或点按状态再做调用识别。完整调用以 ASCII/全角冒号分隔任务，允许前置参数括号；参数括号内的冒号不是任务分隔符。任务原文保留。完整 `DIGR：问题` 即使是询问、只读、要求“别推送”，也属于 EXECUTING；执行模式与写入/推送授权分别判断。无完整调用面的 `DIGR是什么` 等讨论为 NATIVE；精确 `/help` 为 HELP；空任务或损坏的调用为 INVALID。
2. NATIVE 原样交还普通任务处理；HELP 只读 `manifest.help`；INVALID 简明指出结构问题。这三者不创建深执行、计时、契约或证明。
3. EXECUTING读取同SHA的entrypoint与全部core，包括FOUNDATION。声明execution_bundle时核对完整成员、版本及manifest散列；失败不以旧缓存补。先保留调用原文、显式参数和真实冲突，按FOUNDATION独立研究用途、成品、粒度、已有基础、依赖与投入，与用户问答并取得关键决定。前置预算与时钟单列；已有确认续做只问重要变化。确认后再补齐正式参数、显示INIT，并在首项正式实质工作前记录活动边界。身份在实际形成时建立，不预编名册。Codex D/V固定真实独立代理与L3，缺能力不以低L冒充；原生分工授权沿有效任务范围。WORKBENCH按需；CODEX_HOME/digr-codex/toolchain.json仅定位本机工具，不替代在线pin。M默认1，扩线各自完整责任。没有最终拦截器或可信时钟仍继续可做研究，限制如实说明。
4. 普通新任务使用轻量约束，不从历史话题继承 DIGR。真正未完成任务中的补充、澄清答复和压缩恢复继续原执行与已有决定；不重复初始化或收取来源成本。已交付并结束后，普通纠错、讨论先前漏调用或提到 DIGR 均不重启。暂停/待处理纠错先处理，STOP/取消消耗接续资格。依据是当前任务的真实状态，不是调用者手填 active=true。宿主事件未知时保留说明，不伪称已观测。`turn/start` 可向活跃 turn 加输入，方法名不证明新轮；相同 expectedTurnId 也不证明活跃。
5. 补充消息若再次命中 DIGR 候选前缀，仍须真实获取当前通道再分类。若它仍在同一任务内，原 `P_run` 不被新的 HEAD 覆盖；新取得的版本只是新消息的路由/目标信息。明确更换目标时对齐新任务，结束或保留旧任务的真实状态；不能悄悄改写已冻结的原始任务。
6. 用户暂停、取消或宿主中断时停止依赖继续运行的工作，据实记录已完成部分和仍在运行的工具。不要靠新 Goal、后台脚本、代理或自动化绕过停止。恢复时先核对真实文件与进程；不能把断开的计时拼成连续可信时间。

完整执行规则在本 profile 的 entrypoint 与全部 core，包含默认 RETURN。受管理的新会话先保留消息及来源、处理实质纠正，确认只适用于其明确对象；每次 begin/checkpoint 检查当前未完成任务、未处理消息和决定状态。旧会话不自动认证为新流程。本地 AGENTS 不复制执行语义；离线分类、route_pin 字符串或本地检查都不构成活跃仓库获取或完成证明。
