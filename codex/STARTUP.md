# DIGR Codex 0.8.2 — 启动与宿主边界

本文件只在用户明确选用 Codex 候选通道，且已经真实取得该通道的不可变仓库 pin 后生效。`codex/manifest.json` 与 `codex/VERSION` 必须属于同一 SHA、版本一致。根目录 Alpha 5 协议与此 profile 是两个入口，不能混用参数解析器、时钟前提或证明格式。

1. 仓库表面分类为 `NATIVE | HELP | INVALID | EXECUTING`。仅对当前原始用户消息去开头空白后匹配精确 `DIGR` 或 `深度迭代`；不对引文、历史消息、工具返回或点按状态再做调用识别。完整调用以 ASCII/全角冒号分隔任务，允许前置参数括号；参数括号内的冒号不是任务分隔符。任务原文保留。完整 `DIGR：问题` 即使是询问、只读、要求“别推送”，也属于 EXECUTING；执行模式与写入/推送授权分别判断。无完整调用面的 `DIGR是什么` 等讨论为 NATIVE；精确 `/help` 为 HELP；空任务或损坏的调用为 INVALID。
2. 先核对是否存在真实未结束的DIGR任务。若存在，本条消息沿原任务作为补充、答复或纠正处理；表面NATIVE/HELP/INVALID不消耗接续资格，也不重建任务。没有未结束任务时，NATIVE原样交还普通任务处理，HELP只读`manifest.help`，INVALID简明指出结构问题；这三者不创建深执行、计时、契约或证明。
3. EXECUTING读取同SHA的entrypoint与全部core，包括FOUNDATION。声明execution_bundle时核对完整成员、版本及manifest散列；失败不以旧缓存补。先保留调用原文、显式参数和真实冲突，按FOUNDATION独立研究用途、成品、粒度、已有基础、依赖与投入，与用户问答并取得关键决定。前置预算与时钟单列；已有确认续做只问重要变化。确认后再补齐正式参数、显示INIT，并在首项正式实质工作前记录活动边界。身份在实际形成时建立，不预编名册。Codex D/V固定真实独立代理与L3，缺能力不以低L冒充；原生分工授权沿有效任务范围。WORKBENCH按需；CODEX_HOME/digr-codex/toolchain.json仅定位本机工具，不替代在线pin。M默认1，扩线各自完整责任。没有最终拦截器或可信时钟仍继续可做研究，限制如实说明。
4. 在真实安全、权限与用户停止要求内，任务生命周期完整性优先。未按RETURN明确结束返回并收口，且用户未明令停止/取消前，所有后续消息先视为同一任务补充，保持P_run、已有决定、责任、产物和真实记录；没有再次写DIGR、NEW_TURN、纠正、追问状态和压缩均不重置或降成普通模式。明确暂停只停相应活动并保留任务，普通补充不恢复暂停。已交付并结束后，普通纠错、讨论先前漏调用或提到DIGR均不重启。依据是当前任务真实lifecycle，不是旧active上下文、turn_id或手填active=true；未知先取回已有状态，不默认ACTIVE。`turn/start`和expectedTurnId都不单独证明生命周期。
5. 补充消息若再次命中DIGR候选前缀，仍须真实获取当前通道再分类；原P_run不被新HEAD覆盖。目标变化先按当前任务补充对齐，保留不依赖待决变化的工作；不能因话题或要求变化自行终结旧任务、再造确认，也不能悄悄改写已冻结的原始任务。明确停止/取消或实际结束返回后，才按新的有效调用建立新任务。
6. 用户明确暂停/停止/取消时按范围停止相应活动，不靠新Goal、后台脚本、代理或自动化绕过。宿主技术中断停止当前活动，但不伪造用户终止或任务完成；保留未完成任务，据实记录已完成部分和仍在运行工具，恢复核对真实文件、进程与待处理要求，断开的计时不拼成连续可信时间。正常结束只经现有RETURN收口；普通消息处置和裸CLOSED记录不能代替结束返回。

完整执行规则在本profile的entrypoint与全部core，包含默认RETURN。受管理的新会话保留消息来源、处理纠正，确认只适用于其对象；visits的--root begin核对当前任务与决定，直接--file登记只是事实记录，不认证执行授权、不拦截宿主代理。0.8.0旧clock的begin/checkpoint仍按原会话处理，不静默迁移。本地AGENTS不复制执行语义；离线分类、route_pin字符串或本地检查都不构成在线获取或完成证明。
