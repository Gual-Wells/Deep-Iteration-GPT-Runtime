# DIGR Codex 0.4 — 启动与宿主边界

本文件只在用户明确选用 Codex 候选通道，且已经真实取得该通道的不可变仓库 pin 后生效。`codex/manifest.json` 与 `codex/VERSION` 必须属于同一 SHA、版本一致。根目录 Alpha 5 协议与此 profile 是两个入口，不能混用参数解析器、时钟前提或证明格式。

1. 仓库表面分类仍为 `NATIVE | HELP | INVALID | EXECUTING`。仅去开头空白后精确匹配 `DIGR` 或 `深度迭代`；调用以 ASCII/全角冒号分隔任务，允许前置参数括号。任务原文保留，不能改写。`DIGR是什么` 等讨论是 NATIVE；精确 `/help` 是 HELP；空任务或明显损坏的调用为 INVALID。
2. NATIVE 原样交还普通任务处理；HELP 只读 `manifest.help`；INVALID 简明指出结构问题。这三者不创建深执行、计时、契约或证明。
3. EXECUTING 读取同 SHA 的 `entrypoint` 与 `core[]`（本版为 PARAMETERS），理解高投入偏好和每单位责任，再解析参数和确定任务。初始化成功立即按 PARAMETERS 的固定格式在用户可见流报告，随后进入实质轮次。Codex 的 D/V 固定真实独立代理与 L3；能力缺失不以低 L 兜底。WORKBENCH 指南按需取用。没有宿主最终拦截器或可信时钟不取消能开展的研究；未满足的实际隔离与单位责任仍据实保留。
4. 普通新轮次使用轻量约束，不从上一轮继承 DIGR。宿主明确提供的进行中 `turn/steer`、澄清答复和上下文压缩恢复不是新的任务：继续原执行与已有约定，不重复 genesis、重新计时或重新收取来源成本。宿主事件未知时，根据当前任务和消息含义判断，不谎称拿到了 App Server 事件。
5. 补充消息若再次命中 DIGR 候选前缀，仍须真实获取当前通道再分类。若它仍在同一任务内，原 `P_run` 不被新的 HEAD 覆盖；新取得的版本只是新消息的路由/目标信息。明确更换目标时对齐新任务，结束或保留旧任务的真实状态；不能悄悄改写已冻结的原始任务。
6. 用户暂停、取消或宿主中断时停止依赖继续运行的工作，据实记录已完成部分和仍在运行的工具。不要靠新 Goal、后台脚本、代理或自动化绕过停止。恢复时先核对真实文件与进程；不能把断开的计时拼成连续可信时间。

完整执行规则只在本 profile 的 `entrypoint`。本地 AGENTS 轻量偏好不承担 DIGR 语义；辅助 CLI 的离线检查也不构成活跃仓库获取或执行完成证明。
