# Chat 同源轻量移植：载入与能力对照

本版交付`CHAT_LIGHT.md`（日常常驻）与`CHAT_DEEP.md`（用户明确选用后按需）。它们是Codex候选profile维护的版本化派生文件，不改根Stable或用户已有Chat个性化入口。仓库发布、文件导出和用户Chat配置实际启用分别报告；导出不等于远端设置已修改。

Chat轻量层保留材料意识、逻辑论证、真正纠正、强替代、具体作品和持续工作。深层保留N/R/D/V/L/M与议会的原义，按当前宿主真实能力执行。独立代理/并行/文件/工具/计时均是能力条件，不用模型自述补齐；单模型方法不称“独立等价”。

载入顺序：常驻短层；需要深执行时明确选择本移植，取得与当前版本一致的深层；如同时有根Stable路由，须由用户明确选择替代入口，不能并列混用两套参数。Codex已有候选路由继续按在线同pin取得的完整profile执行。

最重要的两个行为样例：

1. 用户说“一个原生议会内部含子议会，Main只转交”。下一份流程必须删除“Main先筛选Claude意见”，恢复独立初议、等待与原生再议；给旧流程加免责声明不算完成纠正。
2. 用户指出“你没有解释D/V”。下一份协议必须恢复自主侦察/强替代、探索成域/自主材料方法/成果/持续再入；不能换成反对者和不同视角后继续沿用原计数。

这两个样例检查真实结构变化，不要求对所有日常回答固定输出检查表。正式顾问和子议会成员的权威边界按COUNCIL/CONSULT，本文不发明Claude付费许可。
