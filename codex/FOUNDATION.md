# U0 — 任务对象、决定与改向

U0 的产物是能让用户看懂、纠偏并真正决定的工作对象。原话与来源、模型解释、已给委托、后续费用决定、实际操作分别保留。前置访时与正式投入分开；研究多少由目标规模、真实歧义、已有基础、依赖及误判返工决定。

## 形成足以执行的说明

说明用途、成品形态和范围、加工粒度、已有材料、必要依赖、可比较的整条方案、资源和完成条件。先取得关键原件，让较早的实际候选帮助澄清真正的分歧。短而清楚的任务可以几句讲清。对已委托的前置研究按它自身执行，无须再把它变成一个前置。证据与方法见 [METHOD](METHOD.md)。

用户已经明确给出执行委托且没有新的实质选择时，直接采用。保存其明确范围和原话。显示关键取舍与理由。只在影响成品或投入且已有授权未覆盖时请求实际决定，等答复期间继续不依赖该选项的工作。问题默认供参考。有阻断要求时按 [PERMISSIONS](PERMISSIONS.md) 说明当前依据、最小范围与必要性。

当前答复只作用于它实际决定的对象。付费答复处理额度，状态追问处理说明。它们不确认成品，也不更换内容锚。真实委托与呈现后的方案确认分别记录。第二层实际内容依赖需要适用的完整公开指导；第一层意见按议会再议处理。明确的用户规格、纯执行和已经覆盖的指导继续生效，只等待依赖新指导的内容选择。

## U1 启用的独立提取

U 默认为0，由 Main 形成当前 U0。实际 U1 的初次任务或真实改向，在第一层权限和余额允许时，将同一份用户原话、已定事项和必要材料交给独立 Codex、Sonnet、Hydrogen 和 Grok。各上下文从共同材料独立提取目标、成品、范围与关键取舍。Main 按 LIVE 转播外部成员的实际公开增量。

外部成员完整的意图理解同等优先，共同参与 U0 重组。有实质分歧时按用户原话、可核原件、已定范围和可用条件作取舍，仍有会改变成品的选择时保留给用户决定。Codex 的独立初稿提供核对与可行性判断。只取得一位完整外部草稿时采用其可核理解；所有外部成员均无完整草稿时采用原生提取。已收到的部分文字仍保留来源。重组后的 U0 仍按本章由 Main 采纳已有委托或取得用户的必要决定。

通过 [COUNCIL](COUNCIL.md#独立前置意图提取) 同轮并发发起，沿用第一层累计额度、每请求 Split、原文转播和对账。普通状态问题、同范围续做和恢复使用已有记录。新实质输入用独立前置轮，原稿、费用和迟到证据仍保留其原输入。如果当前宿主无法建立独立作者、授权或提供商通道，按实际可用结果处理。前置轮不递归启动 U0。

## 在同一任务更新 U0

一般事实维护、明确的局部纠正与已经授权的制作更新可直接落实；改目标、成品、关键路线或足以改变选择的资源时，形成新的 U0。指出旧结果受影响的部分，按照当前委托修订、重做或保留。用户明确扩张并要求执行时采用真正的当前委托，不把旧说明假设成新授权。清楚划定仍处于原授权的独立线路；尚待决定的部分停在依赖边界。用户明确撤回会关闭其约束范围内的旧权利。

对话补充、暂停和恢复沿原任务身份。停止先停实际活动。缺失日志不阻断不依赖日志的判断。工具只能核对版本、保存来源及记录原因；宿主仍须分析意图、落实纠正并实际发送 [LIVE](LIVE.md) 的可见阶段。

## 工程入口

- `task create --require-foundation`，`foundation propose/show`。新解释用 `change-kind material`；仅材料观测更新用 `non_material`。改变关键决定不能用观察维护标签。
- `task message` 保存当前真实来源。实际改变 U0 用 `task handle --action revise`，等新说明提取仍适用的范围。实质补充用 `continue`，无内容或许可变化的追问用 `ordinary`，独立费用决定用 `budget`。新说明可用 `unaffected_lines` 指定仍属已接受范围的现有线路。
- `foundation answer/confirm` 核对当前实际答复。已明确委托用 `foundation commission --input`，登记 `revision`、`commission_source`、`commission_sha256`、`commission_scope_quote`、`explicit_execution_commission`、`no_new_user_choice` 及原因。实质改向含明确新委托时，另给处理为 `revise` 的实际 `commission_message_id`。工具保留用户是否亲自确认这版说明。
- 需要指导时声明 `guidance_required`，使用实际 `exchange_id` 和 `public_sha256` 提供完整回执。未改变主观规格的来源维护以及明确的局部改变见 [WORKBENCH](WORKBENCH.md)。正式投入按 [PARAMETERS](PARAMETERS.md)，前置与结束照 [LIVE](LIVE.md) 和 [RETURN](RETURN.md)。

旧任务与旧论文记录继续使用冻结工具和当时文档。

## 每个真实U0之后的协议自提醒

任何一层实际形成、修订或恢复U0后，在进入该层下一项实质工作前，自提醒沿当前P_run与真实委托遵循协议。Main、subMain、D/V、第一层议会、第二层Consult以及Split，只要实际发生U0都适用；不因层级或称呼省略。提醒应简短，核对本次相关的LIVE、独立性、公开正文转播、权限/费用和RETURN/接续要求，并在用户可见阶段中说明已恢复的责任。后续按真实边界持续执行，不能只在收口时补报告。

提醒不等于已遵循的认证，也不要求逐次工具调用、每个角色或每次续作新建U0。不递归启动新参数任务，不重新全文读取无变化协议，不输出隐藏思考；既有U0不变的续作只恢复适用决定。`foundation propose/show`给出短提醒帮助宿主恢复，真正显示进度和执行仍由宿主负责。
