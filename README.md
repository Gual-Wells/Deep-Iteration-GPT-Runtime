# Deep Iteration GPT Runtime 2.0.0

**版本：`2.1.0`｜协议：`digr-v2`**

这是一个由 GitHub 托管规则、由 GPT 在同一次工作中自行执行的三目标、三阶段运行时适配协议。

## 触发格式

```text
深度迭代：<用户任务>
```

兼容半角冒号：

```text
深度迭代:<用户任务>
```

没有该显式前缀时，不自动启用。

## 三个目标

1. **任务提示优化**：提高意图保真、约束完整性、执行可行性与信息密度。
2. **GPT 缺陷消融**：抑制假性反驳、边界抬杠、教师姿态、纠正表演、元语言和冗余。
3. **资源感知工作流进化**：在必要时结合 GPT 知识、官方文档、研究文献、社区反馈、论坛经验、代码与工具结果，优化完成任务的方法、来源、流程与验证策略。

## 三个阶段

1. **阶段一：前置联合进化**  
   建立原始任务锚点，进行提示优化、缺陷消融、资源门控、元调研和工作流进化，形成内部工作包。
2. **阶段二：原生能力完整执行**  
   由 ChatGPT 继续完整使用其原生规划、深度思考、深度调研、工具调用、重规划和质量控制能力完成任务。
3. **阶段三：结果回代验证与修订**  
   将初步结果回代入代理规则，检查任务保真、证据完整、流程缺口、模型缺陷、原生能力退化与用户可用性，再生成最终结果。

## 执行证据摘要

最终结果之前必须给出 3～6 行简短执行证据，区分：

- 外部可核验动作；
- 运行时自证状态；
- 未独立证实或降级部分；
- 总体证据状态。

执行证据不得泄露隐藏推理，也不得把协议要求、计划动作或“已认真思考”等自述伪装成可审计事实。

## 全局不变量

仓库协议是**强制前置检查与结果复核框架**，不是 ChatGPT 原生能力的替代品，也不声称优于 ChatGPT 原生流程。

协议定义的是最低检查点，而不是能力上限。ChatGPT 必须继续使用所有有助于质量的原生能力，并可根据任务、工具结果和新证据自主增加、调整、重排或重复必要步骤。

## GitHub 与 GPT 的职责

- **GitHub**：托管规则、模块、画像、路由、Schema、测试与版本历史。
- **GPT**：读取规则，在当前工作中完成内部进化、原生任务执行、结果回代与最终输出。
- **本版本不要求**：外部模型 API、独立编排服务器、数据库或用户复制中间提示词。执行证据是当前运行的简短证据摘要，不应被描述成不存在的独立中间件回执。
