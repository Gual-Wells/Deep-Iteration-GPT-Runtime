# Deep Iteration GPT Runtime 2.3.0

**版本：`2.3.0`｜协议：`digr-v2.3`**

DIGR 是一个由 ChatGPT 在当前任务中执行的用户级任务优化协议。2.3.0 的核心变化是重新定义 `T`：它不再代表“人类大概做多久”或一个粗粒度档位，而是以 **GPT-5.6 Sol / High** 为参考配置的**语义任务规模**。

## 触发

```text
深度迭代：<任务>
深度迭代（N，T）：<任务>
```

- `N`：提示词优化循环的强制最小有效次数。
- `T`：在 GPT-5.6 Sol / High 下，通常值得投入约 T 量级**有效主动工作**才能高质量完成的任务规模参考。

有效主动工作可包括：任务理解、提示优化、推理、研究、资料阅读、来源核验、竞争方案、反例、工具调用、代码/文件/数据处理、测试、模拟、结果回代与修订。具体组合由 ChatGPT 根据 `U0` 和执行中新证据动态决定。

`T` **不是**：墙钟 SLA、等待目标、token 数换算、固定搜索次数、固定步骤数、固定档位或回答长度目标。工具并行和高信息密度可能使墙钟时间短于 T；但明显提前结束时，必须先做 T 预算充分性回检，确认不存在仍值得做的高价值工作。

## 2.3.0 核心链

`解析调用头 → 固定协议版本 → U0 → N 次以上提示优化 → P* → T 复杂度感知与工作流设计 → 原生执行 → T 充分性回检 → 结果回代 → 必要重做 → 最终结果 → DIGR 记录`

## 关键设计原则

1. **模型解释 T**：参考解析器只保留 T 原文；不把 `15min` 编译成工作量表。
2. **连续语义，不离散分档**：15m 就按 15m 级任务规模理解，不先压缩成 `Analytical` 等枚举。
3. **预算是质量尺度，不是消耗指标**：较大的 T 应在仍有高价值工作时实质扩大研究、验证、方案或覆盖，而不是制造等待。
4. **停止前检查预算充分性**：已有“可用答案”不等于 T 已落实；仍存在可能实质改善结果的工作时继续。
5. **原生能力优先**：协议不替代 ChatGPT 自己的规划、搜索、工具、测试、反例和重新规划能力。
6. **远程规则固定版本**：从 `stable` 启动时优先先解析一个 commit SHA，本轮所有模块从同一 commit 读取，避免发布窗口混读。
