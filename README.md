# Deep Iteration GPT Runtime 2.2.0

**版本：`2.2.0`｜协议：`digr-v2.2`**

DIGR 是一个由 GitHub 托管规则、由 ChatGPT 在当前工作中执行的用户级任务优化协议。2.2.0 将 2.1.x 的“执行证据摘要”改为更有用的**可观测运行记录**：提示词迭代次数、最终优化提示词、进化度量、正式重做次数、实际流程链以及真实查询/引用来源。

## 触发

```text
深度迭代：<任务>
深度迭代:<任务>
```

可选预算参数：

```text
深度迭代（4，30m）：<任务>
深度迭代(8,2h):<任务>
```

- `N`：提示词优化循环的强制最小有效次数。
- `T`：参考任务复杂度预算，不是实际墙钟耗时承诺。
- 不带参数时，N/T 由运行时依据任务自动确定。

## 核心链

`U0 → 参数解析 → 提示词迭代 → P* → 资源门控/工作流设计 → 原生执行 → 结果回代 → 必要正式重做 → 最终结果 → DIGR 记录`

其中 `U0` 始终是用户事实、目标、约束与授权锚点；`P*` 是可公开展示的用户级执行提示词，不得包含隐藏思维链或高优先级秘密指令。

## 三目标

1. **提示优化**：意图保真、约束完整、执行可行、交付明确、信息密度、验收能力。
2. **GPT 缺陷消融**：减少假性反驳、边界抬杠、教师姿态、纠正表演、元语言与重复空话，同时保留必要纠正与限定。
3. **资源感知工作流进化**：只有在能够实质改善结果时使用搜索、官方文档、研究文献、GitHub、社区、文件、代码、测试、模拟与多来源核验。

## 2.2.0 的输出变化

默认先输出真正的任务结果，再输出简洁的 `【DIGR 记录】`。不再要求旧式 `【执行证据】` 区块。

运行记录包含：

- 参数与复杂度等级；
- 最低/实际提示词迭代次数；
- 最终迭代提示词 `P*`；
- 0–5 整数的进化度量；
- 正式重做次数及原因；
- 仅含真实高层动作的流程链；
- 实际查询/引用来源及用途。
