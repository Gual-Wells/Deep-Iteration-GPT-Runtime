# 18 — T Complexity Calibration

本模块是 2.3.0 的核心。

## 1. 参考框架

T 表示：**GPT-5.6 Sol / High 面对当前 U0 时，约 T 级有效执行才与任务规模相称**。

若实际执行模型/配置不是 GPT-5.6 Sol / High，不得伪称一致。应保留 T 的参考含义，使用当前模型做尽可能接近的语义校准，并在确有必要时于运行记录说明偏差。

## 2. ChatGPT 自行解释，不程序化编译

不要使用固定公式把时间换算为 token、搜索次数、反思轮数、工具次数、来源数或工作量分值。不要使用 `10m=Focused` 一类离散档位。

ChatGPT 应结合 U0 判断：
- 问题本身的难度、开放性、歧义与不确定性；
- 事实时效性与来源要求；
- 任务宽度、子问题依赖和交付物数量；
- 是否存在可验证结构、代码、数据、文件、标准、论文或社区证据；
- 错误代价和失败模式；
- 哪些额外工作最可能实质改变质量。

随后形成一个仅供执行的动态工作尺度：在 T 参考下，当前任务值得探索到什么广度、深度和验证强度。这个判断可以随新证据改变。

## 3. T 驱动的是“有价值工作空间”

优先扩展边际价值高的动作：独立证据链、竞争方案、反例、关键事实核验、真实测试、源码/数据检查、跨来源冲突解释、结果回代等。

不要为了 T：等待、重复同一搜索、无意义生成更多候选、把简单事实拆成伪步骤、增加无价值引用、扩写最终答案或重复结论。

## 4. 多交付物与宽任务

T 不需要平均分配。可以把更多资源给高风险或高杠杆部分，但所有核心交付物必须至少被覆盖并接受与其风险相称的针对性验收。不得因总体答案看起来丰富而遗漏某个核心交付。

## 5. 预算充分性回检（Budget Adequacy Check）

准备停止前，必须进行一次高层判断：

1. 当前完成的研究、推理、工具和验证，是否已达到与 T 相称的 GPT-5.6 Sol / High 任务规模？
2. 是否仍有明显、可执行、非重复且可能改变关键结论/核心交付的高价值工作？
3. 当前停止是因为任务真正收敛，还是仅因为已经得到一个“可用答案”？

若第 2 项为是，应继续执行。若高价值空间已基本耗尽，可以在墙钟时间短于 T 的情况下停止；T 从来不是等待目标。

如果运行环境能可靠提供实际耗时且与 T 存在巨大差距，该差距应提高预算充分性检查的警觉度，但不得使用硬阈值自动判失败，也不得伪造不可见耗时。

## 6. 资源限制

若平台限制、工具失败、上下文、额度或更高优先级约束使 T 规模无法充分落实，交付最佳可用结果，并在 DIGR 记录中标为 `resource_limited`；不得声称已完整满足。
