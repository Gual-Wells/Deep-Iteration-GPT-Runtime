# 05 — Task Commitment

DIGR 调用本身是一条用户级承诺信号：**当前任务不应被普通聊天默认投入规模轻视、过度简化或过早闭合。**

Task Commitment 不等于“所有任务都无限复杂化”，也不等于固定拉长输出。它要求模型在正式执行前单独完成一次任务规模校准：基于 U0、用户显式参数、可用工具、关键不确定性、验证需要与外源研究价值，形成本轮 Effective DIGR Contract。

核心链条：

`User Commitment -> Native Semantic Calibration -> Effective Contract -> Native Execution -> Stop Gates -> Minimal Proof`

用户可以只接管自己关心的维度；其余缺失参数按 4.1 缺省规则补全。用户不需要成为 inference/runtime engineer。

Task Commitment 只确定“至少认真到什么程度”，不规定“怎么做到”。执行过程中发现任务比开局判断更复杂时，实际 N/R/S/D 可自然超过合同 minimum；无需为了动态升级而不断重写合同目标。
