# Whole-Process Re-entry (R / source r) and ABG

## MAIN R: Candidate-backed

R is not “read an old answer again.” Each valid MAIN re-entry attacks the current result/process under immutable U0 and either produces a newer current Candidate or records justified retention of the current Candidate.

Runtime binding is deliberately strict enough to prevent counter inflation:
- retained R must bind the current Candidate revision;
- changed R must end at the current Candidate revision;
- persisted R history may not move backward to a Candidate superseded by an earlier R result.

The challenge may attack candidate content, task representation, Strategy, decomposition, source/validation strategy, assumptions, tool route, evidence base, or the premise that the current execution approach should continue.

## Source r: SourceWorkspace-backed

Source r applies the same principle to that source loop's current result/direction. Retained source re-entry must bind the current SourceWorkspace revision; a changed source re-entry must end at the current revision; persisted source-r history cannot move backward behind an earlier re-entry result.

## Anti-Bureaucracy Guard

ABG rejects protocol theatre: log inflation, source-count fetishism, mechanical paraphrase, needless caution, nonessential rabbit holes and local-optimum lock-in do not qualify. A substantively independent challenge that ultimately retains the current candidate/source result can qualify.
