# 85 — Execution Evidence Report

## 目的

在最终任务结果之前，输出简短、真实、可区分证据层级的执行摘要，使用户能够判断本次深度迭代是否真正加载规则、使用工具、完成回代和发生降级。

该摘要不是思维链，不是完整审计日志，也不是独立中间件的虚构回执。

## 证据层级

### E1：外部可核验

具有可复核对象的执行事实，例如：

- 实际读取的 GitHub 文件路径；
- 实际发生的搜索、网页、文件、代码或连接器调用；
- 可访问的来源；
- 已生成的文件、哈希、测试结果；
- 工具返回的状态或数据。

仅当动作实际发生时才能报告。

### E2：运行时自证

当前 GPT 在本次工作中报告、但没有独立外部记录的状态，例如：

- 已建立 `U0`；
- 激活了哪些规则模块；
- 三阶段的内部完成状态；
- 结果回代检查结论；
- 是否发现并修订缺陷。

必须明确标为“运行时自证”，不得写成独立可审计中间件证据。

### E3：未独立证实或降级

包括：

- 未读取的规则文件；
- 无工具记录支持的执行声称；
- GitHub 获取失败后采用本地降级核心；
- 没有可复核产物的阶段；
- 工具失败或来源缺失。

必须如实指出，不得以笼统措辞掩盖。

## 输出格式

默认格式：

```text
【执行证据】
- 外部可核验：……
- 运行时自证：……
- 降级/未证实：……
- 证据状态：完整 / 部分 / 降级

【最终结果】
……
```

可删除没有内容的行，但不得删除“证据状态”。

## 证据状态

- **完整**：所有对最终结论有实质影响的规则加载、外部动作和关键验证均有对应可核验证据或明确的运行时自证分类。
- **部分**：核心任务已完成，但部分规则加载、阶段执行或验证只有运行时自证，缺少独立记录。
- **降级**：远程规则、关键工具或主要来源不可用，已使用本地核心或替代方法继续执行。
- **失败**：关键任务无法完成。此时不得伪装为成功结果。

## 禁止作为证据的表述

以下内容单独出现时不构成证据：

- “已认真分析”；
- “已进行了多轮思考”；
- “已严格按照三阶段执行”；
- “已全面核查”；
- “已完成深度迭代”。

必须给出实际文件、工具、来源、产物、检查项，或明确标记为运行时自证。

## 生成顺序

1. 完成阶段三回代；
2. 完成最终文本消融；
3. 根据真实执行记录生成证据摘要；
4. 在证据摘要之后输出最终任务结果。

证据摘要不得反向改写任务事实或污染最终结果。
