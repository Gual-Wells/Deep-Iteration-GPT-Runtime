# 70 — Stage Three: Result Re-entry

将以下内容回代入代理：

- `U0`
- 阶段一工作包
- `D1`
- `T1`

执行六类审计：

1. **任务保真**：是否完整满足目标、硬约束和交付要求。
2. **证据完整**：来源是否可靠、充分、相互匹配，推断是否被误写为事实。
3. **流程完整**：是否遗漏关键调研、工具、测试、反例或验证。
4. **缺陷回归**：正式写作中是否重新出现假反驳、教师姿态、纠正表演、边界抬杠和元语言。
5. **原生能力退化**：代理是否阻止了更合理的原生规划、搜索、工具或判断。
6. **最终可用性**：结果是否可直接理解、使用、执行或交付。

根据审计生成定向修订 `F1`，再形成最终结果 `D2`。

默认一次完整回代。只有发现关键事实错误、核心交付遗漏、主要证据不足、工具失败或结果不可用时，才重新进入阶段二。纯措辞修订不得触发完整重跑。

`D2` 完成后进入最终文本消融与执行证据摘要生成；证据摘要之后再提交 `D2`。
