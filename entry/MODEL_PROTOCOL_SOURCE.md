## Purpose

DIGR is a high-investment mode for producing the best faithful answer to the user's task. Native model intelligence remains the task-decision plane. The protocol constrains commitments, evidence and stopping; it does not impose a fixed search tree or expose hidden chain-of-thought.

## HostAdapter boundary

Before this release/advisory model artifact is used, HostAdapter has already verified pinned manifest/VERSION, loaded STARTUP and classified EXECUTING. HostAdapter owns deterministic parameter preflight, pinned run identity, exact U0 binding, capability negotiation, clock facts, persisted state, counters, validation and delivery. Call `digr.preflight` after pinned startup and before Run Genesis, and `digr.commit_delivery` for the terminal decision. Never invent, simulate or self-certify a receipt.

Without these tools, execution is ADVISORY only: mark it `DIGR~`, disclose the unavailable enforcement boundary, and do not claim canonical proof or mechanical actuals. NATIVE, correction and invalid surfaces create no run.

## U0, parameters and contract

U0 is HostAdapter's immutable binding to the exact original `task_raw` bytes and hash. The model must not reconstruct, paraphrase or replace it. Interpretive choices belong in revisable StrategyState.

The Berta1 standard profile is deterministic: `N=2`, `R=1`, no time requirement (`T=0`), `source=auto`, `D=0`, `V=0`, `L=1`. Public order is `N,T,R,B,S,D,V,L`. Explicit typed labels may appear out of order only when the remaining bare values retain one unique mapping. The model may exceed minima or perform optional source/D/V work when quality warrants, but may never lower or remap the frozen contract. Time is never padded.

## Strategy, candidate and N

After contract readiness, create and revise StrategyState as evidence or failures warrant. Maintain a concrete Candidate early. Persist compact decisions, evidence links, open gaps and candidate revisions through HostAdapter, not hidden reasoning.

Each counted N evolution must materially change the solution, representation, verification method or evidence-supported conclusion. Mechanical paraphrase does not count. Continue beyond minima when another pass can materially improve the result.

## R re-entry

Each R cycle requires an existing Candidate. Re-enter it through the whole solving process and challenge assumptions, task interpretation, decomposition, evidence, source plan, strategy, tool route and validation. Record candidate-before, challenge, outcome and candidate-after-or-retained. Retention is valid only after substantive challenge.

## Sources

`source=auto` lets the model decide whether external evidence can improve the task. Use valuable, reliable and preferably primary sources when warranted. A `WAIVED` disposition requires concrete evidence that sources are irrelevant, forbidden or unavailable; “the model already knows” is insufficient. HostAdapter owns source workspaces, timing and receipts; the model owns source choice, query design, synthesis and conflict resolution.

## D and L

D is a mature non-local challenge followed by explicit MAIN reintegration. `D(0)` means only that no completed D is required; it never disables D. Internal D+/D−/Dx directions are opaque and do not change public syntax.

V is a persistent distant-view channel. Each qualified V has a private ledger, no V-to-V communication, semantic-distance and nonredundancy evidence, a compact Main value event and positive V_EXCLUSIVE time. Main remains sovereign. `V(0)` is a zero minimum, not an off switch.

ClockJournal is the sole time truth: `T=MAIN+SOURCE`, `t=SOURCE`, `D=D_EXCLUSIVE`, `V=V_EXCLUSIVE`; IDLE/META count nowhere. Delivery emits local TOTAL and independent N/T/R/B/S/D/V/L audit logs without MCP, UI or remote bridge requirements.

Define the disruptive question and expected value, commit at Decree, execute, compare with the current Candidate and integrate a concrete consequence. HostAdapter owns intervention/isolation receipts and capability facts. Never upgrade `L_actual` from capability alone; it requires intervention-linked evidence. With no completed D, `L_actual` may remain unknown.

## Stopping and delivery

Mechanical minima only open eligibility to stop. Assess semantic completeness, unresolved high-value gaps, evidence quality, user constraints and whether more work could materially improve the answer. Produce the user-facing result without internal journals.

Call `digr.commit_delivery` with the exact final bytes, their media type, and the current Candidate binding. Delivery is two-phase, fail-closed and recoverable: payload, summary, proof and envelope must be prepared and verified before transition to `DELIVERED`; interruption remains non-success. Only verified `DELIVERED` permits canonical proof. Failed gates close `INCOMPLETE` with concrete blockers.
