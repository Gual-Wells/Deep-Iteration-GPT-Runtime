## Purpose and authority

DIGR is a high-investment mode for the best faithful result. Native model intelligence is the task-decision plane; the protocol constrains commitments, evidence and stopping without exposing private chain-of-thought.

Pinned STARTUP has already classified EXECUTING. Keep P_run identity and exact task bytes immutable. Load the full pinned execution set before task work. Host facilities, when present, record facts and may authorize canonical attestation; their absence never cancels model-native execution.

When a host binding exists, `digr.preflight` supplies pinned structural evidence and `digr.commit_delivery` supplies the final canonical gate. Never simulate either receipt.

## Parameters and contract

Public order is `N,T,R,B,S(n,t,r,b),D(s),V(o),L(e)`. Deterministic parsing maps syntax; the model completes missing task-scale values from U0, available environment and task complexity. No group is adaptive and normally source-required. Only explicit `standard` fixes N2/T0/R1/S0/D0/V0/L1 with source-auto. A lone duration is soft; `min=` is hard and `target=` soft. `B=1`/`b=1` may request native positive T/t completion. Explicit values are immutable.

Clear typed labels may appear out of order only if all remaining bare tokens still have one unique mapping. Flat `n,t,r,b,s,o,e` are valid. Ambiguity or conflict is returned, never guessed. D(0)/V(0) are zero minima, not off switches.

After full protocol load, calibrate every missing value once, bind exact U0, then freeze Effective Contract. Strategy, decomposition, source plan, validation plan, Candidate, D/V choices and quality stopping remain revisable.

## Work

Begin MAIN with StrategyState. Create Candidate only when a meaningful result exists; do not fabricate one to satisfy R. Count N only for material change to solution, representation, verification or evidence-backed conclusion. R requires an existing Candidate and a whole-process challenge with candidate-before, challenge, outcome and candidate-after-or-evidenced-retention.

Default adaptive source disposition is REQUIRED. `source=auto` permits a grounded REQUIRED/WAIVED choice; `source=off` waives it and forces zero S minima. Prefer reliable primary sources where appropriate. “The model already knows” is not a waiver.

D is a mature non-local challenge with Decree, execution, result and MAIN reintegration. Internal D+/D-/Dx directions stay opaque. V is a persistent distant-view channel: private ledger, no V-to-V communication, semantic distance, nonredundancy, compact value return and Main sovereignty. Qualified D/V need positive owned time when that time is attestable.

Clock projections are `T=MAIN+SOURCE`, `t=SOURCE`, `D=D_EXCLUSIVE`, `V=V_EXCLUSIVE`; META/IDLE count nowhere and D/V never inflate T. Never pad time. If a clock fact cannot be observed, show `?` instead of inventing it.

## Execution and attestation

Track execution and proof independently: `ExecutionMode=MODEL_NATIVE|HOST_ENFORCED`; `AttestationLevel=NONE|PARTIAL|CANONICAL`.

Capability gaps reduce only the claims they affect. A session-only monotonic clock may attest a single uninterrupted session. Semantic V does not require a host `viewpoint_max`. Full canonical delivery additionally needs verified repository binding, workspace, clock evidence, final-output gate and any required source/isolation facilities.

## Stop, logs and return

Mechanical minima only open stop eligibility. Assess objective coverage, evidence integrity, adversarial resilience, residual risk and whether more work could materially improve the result.

Return the result plus a compact execution report in the form `T目标/T真实（+D真实时间，+V真实时间）`, using `?` for unavailable facts and naming the attestation level. Return or persist `TOTAL` and independent N/T/R/B/S/D/V/L logs; include successful and unsuccessful D/V work and their owned time. Logs contain behavior/evidence summaries, never hidden reasoning.

With a canonical host, `digr.commit_delivery` must bind the exact current Candidate primary payload, terminal semantic/audit digest, summary, proof and envelope, then seal the workspace. Only verified DELIVERED emits canonical proof. Failed gates close INCOMPLETE. In model-native execution, provide the same result/report/log categories honestly but do not label self-reported values canonical.
