# DIGRP 0.1.0 — 从完整论文到可回读的完整导读

DIGRP 是用户明确选择的论文解构增量。它给每篇论文配置完整主进度和相互交接的工作职责，让读者先理解整篇构想和有限模型世界，再读基础、关键推理、实验与原文。原文始终是阅读对象，导读承担解构、补步和连接。

## 进入与版本

先履行所选 DIGR 通道的真实在线获取、同 SHA pin、完整执行协议、任务对齐与持续授权。再取同一 SHA 的 `paper/manifest.json`、`paper/VERSION` 与清单成员，核对版本和散列。`codex/manifest.json` 的 `paper_addon` 声明该入口；技能安装路径和旧论文包都不替代本次获取。缺失的是当前阶段必需的仓库协议时，遵守所属路由的失败规则，不用旧版重建。

首版兼容调用为 `DIGR：按 DIGRP 完整处理……`，也可在已运行的 DIGR 内明确选择增量。独立 `DIGRP：` 前缀尚未启用；本机薄路由不复制第二份协议。`paper acquire --continue-from <同轮已取得的execution目录>` 只续读该 pin，不重新解析 HEAD，不等于下条消息的新获取。

## 每篇一条完整 M

这是对 M 作用域的一项明确增量：用户共同目标、纠正、来源要求与资源边界保持共享，每条 M 的 `paper_scope` 指向指定论文及约定附录，对这一完整论文对象承担独立主进度。各篇分别初始化并履行所属 pin 的 N/R/D/V、来源与隔离责任，不能共享一份计数，也不能把 m 工单数当成深度。普通 DIGR 的 M 语义不因此改变。

公共协调者管理共用来源、最新用户要求、槽位和最终汇合；各篇有自己的作者、候选、尚未处理的返回、访时和接续位置。多篇可以先后、分批或并行；一篇完成不等待其它篇，后来的纠正仍送给相关未完成篇。公共工程不冒充额外论文 M。

## 五项职责，读者顺序 1 → 4 → 2 → 3 → 5

**m1：全景和有限世界。** 从论文呈现的结论、方法、架构与算法倒推问题、变量、目标、约束与构造。用一个完整的系统过程、图或对象，把各模块接起来。明确论文将什么固定、忽略、理想化，它与实际过程有何差异，以及差异影响什么使用。先暂时收起证明细节；每条依赖证明的全局结论仍带稳定链编号，说明它为什么需要成立、成立后供谁使用。

“假设证明已成立”是阅读上的条件性展开，不把作者声称、核对过的推导、实验观察与另加假设混为同一种结果。依据只在影响的主张旁清楚说一次，避免用警示表占据全景正文。

**m4：原文语言和必要基础。** 完整备齐符号、下标、集合、量纲、定义、常规变形与背景工具；提前提供可独立读、可查的准备路，再在主链使用处极短复提。优先保持原论文对象与记号，特别区分同一字母的局部含义、归集范围和单位。确有必要压缩长表达式时，把可见原式的一整段标成有意义的局部块，在同一连接内映回；不先造一套覆盖全文的简记字典。

**m2：完整推理骨架。** 按有目的的连接分块：起点是什么，想得到什么，为什么整篇需要它；原式说什么，每一步怎样变形、用什么前提，结果如何接到下一原式。关键、复杂的链走透；简单台阶仍保留简短说明，避免分层后断链。原式→说明→必要补步→下一原式形成连续章节，不以公式逐条名词解释代替论证。

论文略写的代数、外部定理、教学推导、额外假设和无法接通的断点分别标识。能补的实际补完并核对；不能从现有条件推出的命题，指出精确缺口与全局后果。条件性示范可以解释一座桥需要什么，不静默升级为作者已证原结论。数值、边界或符号复算支撑对应步骤，不冒充整体数学证明。

**m3：实验作为证据。** 逐图表连接待支持主张、数据/环境、基线、控制变量、指标、横纵轴和实际结果。把效果与决策/训练/存储等相关开销放在同一比较条件下；保留不利和不变结果。作者的原因解释、可直接读出的观察和教学推测分开。有限仿真曲线与长期定理、训练回合与运行时间、均值与总量不能因名称相近而合并。

**m5：全篇原文回读。** 从摄入即参与，最后呈现。核对章节、定义、编号及无编号关键公式、图表、算法、脚注、附录、综述与引用在导读中的实际去处。改变核心解释的发现回送 m1/m2/m3 修订，不藏进“其它内容”。参考文献说明它在本篇的作用；关键前提和证明的外部依赖定点取回，未读保留未读，不无限递归整个引用网络。作者、版本、资助等来源身份可简要交代，区分非论证内容与遗漏。

## 生产与交接

m 是稳定职责，不要求五个常驻人物。先共享原件版本和初步结构，再并行发展全景、基础/主链、实验与回读；m2/m3/m5 的发现返回主进度修订。各职责交接带最小必要的原页、原式、条件、候选位置和未解问题。定义或来源变化只复核受影响部分；同名符号不能自动合并。

读者顺序固定于已接受的当前版，生产则允许反馈环。角色划分不直接成为分页和五份孤立报告；主进度综合成一份可连续读的作品。所有代理返回均须处理中心主张、选择及实际后果，真实隔离、持续领域与竞争介入仍按底层协议承担。

## Markdown 到手机 PDF

导读有可维护的 Markdown 源，公式、原图、表和算法在相关解释旁实际插入。源页定位文字不能替代尚未嵌入的材料。跨栏原式按原阅读顺序接合，裁图清除相邻无关碎字，保留完整符号、图例与数值；作者内容、原件上的读者批注、裁图和教学补充身份分开。

在本机完成数学、行内上下标、图片与字体渲染，再对排好的页面截图拼 PDF。纸面宽度与字号按手机阅读决定；窄屏模拟只报告其实际条件，不称手机实测。原式太长时优先分行或局部语义压缩，不把文字和复杂公式无限缩小。标题/引出句和接下来的公式、公式与必要说明、图片与图题保持连贯；表和算法可按语义拆页，序号延续。避免机械按角色或小标题新页造成大块空白。

成品要打开实际 PDF：看全页整体及符号密集/跨栏/图表等关键大图，核对正文连续、原式对应和读者路径。零溢出、页数、哈希和文件存在仅是检查事实，不等于好读或讲懂。既有成败经验须取回实际材料与反馈，并落实到当前作品；用户否定的小样不继续作为已接受基线。

## 每篇独立 Gmail 返回

先完成本篇约定内容、原文覆盖与真实职责，核验最终 PDF，再用已获授权的 Gmail 能力发送。发件任务不因此新增付费 API 或密钥依赖。收件地址沿实际用户授权；正常任务内发送不重复询问。PDF 过大可按连贯章节分卷分封，每卷有明确顺序，同篇直到全部约定文件都发送核验才返回。

记录发送所选的最终文件身份、实际消息 ID；读回已发送邮件，核对收件人、SENT、附件名和大小。发送响应不明时先在 Gmail 查明是否已发送，不盲目重发。草稿、准备好的附件、调用已发出、邮件已发出、读回核验和本篇返回是不同事实。附件之后修改了，旧消息不代表新文件已交付；保留旧版记录，新候选重新核验与发送。

单篇 `RETURNED` 表示本篇完成说明及文件已按此路径交付，不表示用户打开、理解或长期掌握。它不关闭父 DIGR 生命周期，不提前发送整个任务的最终返回。所有约定论文和公共工程完成后，才按所属 pin 的 RETURN 统筹正文报告并真正收口；停止/暂停仍立即按用户范围生效。

## 私人资料与接续

原件、导读、真实反馈、Gmail 证据和私人路径在任务私有区；公共协议、技能、工具和合成测试不带这些材料。每篇工具只保存论文来源与交接事实。已有 Paper Knowledge 池仍是个人学习记录权威，按概念含义和局部用法比较后复用；准备讲义、发送和理解分别记录，不另造相反的能力状态库。

接续先读本任务最新决定、每篇实际状态、原件版本和游标，保留当前例子、符号与步骤。不同篇的状态独立，工具的 `summary` 只是汇总；它不代替最终统筹判断。文件与命令契约见 [DATA.md](DATA.md)，原生宿主负责语义、授权、代理、作品和真实发送。
