# DIGR 论文增量 0.6.3 — 同范围产出与比较

本增量适用于统一 DIGR 中委托外部作者参与整篇论文解构、导读或完整读物的任务。独立原生作者与选定外部作者按同一读者用途研究和成稿。原文始终是阅读对象。每篇承担完整主进度，交付一份标准页 PDF，沿任务选择的 X 返回文件。


双方共用 [SPLIT](../codex/SPLIT.md)、文本优先准备、公开增量转播及费用恢复。实际委托的整篇产品采用完整导读、来源覆盖与标准页 PDF。普通翻译和局部问答按本来产品完成。

从 Codex 1.9 起，Main 按共同规格、论文原件与可读性比较同范围候选，可采用原生稿、外部稿或综合。外部复审按实际需要参与。登记 PDF 时绑定已落实的比较结果，以及本篇实际参与的外部候选或复审。[核心正式产出](../codex/CONSULT.md)规定作用域、费用及接续。旧任务依冻结 pin 恢复。

## 进入与版本

先履行所选 DIGR 通道的真实在线获取、同 SHA pin、完整执行协议、任务对齐与持续授权。再取同一 SHA 的 `paper/manifest.json`、`paper/VERSION` 与清单成员，核对版本和散列。`codex/manifest.json` 的 `paper_addon` 声明该入口；技能安装路径和旧论文包都不替代本次获取。缺失的是当前阶段必需的仓库协议时，遵守所属路由的失败规则，不用旧版重建。

当前核心的第二层入口为 `DIGR：：用Sonnet完整处理这篇论文……`，也可按当前任务的真实用户决定接入。按核心 [PROTOCOL](../codex/PROTOCOL.md) 核对角色、范围和费用。子议会中的论文讨论属于第一层评议，整篇导读在实际采用第二层后建立。宿主按用户真实用途绑定整篇对象，取得同 pin 协议并登记来源。`paper acquire --continue-from` 续读原 pin，新前缀按当前路由获取。内部 `--paper-root` 选择本次实际论文。历史 DIGRP 拼写及任务按各自冻结核心的规则恢复。

0.5 的论文创作契约为 `sonnet-native-v1`，来源映射契约为 `source-bound-native-v1`。旧任务保留原 pin 与原数据契约，不自动转换为新协作或新内容。统一DIGR中的其它内容对象不因本增量变成论文导读；论文内容的创作关系以下文为准，共用能力、费用和公开交换仍依核心 [CONSULT](../codex/CONSULT.md)。

## 从论文原件独立形成读法

本节以实际选定 Sonnet 的任务为例。选择其它外部作者时按核心记录核对该作者的请求、响应和公共原稿，各份候选沿同一比较标准。

交给Sonnet前，Codex完成完整原件的获取、文本/Markdown整理、公式可靠转写与必要图表裁图；传入实际正文和所需局部图像，保持原式、图题、来源及回原页关系。不把逐页整图作为有可提取文字论文的默认输入，免去重复视觉/OCR工作。扫描、图形布局或不能可靠文字化的局部按实际需要保留图像；内容选择和讲解设计仍由Sonnet原生决定。

Sonnet公开消息和正文增量在实际调用期间按原文实时转播，由Codex负责取流、分段显示、保留原稿及中断对账；不要求Sonnet额外生产进度汇报，也不等待整篇完成才展示成“直播”。公开原文、Codex操作状态和后续成品组装相区分。具体工具及费用依CONSULT。

给 Sonnet 当前用户原话、已经接受的读者目标与纠正、约定的整篇范围、真实原件以及实际能力和资源。Sonnet 可以从一个困惑、一个现象、某页推理或直接写作进入，自己决定如何认识和讲述这篇论文，以及还需要什么材料。它可以形成整篇或局部稿件、提出问题、改变读序、选择章节和例子；不先要求一份固定形状的大纲，也不让它填角色、职责、阶段、覆盖表或五类教学栏。

取消小 m 的分解，同时取消其预设生产路线。全景、基础、推导、实验、回读等内容在本篇及用户要求确实需要时充分处理，但不组成必须逐项生产的通用蓝图，也不因换标题、合章或藏在私有记录中继续强制。已经接受的用户学习目标、读序、解释深度和完整论文范围仍然有效；不能借自然组织缩减用户所要的推导、原图或附录。

Sonnet 自然索取某页、某图、定义、复算、反例或试作，Codex 负责取得、核对和制作。实际传入的正文、图像及其缺损清楚可见，本机路径不等于 Sonnet 已取得原件；尚未传入或未读到的材料保留该事实。公开稿按实际原意区分选定方向、试作、可选项和未决问题。指导应改变真实作品，不把保存交换记录或 API 成功当作落实。

Codex 继续独立承担整篇研究、判断、实质内容工作、工程和交付。它提供值得改变认识的新材料、独立解释、反例与竞争路线，处理返回对中心主张的实际后果，而非只转发稿件或替 Sonnet 整理工单；这些贡献送进当前内容，不能据此预先固定论文读法。原生 D/V/L/N/R 的含义和责任不减少，Sonnet 的参与不充当原生独立角色或额外 M。

当前用户要求、原件事实、真实权限和预算约束双方。确定事实由 Codex 自主更正并说明，尽量保留仍成立的解释；若新原件、独立反例或实际读者使用推翻了讲述前提，或需要改变范围、结构、来源身份和体验，带相关原件、现稿与短差异再与 Sonnet 发展。换字体依赖、保词元续行等产品等价工程可直接完成。保持选定解释的实际后果，实质改动回到共同要求和原件复核。

只保存真实公开消息、稿件和必要身份/用量事实，不索取或持久化隐藏思考。论文请求使用选定的规范 Sonnet 型号标识，服务响应所报型号须与其精确一致；系统角色名不能替代这项身份事实。型号缺失或不符时保留公开稿与费用事实，不将其登记为 Sonnet 原生候选，也不自动重试。首轮公开交换绑定实际论文，后续保留这篇的公开上下文、已接受决定和未决问题；不是每次从模板重新开题。尚无真实 Sonnet 返回时可继续不依赖它的研究、取材和工程，但不能将 Codex 自拟稿、合成公开稿或另一篇指导冒称本篇原生驱动；无法取得时依已有明确回退授权处理，或如实留下未完成协作。

论文结构、解释方式与协作方案的定性判断，依目的、前提、机制和关键反驳形成明确结论，不把实验或读者试用设成默认成立条件。原论文的实测结果与已发生的制作/交付按各自真实情况陈述；这不规定Sonnet的思考程序或固定讲法。

## 每篇一条完整 M

用户共同目标、纠正、来源要求与资源边界共享，每条 M 的 `paper_scope` 指向指定论文及约定附录，对这一完整论文对象承担独立主进度。各篇分别初始化并履行所属 pin 的 N/R/D/V、来源与隔离责任，不能共享一份计数，也不能把章节数、请求数或映射行数当作深度。普通 DIGR 的 M 语义不变。

公共协调者管理共用来源、最新用户要求、槽位和最终汇合；各篇有自己的真实公开协作、当前作品、尚未处理的返回、访时和接续位置。多篇可先后、分批或并行；一篇完成不等待其它篇，后来的纠正送给相关未完成篇。公共工程不冒充额外论文 M。

## 完整、可核对的原文关系

Codex 从摄入起读完整约定原件，并按它实际包含的内容核对作品去处。章节、定义、编号及无编号关键公式、图表、算法、脚注、附录与引用的作用不能因预设教学结构而消失；来源清单和去处由这篇原文与实际作品产生。改变解释的发现修订相关正文，不藏进“其它内容”。参考文献按它在本篇的实际作用处理，关键外部依赖定点取回；未取得的来源明确保留，不无限递归整个引用网络。作者、版本和资助等来源身份与论证内容区分。

解释随本篇真实对象和读者困难发展。沿用原件的记号、单位、局部条件及实际依赖，让读者能从所讲内容回到相应原页。需要补步时真正补完并核对，教学添加和额外假设清楚标识；无法从现有条件推出的结论指出精确缺口及其后果。作者声称、已核对的推导、实验观察与教学推测保持各自身份，限定在影响的主张旁清楚说明。原文中的数值、比较条件、不利结果和未变化结果按其实际意义核查；一次数值复算不冒充数学证明。这里要求来源忠实和解释有效，不规定所有论文必须具有同一组论证对象。

读者纠正也为 Codex 的辅助研究提供具体问题：当前混淆的是哪两个对象、固定了什么、哪一步缺少连接，已用的例子为何没有接通。带相关原式、上下文和读者原话发展实质解释，再与本篇公开创作衔接，不把“没懂”预先改成缩短、另造互动件或重建课程。用户需要理解的技术设计、接口与存储知识仍是内容；工具执行和制作由 Codex 承担。这些问题按实际困难选用，不预设 Sonnet 必须采用同一种思考、章节或教学路线。

私人映射由 Codex 维护，只记录实际原文内容块、原页与作品位置及真实处理情况，不要求 Sonnet 写 schema。粒度应足以暴露实质遗漏，不能把“整篇→第一章”一行当作全篇核对。没有适用于这篇的证明或实验时，不造条目补齐字段。锚点、标题可解析和字段齐全只证明工具所检查的事实；整篇是否真正处理、解释是否成立，仍须实际对照原件与最终读物。

## 面向桌面双页阅读的标准 PDF

导读有可维护的 Markdown 源，公式、原图、表和算法在相关解释旁实际插入。源页定位文字不能替代尚未嵌入的材料。跨栏原式按原阅读顺序接合，裁图清除相邻无关碎字，保留完整符号、图例与数值；作者内容、原件上的读者批注、裁图和教学补充身份分开。

默认一篇一份完整 PDF，每页为统一的 A4 竖版单页；用户另定标准纸型时按该规格。查看器将相邻单页并排，不能把两叶拼成一张宽 PDF 页，不能按内容高低裁成可变长页。版式服务经过实际比较并符合用户要求的读序，按电脑双页阅读比较适合宽度和整组双页完整显示两种状态。

需要选择版式时，用真实内容比较有实质差别的读物路线，再确定字级、行长、行距、版心和页面节奏；已适用的设计可复用，不要求每篇重新选美。正文、标题、数学、图注和回原文提示形成清楚层级；保留原图颜色，图例过小时分子图或局部展开。固定页高内的留白参与构图，不靠裁掉纸面消除空白。

制作机制服从产品。优先比较可搜索文字、嵌入字体和矢量公式；需要截图时按同一标准单页制作并保留足够分辨率。长式按关系分行或局部语义压缩，不能为压页数无限缩小。标题不孤悬，必要说明与原式相接，图题与图相连；长解释、表格和算法可按语义续页。具体设计与实际检查见 [PDF 产品规范](PDF_DESIGN.md)。

打开实际写出的 PDF，查看单页与相邻对页整体，细读内容密集处、图表、公式及章节边界，沿本篇实际阅读路线核对解释和原文关系。真实查看器与离线模拟分别记录；工具受限时如实说明范围，不绕过限制或声称已实测。零溢出、页数、哈希和文件存在不等于好读或讲懂。既有成败经验取回实际材料与反馈，并落实当前作品；用户否定的产品不继续作为已接受基线。

## 每篇独立返回，由 X 选择文件出口

完成本篇约定内容、真实协作、原文覆盖和最终 PDF 复核后，继承父 DIGR 任务的 X：无 X 在当前聊天提供完整文件并记录单篇返回；有 X 用所选原生渠道一次返回本篇。完成单位是整篇论文，不能按章节、证明链或分卷交付。多个 M 可各自完成，不等其它论文；同一篇只有一份完整 PDF 和一次对应版本的最终交付。

X 只控制文件，不控制文字答复，不为无文件任务额外造附件。目标沿父任务冻结的私有配置；`(X)` 与 `(X=Gmail)` 均选本人 Gmail，本版仅实现 Gmail。已有授权持续，真实宿主限制仍须遵守。沿用已有 Gmail 连接，不新增付费 API 或密钥依赖。超过附件限制时先优化同一文件的字体、图片编码和分辨率并保留可读性；仍超限则处理实际可用且已授权的单文件方式，不擅自分卷、多封发送或创建公开链接。

有 X 时先在父任务的共同 delivery ledger 保存本篇候选、唯一 PDF 和发送尝试，再通过 Gmail 原生连接器发送。读回核对当前本人账号、收件人、实际 SENT、唯一完整 PDF 及附件字节；不编造消息 ID 或远端哈希。响应不明先对账，不盲重试。草稿、附件已准备、调用已发出、邮件已发出、读回核验和本篇返回是不同事实。修订整篇之后保留历史，再交付新版完整文件；旧消息不代表新版已交付，旧 0.1 分卷记录不自动改写为新合格交付。

单篇 `RETURNED` 表示本篇完成说明及文件已按所选路径返回，不表示用户打开、理解或长期掌握。它不关闭父 DIGR 生命周期，不提前发送整个任务最终返回。所有约定论文和公共工程完成后，按所属 pin 的 RETURN 统筹正文报告并真正收口；停止/暂停立即按用户范围生效。

## 私人资料与接续

原件、导读、真实反馈、渠道证据和私人路径留在任务私有区；公共协议、技能、工具和合成测试不带这些材料。工具保存论文来源、公开协作和交接事实。已有 Paper Knowledge 池仍是个人学习记录权威，按概念含义和局部用法比较后复用；准备讲义、发送和理解分别记录，不另造相反的能力状态库。

接续先读本任务最新决定、每篇实际状态、原件版本、有效公开创作与游标，保留当前例子、记号和待接步骤。各篇状态独立；工具 `summary` 只是汇总，不代替最终判断。文件与命令契约见 [DATA.md](DATA.md)，原生宿主负责语义、授权、独立研究、作品和真实发送。
