# DIGR 5.0-compatible Local Personalization — Expanded Routing / Transparency Reference

This is the expanded explanation of the version-neutral local Router Transport Contract. Direct-copy text is `CHATGPT_LOCAL_PERSONALIZATION.txt`. Neither file defines versioned DIGR execution semantics.

## 1. Candidate routing is an obligation
For every user message, remove leading whitespace only. Exact uppercase ASCII `DIGR` or exact `深度迭代` triggers routing before task-level interpretation. Lower/mixed-case English does not. The local layer intentionally ignores the remainder; the pinned startup protocol later decides NATIVE/HELP/INVALID/EXECUTING.

A candidate match requires an **actual repository acquisition action before any user-visible reply**. “I probably cannot fetch it”, remembered repository state, or merely having the fixed failure string available is not an acquisition attempt.

## 2. Mutable-ref provenance and immutable pin
Repository: `Gual-Wells/Deep-Iteration-GPT-Runtime`; discovery ref: `stable`.

The only mutable step is `stable → full commit SHA`. Search-engine results, snippets, crawled/indexed GitHub snapshots, conversation text and Memory are inadmissible ref authority. An already-connected GitHub repository connector may resolve the current public `stable` branch HEAD directly. A genuine direct REST client reads both branch and Git-ref resources and requires the same full SHA.

After pinning, every later read for the turn uses that exact SHA. Bind pinned `manifest.json` + `VERSION` and require version equality.

## 3. Transparent machine index comes first
If the pinned manifest declares `bootstrap_index`, load that path **before interpreting the startup/runtime structure** and before the remaining startup slice. The index is a structural transparency lens: it identifies what protocol files, executable helpers, workspace/state objects, schemas and truth sources already exist, and separates deterministic reliability machinery from native model intelligence.

The local layer must not invent the machine from general Agent/runtime/host conventions before this index is read. In particular, a repository-declared helper is an actual execution facility when the pinned protocol calls for it; it is not automatically a metaphor, conceptual simulation, external daemon, mount, attachment or service.

The index itself is not semantic authority. It must not copy or override versioned parameter, timing, stop, D/L or proof rules. Those remain in the pinned startup/entry/core protocol.

## 4. Ordered authority handoff
The current navigation contract is:

`stable → SHA → manifest/VERSION → manifest.bootstrap_index → remaining startup_slice → repository surface`

The pinned index tells the host/model how the machine is assembled and where each truth lives. The remaining startup slice then performs repository-defined classification. NATIVE returns the untouched original message. HELP loads `manifest.help`. EXECUTING follows the repository startup rules and only then loads the same-SHA execution transport declared by the manifest: a declared execution bundle when present, otherwise the logical `entrypoint` / `core[]` files.

A bundle is transport aggregation only; its verified members remain the logical entrypoint/core authority. Legacy manifests without `bootstrap_index` follow their own declared navigation and are never retrofitted with newer structure.

## 5. Operating boundary
The intended host posture is **structure-closed, intelligence-open**:

- repository structure, object identity, persistence, references and executable reliability helpers are discovered from the pinned repository;
- task representation, decomposition, research/validation strategy and substantive reasoning remain native-model responsibilities under the loaded protocol;
- implemented reliability machinery must not be replaced by model self-report;
- deterministic support must not be promoted into a planner that chooses what the model should think next.

## 6. Failure evidence
The fixed route-failure response is permitted only after this turn has at least one real repository acquisition attempt and the currently mandatory repository/ref/SHA/manifest/VERSION/index/startup path still fails, conflicts or has inadmissible provenance. Skipping acquisition or skipping the declared index is router execution failure, not repository failure.

Once the pinned repository protocol is acquired, it is the sole source of versioned DIGR semantics for that turn, subject to higher-priority instructions and current hard user constraints. Conversation context, Memory, previous answers and target versions cannot reconstruct or override those semantics.
