# DIGR Plus Local Personalization — Routing / Immutable Authority / Package Boundary Reference

The deployable text is `CHATGPT_LOCAL_PERSONALIZATION.txt`. This document is version-neutral.

## Candidate routing
After leading whitespace only, exact-uppercase `DIGR` or exact `深度迭代` creates a repository-route candidate. The local layer does not interpret parameters or task semantics.

## Pre-task execution firewall
From candidate capture until pinned startup declares task-work-ready, model/tool activity is limited to repository acquisition, immutable pinning, INDEX/startup loading, and actual runtime/protocol establishment. Reading startup is not executing startup.

## Mutable-ref provenance
Use current `stable` from an already-connected GitHub branch resource, or direct REST branch/ref consensus. Search/crawl/Memory are never mutable-ref authority. A public bootstrap must not force a new OAuth connection.

## Immutable content transport
After stable resolves to one 40-hex SHA, all reads use that SHA. Bind manifest/VERSION. Prefer pinned raw content; Contents API fallback must return raw bytes or decode the JSON/base64 wrapper.

## Transparent machine index
`bootstrap_index` is the first structural lens when declared. It exposes real implementation objects and truth sources without defining versioned DIGR task semantics.

## Execute-before-interpret and package-level implementation delivery
Repository implementations must be executed, not semantically imitated. When the pinned manifest/startup declares a package-level attestation verifier, that verifier is the normal implementation-delivery boundary. Obtain the exact pinned verifier/package and required immutable repository identity evidence, execute the verifier, and use its real receipt. Do not expand a declared package-level attestation back into per-helper fetch/interrogation. Re-open identity only when package/executor identity changes or a real direct attempt fails.

## Surface handoff
NATIVE returns the original message to native ChatGPT; HELP follows manifest.help; INVALID returns startup diagnostics; EXECUTING performs all pinned readiness operations before task work.

## Authority and failure
Pinned repository semantics are authoritative for the turn. P_target/context cannot redefine P_run. Route failure requires a real current acquisition attempt; post-pin startup failure is not route failure.
