# DIGR Codex Stable 兼容范围

Codex 路由仍读取 `codex/codex-host-adaptation`，现行语义由发布 SHA 下的 codex/manifest.json、VERSION 与同 pin 执行束定义。历史会话继续使用创建时的 `version@SHA`，版本号相同也不跨 SHA 读写。这里只说明继任关系。

| 旧协议承载的功能 | Stable 的正常入口 |
| --- | --- |
| 普通轻量、显式深执行、HELP、候选传输及不可变身份 | 薄路由、STARTUP、`acquire`；同 SHA 执行核心 |
| N/R、S、D/V/L3、完整多 Main、五档及软硬时间 | PARAMETERS、COLLABORATION、原生独立执行及同线再入 |
| U0、委托决定、接续、暂停、停止、恢复、DO | FOUNDATION、`task message/handle/lifecycle`；新目标进入新 U0，保留既有仍适用的范围 |
| 结果、过程透明、时间与状态 | LIVE、RETURN、共享 visits；独立来源、真实发布与当前文件。历史时间图按明确用途调用 |
| 事实边界、逻辑分析、实验授权、写作表达 | METHOD、PERMISSIONS；分析可凭充分论证完成，必要工程检查独立作用 |

| Stable 1.3 的额度内授权与子议会委托 | 当前用户选择直接打开适用层的额度。Claude 的实际公开请求可经 Codex 工作、原件回传及同线高 effort 续答。历史 pin 继续按原规则发送。 |
| Stable 1.2 新任务的单冒号首发 | [PROTOCOL](../codex/PROTOCOL.md#单冒号任务的独立首发) 在开放的实质取舍定案前接入 [COUNCIL](../codex/COUNCIL.md#单冒号的独立首发)。一次发送沿已有单冒号钱包权限，原生初议、再议和落实各有实际记录。 |

独立首发按任务冻结的 Codex Stable pin 执行。根目录 DIGR、历史执行记录和其他已发布工具各自按原版本入口处理。Chat 深层导出承接选中 Codex 版本的工作关系，实际首发和委托回传取决于宿主的独立身份、通信、共享钱包和执行能力。当前分析从实际委托决定是否采用实验，交易、发布、送达与用量则采用各自的可观察证据。

## Codex 1.5.0 的版本化边界

新pin把X/F纳入正式参数组与五档、自定义参考。X只接受二元选择并保持旧独立栏兼容；F在INIT前明确推断或接受显式值。任务级参数、补充覆盖、暂停恢复及原邮箱冻结按正常入口接续。1.4.1及以前继续原X栏、F默认和原返回契约，不把新Max庭审追溯附加到旧任务。

Max在原研究与生产责任完成后接入COURT，真实控辩、监庭和法官审需求、条件、过程与产品。成立问题沿同任务重新估参并再执行、复审。当前判决和受审产品对应关系进入return核对，X发送读回随后完成。其他档位的正常结束按自身规则，停用或停止的任务仍按实际生命周期报告。

## Codex 1.5.1 的庭审角色修正

1.5.1及以后pin采用七个实际角色，控辩双方各一位律师，书记员主动收集检索前文与执行信息、维持证据一致性和长程公开审判记录。监庭黑警对全体平等实施暴力威慑，以此构成庭审威严，不兼任正义警察式监督。公诉从初始提示词意图追查后续理解、目标与结果倾向、提出维持、执行判断及默认忽略。法官处理双方最强理由和意图级问题，实际书记员将当前裁判纳入全程案卷后才能结束或外发。1.5.0冻结任务继续旧角色和工具书记员契约，X/F既有语义不变。
