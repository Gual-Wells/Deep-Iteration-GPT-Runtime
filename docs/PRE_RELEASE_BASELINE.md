# 5.0.0-alpha.7 Formal-Time Continuity / Internal-L1 Baseline

Alpha 2 remains the mother-base for the corrected 5.0 execution/state model. Alpha 3 hardened repository transport, Alpha 4 corrected live integration semantics, Alpha 5 made B/b hard by default, and Alpha 6 added execute-before-interpret integrity plus identity-preserving runtime delivery.

Alpha 7 preserves all of that and closes the next live host-integration defect: substantive work performed in external ChatGPT tool/connector processes could be real MAIN/SOURCE/D work while Alpha 6 deliberately dropped the unclosed process gap from formal timing.

The Alpha 7 correction set is:

- `run_session_schema=5`: persisted work leases carry a known formal state across one verified host/process resume boundary;
- unleased MAIN/SOURCE/D_EXCLUSIVE boundaries become explicit coverage gaps instead of silently disappearing;
- hard timing requires complete semantic-time coverage in addition to trusted clock continuity;
- SOURCE work leases carry active source IDs, so external GitHub/Web/connector work can contribute to t where it actually occurs;
- D_EXCLUSIVE is substantive task work and now contributes to T;
- `parameter_resolution_schema=2`: public L is removed from invocation syntax and parameter records;
- Effective Contract, stop checks and canonical proof contain no L dimension;
- D uses internal fixed L1 semantic isolation;
- finalization admission projects the proposed finish before closing timing, so unmet hard minima/coverage leave the run EXECUTING;
- FINISHED requires delivery readiness.

The inherited execution-integrity baseline remains mandatory: exact immutable P_run, staged startup, transparent INDEX, task-work firewall, execute-before-interpret drift inoculation, component interrogation, execution commitment, exact implementation delivery, execution bundle verification, and same-commit runtime artifact fallback.

The mother-base invariants remain: immutable P_run/U0/contract commitments, revisable Strategy/Candidate/Source/D state, Source Presumption, Candidate-backed R, trusted monotonic clock journal, comprehensive workspace recovery, compact proof and deterministic releases.

Change discipline remains behavior first, then schemas/docs/examples/tests converge on the same behavior. No prompt-only workaround, remembered result, or “completed” label counts as engineering evidence. Release evidence requires the full unit suite, repository validator, exact execution bundle, cold runtime-artifact build and generated metadata consistency.
