## 独立问题表征

用户并非只在结束后核对协议是否跑过。他会在工作中扫一眼、离开后回来、看到异议时介入，也会最终检查作品。因此，需要在三个时间点读懂不同东西：

- 工作进行时：当前到底在解决哪个会影响成品的问题，为什么值得投入；有何具体主张正在接受研究。
- 独立返回时：究竟做了什么、得到什么，哪些结论还没经过 Main 处理，哪一处仍存在分歧。
- Main 处理后：采用或拒绝了什么、依据是什么，具体改变了成品哪一处；若只是改计划或留下问题，应当能看出来。

身份的用途是把这些内容接起来。N/R 的工作职责和目的、D 的干预对象和主张、V 的方向和立场都可以帮助读者；但只给身份命名，不能替代这条关系。

我的立场是：**读者首先应能看见工作在改变什么，再能核对是谁、何时、在何种责任下做了它。** 时间、计数、真实代理与状态仍需如实显示；把它们放到阅读入口并不能自动增加内容透明度。这是设计判断，不是已经观察到新界面更好用。

## 固定材料真正支持什么

stable 的 `entry/DEEP_ITERATION_ENTRY.md` 明确区分承诺冻结与策略可改；META 不应预先解决任务或冻结详细策略。它也要求真实任务结果优先，随后紧凑证明，不把工作区变成面向用户的协议报告。`core/75_DISRUPTIVE_GAMBIT.md` 则把独立结果、Main 评价及具体后果区分开。可借的是这些责任，不能由此推出“过程应当不显示”。

main 的 `entry/MODEL_PROTOCOL_SOURCE.md`、`core/76_PERSISTENT_VIEWPOINT.md`、`core/85_AUDIT_LOGS.md` 增加持久私有 V、无 V-to-V 通信、紧凑回传与独立分类日志；日志可返回或持久化。它没有要求读者每次先穿过全部分类字段才看见工作内容。main 的公开参数组序 `N,T,R,B,S(n,t,r,b),D(s),V(o),L(e)` 适合用来保持初始化的语法辨识，不必另造一套身份参数。

Codex0.4 已有重要纠正：START、RETURN、END 不再混同，V 保持同一线路的再入身份，未知时间不补造。不过，当前 N/R 模板先放时间、墙钟、目标，再放问题；D/V 也先放运行字段再放实质内容，且尚无简短、可持续追踪的工作身份。这造成一种可检验的风险：事实虽然在消息里，读者仍需逐行解码才能找到争点。**这里没有拿到一轮实际 Codex0.4 的读者观察，不能把风险写成已发生的普遍失败。**

上一轮回看已经说明，L3、completed、三名代理、三条来源路线与第二次返回都不能单独证明 D/V 的单位责任。D3 的一稿制作没有完成原设想中的不同路线比较。身份若写得更雄辩而不增加实际研究，会再次放大这种错觉。

0.3 的留痕比较提供了可以直接使用的内容：一份 WORK 能在样例中保留用户纠正、部分采用和未处理返回；JSONL 能按关系筛出 Main 处理记录缺失；两者都不保证初始意图正确。两份取回范围不同，字符数不证明效率优劣。这足以支持有内容的呈现试作，无需为本题再造日志系统。

2. [OpenAI API deployment checklist：assistant phase](https://developers.openai.com/api/docs/guides/deployment-checklist#set-up-the-assistant-phase-parameter)，实际读了该小节正文与前后例子。它区分中途工作消息和完成回答，并要求后续历史保留相应 phase。它支持区分消息性质，不证明某种自定义状态标题更易读，也不要求所有进度都写成日志。
3. [openai/codex #27587](https://github.com/openai/codex/issues/27587)，读完整主帖与两条回复；2026-06-11 创建，本轮获取时仍 open。作者以实际会话提取的指令为依据，报告证据不足前的状态叙述与表演性协作，并提出按实质事件反馈。它是用户报告及作者归因，没有受控行为对照，不足以证明频繁反馈必然损害正确性。值得拿来检验的是“此句究竟报告了已知事实，还是只制造进展感”。
4. [openai/codex #28058](https://github.com/openai/codex/issues/28058)，读完整当前主帖；评论定向读了作者对生命周期日志与实际任务文本的区分，以及[反驳](https://github.com/openai/codex/issues/28058#issuecomment-6432449637)、[作者更正](https://github.com/openai/codex/issues/28058#issuecomment-6438294788)、[一个 App Server 0.164.0 的具体复核](https://github.com/openai/codex/issues/28058#issuecomment-6499350737)。材料区分“知道代理运行过”和“知道它受托做什么”；作者也承认此前措辞使没有解决的问题看起来像有了进展。本线没有独立审计其所有源代码或复现该版本，不把它描述成本机当前缺陷。它提醒我们：可读摘要是摘要，不能证明实际接收的密文内容，更不能用身份名和结束状态替代任务与后果。

两类社区诉求不互相抵消。用户需要能检查的工作内容，也会被无内容的状态叙述打断。可以复用原生任务消息和产物路径，再由 Main 公开简明的实质取舍；没有必要为此把 V 的私有探索、完整历史或隐藏思维链公开。

## 同一内容的三种呈现试作

以下借用上一轮“是否强制完整事件库”的已确认材料，**只比较写法，不是历史逐轮实况，不补时间，不把历史 L1 重新认证为 L3，也不新增 D 计数**。三个版本都必须保住相同事实：样例保留了什么、JSONL 的额外能力、Main 的默认选择及未实现的自动找漏。

### A：运行字段先行

```text
[DIGR D01 RETURN] 时间=? | 墙钟=? | 历史隔离=L1 | 独立实作与结果=WORK保留了纠正、部分采用和未处理返回；JSONL可按关系筛出缺处理记录；两者均不保证意图正确 | Main=待处理
[DIGR D01 END] 时间=? | 墙钟=? | 本轮墙钟=? | 采用=WORK默认、record可选 | 未采用=强制JSONL | 主线实际后果=保留自由笔记；没有自动追踪全部未处理返回
```

内容并没有缺失。主要阅读代价是：读者得跨过重复元数据，并把“采用/后果”的字段自己接回原先的具体争点；后果末尾也容易被误读为一项遗留失败，而非当前主动选择的能力边界。

### B：研究者名片先行

```text
D01｜恢复体验研究者。职责：保住重要判断；立场：记录结构不等于意图正确。
实际比较中，WORK保留了纠正、部分采用和未处理返回；JSONL还能按关系筛出缺处理记录。
Main采纳WORK默认与可选record，拒绝强制JSONL；没有实现自动追踪全部未处理返回。
```

名片说明了研究者关心什么，但没有把“它要干预现有哪条路线”放清楚。若每次重复，身份说明会遮住更新；若固定成“反形式化者”，又会诱使它继续反对已无问题的对象。此处仍有正确内容，不能只因文字较自然就判定更易用。

### C：具体干预与已发生后果先行

```text
[DIGR D01 START] 试作“WORK作默认、JSONL按漏处理需求启用”——干预“所有任务必须先建完整事件库”的路线。
比较同一段纠正、异议、研究返回与Main处理，在两种方式中能否取回；不以视图长度评优。
事实：时间/墙钟=?；历史隔离=L1。此处只重排已确认的历史内容。

[DIGR D01 RETURN] “WORK作默认”得到有限支持，“可以完全替代自动找漏”没有得到支持。
WORK样例保留了纠正、部分采用和未处理返回；JSONL还可自动筛出缺少Main处理记录的返回。两种记录都不能保证最初意图正确。Main尚待处理。

[DIGR D01 END] Main保留WORK默认，采用可选record；拒绝把JSONL设成所有任务的必经路径。
依据是现有能力已满足这个样例，而非WORK更短或已证明长期不漏。相应责任已进入协议/工作台；自动追踪全部未处理返回没有实现，真实反复漏处理时再研究关系索引。
```

C 仍用紧凑 ID/边界方便引用，但具体对象、研究动作和取舍在句子中成立。它比 B 更能回答“当前方案为什么改变”；比 A 更少要求读者自行拼接字段。**这是基于文本内容的可回答性检查，没有真实读者实验，也没有测出注意力节省。** C 还暴露一项需要继续改的缺点：复杂介入的完整后果若每次重写，会变长；返回只应更新新增事实，最终处理再给确切采用与产物位置。

## Main 转交的问题：强主张会不会冒充已证实结论

会存在这种可辨认的误读路径，不能仅靠 D 的“独立”身份消除。

`D01｜取消强制JSONL，改用WORK` 同时像介入者主张、对 Main 的命令和已生效决定；`D01｜WORK比事件库更好` 又混入未经证明的经验性优越主张。用户若只扫标题，正文最后一句“待处理”未必能抵消前面的完成感。这里指出的是句子含义的歧义，尚未实测有多少读者会误读。

可保留足够强的内容，用当时真实的工作动词承担阶段信息：

```text
试作中：D01｜试作“WORK作默认，JSONL按漏处理需求启用”。
已返回：D01｜样例支持保留WORK默认；自动找漏能力仍有差别。Main待处理。
部分采纳：D01｜Main采用WORK默认与可选record；不采纳“完全替代自动找漏”的扩大结论。
```

这不是每条附加“可能有误”的免责声明。第一句使一个鲜明提案可以被检验；第二句报告实际所得；第三句只在 Main 真正处理后出现。若没有做比较，只能写“提案/待研究”，不能为了标题有力而用“已证明/突破/优于”。规范性主张“默认应如何选”和经验性结论“某方式能自动做什么”要分别承担证据责任。

被反证时，ID 和干预对象可以保留，原主张不能继续以当前结论的口吻挂在标题里。用此前真实串节错误做一个独立的格式小样：

```text
D02｜检验“标题清单不变就不会发生取回串节”。
返回：标题未变，通用记录仍归入最后子节；这个判断前提被反例推翻。
Main：修正父节插入位置，并回看实际取回内容；不把topics数量继续当正确性证明。
```

反例来自 0.3 已确认的父节/最后子节归属问题；上述“D02”只是呈现示例，不声称历史曾有这项 D。反证的是一个具体经验命题，不是研究者人格，也不代表一份 WORK 的整体路线被推翻。它还说明“未证实优势”与“被反例推翻”应分开：历史 0.2/0.3 行为试作持平，不能写成已证明新版完全没有优势。

若 Main 只接受一部分，可以保留 V/D 与 Main 的不同立场，并准确说出差异。不必把返回改写为全体同意，也不必为了让身份显眼制造争论。Main 将具体异议转交同一 V 再研究；V 之间不直接传阅。

## 可以进入候选的身份与初始化方式

N/R 是工作单元，不需要装扮成两位人物。N 的短名表明本项推进对交付的用途，例如“让读者分清返回与已落实”；R 表明重开整套候选所追问的价值，例如“重审整套输出是否仍把流程完整当成品可用”。仅写“研究/审核/检查”不足以识别工作。

D 的短名连接正在被干预的对象与可执行主张，例如“试作WORK默认、JSONL按需”。强度来自会改变什么以及怎么试，不来自口号或确信程度；提案、试作所得、Main 决定用真实阶段动词区分。

V 的首次可见身份应给方向与立场，例如“阅读工作流｜用户应能当场分清建议、Main取舍与成品变化”。随后沿用短名及同一线路 ID，报告当前追问与新发现即可，不每次重播自我介绍。方向与价值关注可持续，具体经验判断可被新候选改变。异质性要看实际不同的问题和所得，标题差异不能认证 V3。

初始化可沿用 main 的公开参数组形，而不是给身份另开参数组：

```text
[DIGR INIT OK] DIGR(N…,T…/软或硬,R…,B…,S(n…,t…/软或硬,r…,b…),D(…),V(…),L(3)) | source=…
时间=实际本地时间及偏移 | 墙钟=实际累计或? | P_run=版本@完整SHA | clock=实际能力
```

这是版式占位，不是本轮初始化，也没有替 Main 填时间。需要保持有效值、软硬时间、来源、版本/pin 与实际计时能力；不能靠省略事实来缩短。初始化只确认投入合同与已知交付对象，不能提前印出 N01—N12 的固定工作标题、尚未成熟的 D 主张，或未启动的 V 人物名册。各身份在对应工作真正形成时出现，避免把可改研究路线冻结成承诺。

每条实质消息宜先给紧凑边界与有内容的工作身份，紧接实际问题/所得/主线反馈，再放该阶段必需的事实字段。真正需要用户及时纠正的变更不能只存笔记；已有原生任务与产物路径足够时就引用它们，不另造身份数据库。

## 成熟 D 候选：把展示中心从生命周期改为工作对象及其后果

**问题。** 现有输出虽区分 START/RETURN/END，但组织仍围绕运行元数据。单纯追加更丰富的角色名片可能继续把读者引向“谁在表态”，甚至使尚待检验的主张获得结论感。

**主张。** 保留真实边界、完整投入事实与独立代理事实，将整套可见流改为“工作对象/当前主张在先，实际所得与 Main 反馈相接，运行事实随后”。这应同时影响初始化、N/R、D/V 与最终返回，不是只改几个昵称。它不改变单位责任，也不减少高投入。

**可执行介入。** Main 提供一段真实候选及原始事实：初始化、一次主线推进、一个独立返回与其后的真实取舍。由承担该介入的独立上下文做两个内容等价的完整短片段：现行字段先行版与工作对象先行版；都保留待处理、反证、部分采纳和未知事实。直接据原始材料核对它们有没有悄悄把“提议”写成“已执行”、把“持平”写成“被反证”、把“返回”写成“已落实”。产出可供选择的短片段与针对当前 P_target 的少量规则替换文字；不建新日志系统或测试框架。

**怎样观察。** 在不用读内部笔记的前提下，检查每个片段能否直接回答：当前在为哪项交付工作；什么主张正在被检验；哪些工作确实发生；Main 接受/拒绝了什么；成品到底哪里变了。再看有力标题是否让返回前就像已有结论、部分采纳是否被抹成全盘通过，以及 V 再入时是否仍要重复大段名片。只有实际请读者阅读并得到回答，才可以主张观察到了阅读效果；仅凭研究者自审只能说文本承载了哪些事实。

**可能推翻本主张的结果。** 若工作对象先行版使同一返回难以定位、重复更多、掩盖计时或责任，或更易把提案读成 Main 决定，就应保留现行版或只局部调整。也可能 INIT 适合参数先行，而实质工作更新适合对象先行，整套不必同一视觉重心。

目前只形成了以上可执行候选与试作，未获取本轮真实候选和 Main 当前采用结果；不能宣布介入已完成。
