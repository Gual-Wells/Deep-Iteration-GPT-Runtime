# 初始化、稳定身份与 Main 中介交流：独立视角研究

本文件保存“交流能否真实运行、信息边界能否保持”这一持续 V 的公开研究与后续再入，不读取其他 V 笔记、不与其他 V 发消息。初轮的格式与会话试作不是已生效协议或真实 N/R/D/V；后续实际材料、研究与 Main 处理另作明确说明。

当前研究入口为文末“V03.2：从 C1 到 C4 后怎样继续协作与综合”。初轮呈现方向的 D 提案未作为 D03 启动；后来另行实际执行的是回应关系干预，见自有 `D03-coordination-intervention.md`。Main 已将其中心结论写入设计 C4；这不表示 canonical 已改。

## 当前判断

建议用**有意义的工作身份 + 实际执行者 + 所针对的候选/问题**组织交流。编号可以保留为短锚点，不能独自承担身份。Main 可以同时承担许多 N/R；不能把模型内部的工作轮次画成额外代理。D 的身份来自“介入什么、主张改变什么”，V 的身份来自持续的问题表征或价值关注。

独立 V 应始终通过 Main 获得必要材料与质疑。Main 不复制别的 V 的工作历史，也不要求 V 去“和另一位讨论”。主线可以转交一个值得检验的命题或反例，但必须把它当待检验问题，不能将“另一位已经同意”当证据。V 的返回、Main 的选择、选择是否落实是三个不同事实。

这些行为可直接用现有原生代理、消息、结果文件与一份主线笔记运行。不需要先建消息服务器、事件数据库、共享聊天室或通用日志平台。共享文件系统意味着“不读其他 V 笔记”仍是明确的信息使用约束，不能宣称宿主已经提供操作系统级文件隔离。

## 初始化应告诉用户什么

初始化是本轮**承诺与能力事实的起点**，不是已经完成工作的缩影。必须区分：参数已确定、代理已启动、隔离条件实际成立、贡献有效、候选交付成功。前一项不自动证明后一项。

建议保留 stable/main 已有的公共顺序 `N,T,R,B,S(n,t,r,b),D(s),V(o),L(e)`，用统一的参数句式连接调用、初始化与最终实际报告。初始化只列已生效目标；最终才列目标/实际。不要在初始化把 D/V 计划数画成已上线代理，也不要把 L 目标写成全程实际等级。

### 候选 A：参数句式为主

以下是格式试作，不是本次研究的初始化；尖括号须由任务实际补齐。

```text
DIGR 初始化：N≥12，T=<软目标时长>，R≥4，B=0，S(n≥<值>,t=<软目标时长>,r≥<值>,b=0)，D≥3，V≥3，L目标=3；source=REQUIRED。
Codex 0.4 · pin=1c5665b91cc1209eb20bd9b058c9e28bc4a44827 · MODEL_NATIVE；计时=<实际能力/未知>，实际时长=?；D/V=待启动。
```

优点是读者容易把目标与返回的实际对照。问题是如果还承担当前版本固定 `[DIGR INIT OK]` 锚点，直接替换会造成旧格式不连续。

### 候选 B：保留 INIT 锚点、改成两条可读表达

```text
[DIGR INIT OK] N≥12，T=<时长，软>，R≥4，B=0，S(n≥<值>,t=<时长，软>,r≥<值>,b=0)，D≥3，V≥3，L目标=3；source=REQUIRED。
版本=Codex 0.4；pin=<完整SHA>；时间=<实际工具读数及偏移>，墙钟=<实际已记录值/?>，T/t计时=<实际可用方式/未知>；D/V尚未启动，实际隔离逐项说明。
```

B 更适合作为渐进修订候选。它承接现有初始化要求，同时把“全部参数已确定”与“实际工作待发生”分开。初始核心问题、Main 的职责和已实际启动的独立视角随后用有内容的文字交代，不把十二项 N 预排成十二个空格，也不为满足 V3 预先假造三位已经到位的角色。

任何关键参数或显式约束冲突仍未解决时，不输出 OK。时钟未知本身不使所有参数初始化失败：写明能力缺口，不能把 `T/t=?` 改写成“已验证软/硬时间”。`source=auto` 应先完成实际来源判断；不能把 auto 留成未决而称全部落实。`source=off` 及其他显式值按原义处理。

初始化不承诺完整分工表。工作对象尚未形成时，最多说明当下已经有依据的工作焦点。D/V 的名字在真实启动、获得真实代理地址之后再出现。

### 返回候选：先作品，再同序目标/实际

最终仍先给结果和一个当前入口。可借 main 的公共排列，但必须显式称为执行事实报告，不能因长得像 canonical proof 就冒用其证明等级。以下也是模板试作，不是本次研究的实际统计：

```text
<实际结果与可用入口>

DIGR 执行事实〔MODEL_NATIVE，非canonical〕
DIGR（N<目标>/<实际或?>，T<目标>/<实际或?>（+D<实际或?>，+V<实际或?>），R<目标>/<实际或?>，B<政策>，S<实际工作面数>（n<目标>/<实际或?>，t<目标>/<实际或?>，r<目标>/<实际或?>，b<政策>），D（<目标>）/D（<实际或?>），V（<目标>）/V（<实际或?>），L（3）/L（<有依据的实际或?>））
依据与限制：<计数来自哪些真实工作；时钟/隔离哪些已观察、哪些自报或未知；仍影响使用的未完成事项>。
```

这里的 D/V 时间只有真实分段计时才给数；缺失写 `?`，不能把排队墙钟或代理时长相加。T/t 的软硬政策与初始化相同。目标/实际相等不等于作品质量已经证明，actual 更不能由已发送消息数、文件数或 END 标签数推出。仍有返回未处理、决定未落实或单位责任未满足时，必须在相应实际与结果状态中如实保留，不能为了一个整齐尾行改写为完成。

这只借用 stable/main 的可读排列；不移植 `digr.commit_delivery`、terminal seal 或根 runtime 的默认参数。当前 Codex 若无法提供 canonical attestation，就不把此行称作 canonical proof。

## 稳定身份：工作是谁的，谁实际执行

身份至少要能回答两个问题：“这项工作为什么存在”与“谁正在做”。只有编号不能回答前者，只有角色名也不能回答后者。

| 类型 | 名字来自哪里 | 示例工作身份 | 实际执行者的表达 |
| --- | --- | --- | --- |
| N | 当前要推动的职责或问题 | `N03「初始化的承诺与能力」` | `Main`；若借助研究者，说明研究者只提供哪部分材料 |
| R | 重新开题的目的、关键假设和真实候选 | `R02「从中途纠正重审整套协作方案」` | 通常为 `Main`；不能凭另一个角色评价自动算整体 R |
| D | 介入对象与足以改变路线的主张 | `D02「过程界面：改由真实问答组织」` | 实际独立代理路径；同时给出人可读简称 |
| V | 可持续研究的不同问题表征或价值关注 | `V02「异议可持续性」`，关注“主线新结论是待检验材料，而非要求收敛的答案” | 实际独立代理路径；线路与某次回传分开 |
| S/n/r | 来源所支持的问题及其推进/重审目的 | `S1「共享上下文与消息生命周期」` | Main 或明确的来源研究者；网址不是 S 身份 |

编号只作短锚点，不替代名字；真实代理地址只在首次映射、地址变化、需要核实来源时完整出现。Main 的小型映射可以放在已有工作笔记一行，不另造全局身份注册表。

```text
V02「异议可持续性」 → agent=/root/v_dissent_continuity；独立输入；自有笔记=<该线路路径>；交互对象=Main。
```

“稳定”不是把旧名字永远冻结：

- 同一职责研究后改变结论，保留工作身份，说明判断怎样变化。不能把换了结论当新 V。
- N/R 的问题发生实质变化时说明转向，不能通过换名把一项完整工作切碎凑数。
- D 在成熟介入尚未执行前可以修订主张；已承诺并执行后若核心路线错了，应如实说明中止/重开，不能覆盖历史。
- V 的立场是观察方向，不是“无论证据如何都必须反对/支持”。已经不适用时可给出排除结论；若真要换成另一个方向，应公开变化，不把旧线路悄悄改名后补成一个新视角。
- 槽位释放后再激活同一 V 上下文仍是同一线路。若上下文丢失而创建新代理，应写“同一研究线路由新代理续接”，不能声称同一个代理一直运行。

## 可直接运行的交流方案

### 信息只经 Main 形成必要往返

```text
用户的实际委托与纠正
            ↓
          Main ↔ D 的独立执行
            ↕
      每条 V 的独立研究

V 与 V 之间没有直接边；V 不读别的 V 笔记。
```

这个图表示允许的信息路径，不表示已启动的代理数，也不表示进程/磁盘隔离。Main 可以同时维护多条独立往返，不能用群发共识通告代替独立研究。

### 首次交付给独立线路的内容

使用原生 `spawn_agent(..., fork_turns="none", ...)` 时，提供：用户用途与已确认要求；该线路自己的研究问题/介入主张；必要事实、当前候选或代表性材料；允许使用的材料和自有结果路径；回传给 Main 的问题与边界。输入应足以研究，不复制 Main 全部推导，不先要求得出某答案。

一段可运行的 V 输入试作：

```text
工作身份：V02「异议可持续性」。交流对象仅 Main。
用途：用户要看见有内容的研究与交流，同时保持 V 独立。
已确认要求：V 不直接通信，不读他人 V 笔记；N/R 不能伪装成独立代理。
当前材料：C2 的“初始化”和“反馈”两段（此处放确切文本或已固定的对应材料）。
问题：C2 怎样让一次旧返回被误读成对新候选的认可？请独立查证并做一个能推翻当前设计的场景。
可保留或改变判断，不以找出缺陷为硬要求。
只写自有笔记；不要读取其他 V 的研究历史或代理清单中的他人任务内容；需要资料向 Main 请求。
返回：说明回应哪个候选/问题、发现与依据、适用边界、建议 Main 处理什么。不要替 Main 宣称已采用或已完成。
```

在本宿主，共享文件可被技术性访问；以上是实际使用边界，不能称为 ACL 强制。`fork_turns="none"` 只证明不继承完整父历史这一选择；L3 仍要有真实身份、独立指令/执行与工具生命周期、受控实际输入和后续信息流，不能靠一个参数字样包办。

### Main 再入时只交必要增量

新候选/重要材料出现后，Main 把相关候选与新事实交回原线路，并说明当前要回答的问题。允许带回必要质疑；不转发其他 V 全文、笔记路径、完整任务历史或“大家都同意”的压力。

原始证据的出处要保留。若质疑来自另一路意见而非已证事实，应明确标为“Main 转交的待检验命题”，不能洗成用户要求或来源结论。无需让该 V 知道其他 V 的完整发现；也不能通过过度过滤藏起会推翻候选的重要用户纠正或失败证据。

```text
Main → V02「异议可持续性」；针对 C3“名字替代编号”这一段：
Main 转交的待检验命题：同一职责会跨多版候选反复出现，纯名字可能使旧答复误关联。
新事实：用户要求对外看到真实交流，不要求建设消息系统。
请研究命题是否成立；若成立，用最少必要表达解决；若不成立，给出能支撑保留的材料。
```

这属于 Main 对独立 V 的必要反馈，不构成 V 间直接交流。不能把这个问题描绘成“V甲和V乙已经讨论完成”。

### 排队、恢复与回答的语义

正在运行时，`send_message` 可发送必要事实或修正；它不启动新 turn。空闲线路需要实际再研究时用 `followup_task` 激活既有上下文。成功排入消息只证明发送动作，不能先报代理已读、已经认可或已经开始新实作。避免为了礼貌确认再造一轮空回复；实质返回本身可以说明其回应范围。

在同一条线路有多个未答问题时，消息首行带一个可读问题锚点及所针对的候选，如“回应 C3／旧返回误关联”。无须先建设通用消息 ID 平台。若只写可变文件路径，应附上当前版本名及关键原文；涉及并发修改时固定相关内容，不能让 C2 的输入偷偷变成 C3。

对强制停止/取消，使用真实中断机制并核实状态；不能因为一句停止消息已排队就声称代理已停。恢复不重设旧计数或假造连续时间。

### 对用户显示真实动作和结果

原生工具日志是否直接对用户完整显示，不能由协议假定。Main 在用户可见流简洁转交实际发生的交流；只在真实派发/返回后说它已经发生。Main 的转述应标明来源，不假装自己写出的模拟对话就是代理原文。

