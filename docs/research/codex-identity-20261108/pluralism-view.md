## 已观察失败与尚未证实的问题

[0.4 pin 的回看](https://github.com/Gual-Wells/Deep-Iteration-GPT-Runtime/blob/1c5665b91cc1209eb20bd9b058c9e28bc4a44827/docs/CODEX_RUN_REVIEW_20261107.md)足以支持三项具体判断。

1. D1 强在真的改了竞争路线：WORK 与 JSONL 的实物比较暴露了两者都无法保证最初意图正确，Main 因而拒绝强制事件数据库。关键不是 D1 的名称，而是它对“更完整记录是否解决问题”这一支配假设施加了压力。
2. D3 的独立工人真的制作了一稿，但未完成登记设想里的不同创作路线比较。成品有用与非局部介入成熟是两件事。把“正向创作倡导者”写得更鲜明，无法补出缺失研究。
3. 前两条历史研究线主要按公司/来源分工，确有再入和有用后果，但异质前提不够清楚；第三条“记录结构不等于意图对齐”更可能改变问题表征。不能反过来抹掉前两线的贡献，也不能据三个人、二次返回认证 V3。

0.4 的正文其实已经禁止上述混淆，也要求允许研究者质疑问题划分。因此我不主张“重写一套更严格原则”就算改好。格式上的空隙是：D 的“非局部问题与介入”、V 的“独立前提/价值关注”仍容易由 Main 填成概括语；Main=<采用/部分采用>也容许跳过对中心论点的回答。仅靠字段是否存在，无法判断它们是否真的约束了研究。

尚未有证据证明：采用下文写法会改善所有真实任务；或每次公开身份都会使研究更好。这里提出可被实际候选推翻的设计，不把一个好例子写成模型效果结论。

## 一手反例改变了什么判断

本阶段先复用 0.3 的 WORK、当前说明和 claude-sources.json 定位证据，未阅读本轮其它 V 研究。只复核与本题直接有关的少量公开原文。

- [多轮 plan review 的作者原帖](https://www.reddit.com/r/ClaudeCode/comments/1t56l8c/how_to_stop_opus_from_producing_overengineered/)同时报告真漏洞和不断加入的不现实 fallback、迁移与未来重构保护，虽然写作者与评审者均被要求不要过度工程。没有 diff 或受控比较，不能估计发生率。它使我拒绝把“持续反对者”简单实现成持续找缺点的评审席。
- [Anthropic harness 作者复盘](https://www.anthropic.com/research/harness-design-long-running-apps)既报告独立反馈的收益，也报告共享评价措辞引导视觉趋同、中间版本有时更合意、复杂度随评审增长。它支持让 V 检查成功标准本身，同时反驳“一概撤掉评审就更好”。这不是 Codex 对照实验。
- [EMNLP 2024 的 persona 实验](https://aclanthology.org/2024.findings-emnlp.888/)在其四类模型和事实问答设置中，没有发现加角色身份的稳定整体收益。它只削弱“换个专家名字就更强”的推断；不能据此否定长期研究立场，也不能外推当前 Codex 的实际增益。
- [对 MAD 的系统性评估](https://arxiv.org/abs/2502.08788v3)发现若干辩论方法未稳定胜过较简单基线，并研究了模型异质性的收益。这里不增加模型、投票或付费比较；它提醒我：语义立场不同也不能冒充已证实的错误独立性。

我的推断是：身份应能改变某个“研究什么、怎样知道、什么算成功”的选择，交流应让有区分力的证据进入 Main 的路线判断。它们均不能由身份名或最终一致推出。

## 身份的实质：可以被观察到的认识承诺

身份不需要人设、性格或一串履历，也不需要每次强制填表。读者应能从自然语言辨认：这条工作究竟坚持什么问题、为什么当前主线可能漏掉它、什么材料能够改变它的立场。若把该线路换成普通资料工人，不需改写研究问题、取证方式或取舍依据，这个身份大概率只是标题。

| 类型 | 可以成立的身份或责任 | 容易造成的替代 |
| --- | --- | --- |
| N | Main 为当前一个交付问题承担推进责任；说清使哪个认识、路线或成品进入更好状态 | 给每轮起“架构师”“整合者”头衔，把既定动作逐条算推进 |
| R | Main 对已有完整候选采用新的实质审视方式；指明这次重开可能改变什么 | 同一评价表换一个审计身份，再检查局部错误 |
| D | 一次成熟介入的强主张：对哪项当前支配前提或路线发难，主张实际改做什么，如何用研究/试作回答 | Main 先定结论，再让“反对派”制作一份它指定的小样 |
| V | 对一个未被主线充分承担的认识、价值或少数假说持续负责；有自己的问题进展和可修订立场 | 按公司、网址或通用安全/审计岗位切分材料，始终回答同一套 Main 问题 |

强立场并不是“必须反对”。例如 V 可以坚持“当前需要的是更有野心的作品，而非更多纠错”，也可以维护一个后来证实合适的原方案。它必须允许根据证据改口，不能因保住人设而忽略反例。D 也不以 Main 接受为胜利条件；将一条诱人的昂贵路线研究到有据排除，可以有实质价值。

异质性也不要求方法和来源处处不同。两条 V 可以读同一原件、用同一工具，却在关键问题或价值上保持有用距离；不同公司/来源也确实可能带来不同认识传统。要检查它实际展开了什么，而不是把按来源启动的工作一律判出局。

反过来，不能把 Main 提供研究方向本身视为污染。Main 可以指出一个被忽略的价值、提供初始假说、分配题域，甚至请独立代理检验一项强替代方案。独立性取决于是否保留质疑题域、访问反证和改变结论的实际空间。代理自行起名同样不是证明。

## 初始化应该建立什么，何时建立

Main 转交的问题是：INIT 时填满所有身份和标题，会不会把可修订研究路线误写成承诺？我的判断是“可能，但不是必然”。应分清已经生效的责任、暂定认识和已经发生的执行事实。

N/R 的职责可以在 INIT 明确，具体轮题随真实问题、材料和候选出现而建立。此时不必预写 N01—N12 的题目；也不应把四次 R 提前固定成四个审计维度。用户明确要求的题目应保留，其余仍由实际研究改变。

D 的初始职责可以写清，但尚无成熟提案时就应承认尚在形成，而不是为“初始化完整”虚构三个反对对象。成熟提案出现后，声明针对对象、强替代主张与足以行动的路径；代理真实启动后才进入 START。若用户已明确指定介入题目，直接以它作为起点，不需要额外表演一次自发发现。

V 应尽早取得真实独立上下文并形成有内容的初始方向和立场；该立场可以由任务包提出，再经独立研究修订。OPEN 时区分“当前假说”与“已发现事实”，再入时围绕新候选继续追究，而不是从 Main 的反馈中猜一个它希望听到的结论。V 的方向不是不可变协议 pin，也不是未来产物承诺。

可在一段 INIT 说明中呈现四类责任及当前事实。例如“本轮由 N 推进实际展示候选，R 重开整个展示与执行组织；D 的成熟介入尚未形成，V 的持续题域已启动并会回传初始立场”。这不是要求新增一个“所有身份批准后才能工作”的阶段。参数成功初始化与 D/V 是否已有成熟内容是不同事实。

## 最小必要转交，不把 V 变成通讯评审团

当前用户已选定：V 始终独立，只由 Main 转交最小必要质疑，不允许 V 间直接交流。可据此工作，不需要新共识层。

任务包保留用户的实际用途、已确认要求和纠正、真实候选或相关材料入口、当前必要事实与资源边界。不要附整段 Main 推导、其它 V 的完整笔记、谁已赞同或“请支持我们已经决定的方案”。最小必要并不禁止 V 读取原件或请求遗漏信息；否则 Main 的选材可能把最有价值的反证挡在外面。

Main 转交质疑时保留可反驳的具体命题与必要事实。例如：“候选要求代理启动时就声明立场；若第一次独立研究尚未形成判断，这会不会迫使它预填？请检验哪种声明可以先写，哪种应推迟。”不需要传“另一位专家强烈认为你错了”，也不传赞同人数。若作者身份对于事实无关，可以省去；若论点必须依赖特定职责或输入边界，保留必要来源，不搞一律匿名。

收到新材料的 V 继续自己的问题，可以修订、保留或指出转交命题本身设错。Main 不把各线意见全部转发以促成“充分讨论”，也不要求它们共同批准候选。Main 内部发现两条研究实际上重复，就据真实贡献判断，不靠改名字凑出差异；必要时收窄或停止重复线路，但不能把排除一条有据无用的线路与从未做研究混为一谈。

## D 被反证时：改立场，不改历史

D 的身份应绑定介入问题和替代主张，不能绑定“我必须证明此方案正确”。强主张应当承担可失败的预测和寻找反证的责任，而不是更强的语气。

在提案尚未成熟时，允许同一 ID 下修订问题和方案，并标明哪项前提变了；不因每个版本新增一次 D。进入实际介入后，若按足够成熟的方法把主张反证了，且真正回答了原问题并回到 Main 实质处理，这可以是有价值的否定结果。Main 拒绝采用不自动意味着 D 失败。

若只是工具失败、输入不足、试作未完成，或者原问题尚未回答就换做根本不同的事情，不能把它写成“成功排除”。原项保留未完成/中止及所得，新介入需要重新形成成熟问题；另起 ID 只标识新的工作，不能把两次启动都算完成。不要为保住计数把原身份悄悄改成它后来已经做成的事情。

以本题为例，D 主张“去掉每轮重复身份，改用当前争点组织展示”。若实际代表性样例发现去掉身份后读者根本辨不出哪些是 Main 判断、哪些是独立主张，D 就应撤回去掉身份的部分，保留自己的反例与修订原因。同一项成熟比较的结论可以是“保留 0.4 结构，补充有内容的立场与反馈”；不能把它改名为“证明固定格式最好”后再计一次。

V 则通常以持续研究的问题、前提或价值关注保持同一线路，而非固定结论。例如本线路若发现一个由 Main 提供的强假说反而打开了有效研究，应修订“预设身份压缩探索”的判断，继续研究何种输入保留自主性，不另算一条 V。若真正放弃整个原题转入新题，保留原线结论及边界，不能通过改名制造额外有效线路。

## Main 的分析反馈要回答中心主张

“部分采纳，继续完善”不够。Main 应回答独立线路究竟改变了哪个判断，为什么接受、拒绝或暂缓它，以及当前实际动作/产物是否已经跟着变。并不要求每次长文，也不公开隐藏思维链；一小段有依据的决定摘要即可。

尤其不能只采纳方便的措辞建议，却回避 D/V 对任务框架的挑战。若 D 要撤掉整套流程，Main 只改字段名然后宣布“已采纳”，这属于没有处理中心主张。Main 可以拒绝撤流程，但应说明哪项真实用途仍需要它，证据是什么；随后实际保持或修改对应部分。被拒绝的强论点可以保留清楚的重开条件，不必反复转交，直到大家同意。

同样，不能要求每条 V 都改变候选，否则会激励制造差异。Main 看过竞争解释、反例与实际候选后保留方案是有效取舍。关键是这个保留有实质依据，而非以“总体方向一致”吞掉少数意见。

## 同一个问题的内容示例

以下均是设计示例，不是历史逐轮回放，不是本轮真实 START/END，不产生计数或已经修改 canonical 的声明。例子使用已核实的 0.3 回看事实来比较两种写法。

只有标题的写法：

> V02：认知多样性研究员。独立检查 D/V，认为要明确职责、加强反馈。Main 部分采纳，完善格式。

这段无法区分它与普通审阅工人，也不知道它认为当前路线哪里错。换成别的角色名，内容几乎不变。

让立场约束研究的写法：

> V02 OPEN：方向是进度展示对研究自主性的反作用。当前立场是：如果 Main 在初始化时替每条线路写好应发现的缺口，独立上下文仍可能只实现同一份任务分法。我会用 D1 的路线拒绝、D3 的一稿制作与两条按来源分工的历史事实，检查“身份清楚”是否真的允许改变研究对象。这个立场也须解释 Main 提供强问题为何有时有效，不能一概反预设。
>
