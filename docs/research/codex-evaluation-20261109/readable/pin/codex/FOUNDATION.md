# U0前置：共同决定要完成什么，再全面投入

U0保留用户原话及其上下文来源；任务说明是模型经研究形成、可被用户纠正的解释。保存请求、填满字段、冻结版本都不等于理解意图。前置交付的是用户能看懂、纠偏并决定的完整任务，以及有依据的投入选择。

## 进入与边界

EXECUTING取得同pin完整协议后先进入FOUNDATION。调用原文及显式参数立即保留；正式N/T/R/S/D/V/M的补齐、INIT和全面执行在关键决定明确后进行。前置独立定投入、记录与计时，不冲抵正式参数。专门委托研究或建设前置阶段的任务本身仍按自己的调用执行，不递归再造无限前置。

新任务先形成有依据的理解，研究足以让用户选择的关键分歧。已有明确确认的续做取回原决定、真实产物与未解问题，只讨论相关变化。短而清楚的任务可以用几句话完成，不因本协议先造工作台或重问已有决定。

前置可以查原件、运行已有入口、比较路线、做有界且可丢弃的小样，使用确有价值的独立研究。每项投入解释它帮助决定什么、预期得到什么可比较认识。不能以准备之名提前批量生产、全量深加工或另造复杂设施；也不以空泛提问代替调查。

## 研究后任务说明

先组织一个完整可辨的结果，覆盖必要内容；这是模型的内容责任，不是用户问卷：

- **目标与用途**：拿什么解决什么。原话、已确认决定、模型解释、证据、未决建议各有身份；例子、抱怨、灵感不自动成为建设承诺。
- **成品与范围**：最终形态、内容边界、关键质量、使用入口和何时可用；本次是完整任务还是用户明确选择的阶段，该阶段怎样通向整件事。索引、素材库、评测设施等中间件不冒充成品。
- **粒度与组织**：按什么单位取材、处理、制作和验证，为什么这层深度服务用途；给出最早可以比较的整体候选及扩展方式。命令、文件、知识原子和角色数不自动成为工作单位；不能不断精修一小块而留下全局空白。
- **已有基础**：实际取得、打开或运行过哪些材料、版本、代码、样品及旧决定；哪些直接复用、需调整、待核实、可放弃。路径存在、目录名和旧完成声明不代替实物判断。
- **依赖**：必要条件、可替代参考、条件增量及缺失影响、可行替代；区分不可变来源、允许修改的基础和生成中的候选，不因正常生产变化重做全部确认。
- **路线与投入**：真正有竞争关系的路线、剩余困难、预计工作量、前置预算、正式参数建议及理由、真实费用限制、未知和增投条件。比较完整交付差异，不只比较哪条路线容易造中间件。
- **完成与退出**：什么实际行为、文件或判断才算完成，什么只是支撑；哪些未知可以留待执行。研究本身是任务时，完整论证和选择可以就是成品，不强制软件化。

允许用连贯说明、原件、竞争路线或代表小样组织。若用户仍不能辨认最终结果，继续改善这个对象；不以字段非空、表格、角色和检查数量证明对齐。

## 问答与明确决定

使用宿主可用问答工具或对话，提出会改变成品、关键路线、粒度、依赖或投入的选择。先查上下文和已有材料，不让用户代替模型搜索本机信息。每轮优先少量关键问题，解释差异、推荐依据和后果，允许自由纠正、否定问题和提出新路线；不固定轮数凑完成。

答复要改变说明和下一项相关行动，并处理已造成的错误。局部回答只解决局部；沉默、超时、未反对、预选默认项或脚本成功都不构成全面开工确认。关键取舍研究到足以选择后，呈现当前完整说明与必要差异，取得明确执行决定。

用户已看过完整对象并说“把X改Y，其余照做，开始”，可以直接成立；保留原说明、差异和真实答复，不要求魔法口令。仅纠正而未表示执行时继续处理、保留待确认。确认针对任务和投入方向，不是逐文件、逐命令审批。

文字维护、不改变选择的新事实、已授权生产中的候选更新不自动撤销决定。用途、交付、关键路线、显著成本或用户负担变化，先展示影响，只对变化问答；旧确认不冒充对未见方案的同意。待决变更不扩入生产，原确认范围内不依赖它的工作仍可继续；旧路线整体失效时停下相关路线。

## 独立的资源研究

前置深度依任务规模、真实歧义、已有基础、研究难度和误判返工代价决定。结合独立材料，说明为什么需要这份投入、什么发现会改变选择、何时返回用户决定。大任务或高参数不表示每个中间片段都应全量深加工；成熟资产也不表示可以跳过关键意图差异。

比较真正有竞争力的直接复用、局部加工、重新建设或先澄清支配决定等做法。允许陌生研究先形成有内容的机会，不要求每个新想法即时量化收益。研究已不能改变关键选择时结束该支路；关键歧义仍在而需要显著增投时，带回当前认识、代价和替代，与用户讨论。

正式建议解释N推进什么、R重开何种完整候选、D争夺什么、V发展什么陌生领域、M为何需要独立整线。来源t包含于T；并行墙钟、调用量、工具执行与等待分别说明。无实测usage和单价就保留未知，不把参数乘成伪精确美元或把旧余额当新预算。用户显式正式参数保留，冲突先澄清，不为前置静默扣减。

前置没有固定N12/R4/D3/V3下限；可深研，也可复用已有确认。研究与正式投入分开显示，前置D/V、独占等待及问答等待不转算正式责任。来源研究仍记为真实研究，不标META使成本消失。

## 可见过程与工程接续

新任务在前置投入形成后显示：

```text
[DIGR U0 INIT] 前置研究
当前理解=<用途、完整结果、待查关键分歧>
投入=<本次深度、必要独立线路、预计范围与显式限制>
依据=<已有基础、返工代价及为何需要研究>
返回点=<什么结果足以作决定>｜增投条件=<何时再讨论>
正式配置=<保留用户原值；缺失部分待补齐，尚未全面执行>
```

中途用 `🟦 **U0｜具体问题**` 等身份报告实际所得与纠偏，不复读字段。确认后显示 `DIGR U0 CONFIRMED` 的结果、粒度、主要取舍和投入范围，再按PARAMETERS正式INIT。已确认续做只说明沿用什么、变化是什么。

复用一份WORK与现有session。REQUEST.txt保留原话；foundation.json保存当前解释、问题、答复来源和决定。foundation show产生可读说明，也作为执行提示与恢复输入；不让另一份相反的旧计划继续指挥。

新通道使用task create --require-foundation。前置先以COMMON和scope=FOUNDATION记录活动；明确决定后才进入scope=EXECUTION。CLI在受管理的正式实质begin/checkpoint检查当前确认，含独占D/V；end/recover始终可用。准备文件不等于开工，旧会话缺说明不自动补成确认。

工具保存模型解释和实际答复，检查版本与入口，不自动生成真实意图、认证用户身份、判断自然语言质量或拦截宿主全部工具。模型仍须服从真实会话的纠正和停止；CONFIRMED文件不凌驾于新消息。前置、正式、已执行和已观察效果分别报告。
