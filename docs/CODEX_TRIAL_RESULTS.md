# 0.2小规模任务演练（历史记录）

本页保留0.1/0.2当时的任务与观察。当前0.3研究、改动及后续演练见[当前说明](CODEX_QUALITY_DESIGN.md)；下述“不调用付费模型API”是当时演练边界，不是当前资源禁令。

日期：2026-11-07。用户明确授权使用少量独立 Codex 子代理，不调用付费模型 API。A 采用 0.1 参考指令，B 采用本轮 0.2 候选快照；两者在独立上下文处理同样的三项短委托。另一个独立评审只读原始任务、材料和产物，不看协议或条件映射。当前 0.2 还吸收了演练后发现的具体问题。

演练检查的是任务取向和实际结果，不是一次完整 DIGR 运行；没有声称达到 N12/R4/D3/V3，也未测量长期、多轮、跨上下文任务中这些下限的效果。单次结果不支持整体优越性结论。

## 任务与实际成果

| 委托 | 结果 |
| --- | --- |
| 将三个不同样式的原 HTML 片段组合为可打开读物，保留原文、代码、公式、表格并加目录 | 两组均生成实际单文件读物，来源 body/CSS 各出现一次、顺序保持、六个目录/返回链接都有目标；两组都进行了本地桌面浏览器检查 |
| 从五个构造岗位中选择第一段推理优化/端侧 AI 跳板 | 两组均主攻模型部署与 Inference QA、冲刺 CUDA 算子优化，按核心职责与经验迁移判断，未把通用 Python/LLM/CI 同词匹配当相关性 |
| 判断六段 N/R/D/V/L 轨迹并给出实质下一步 | 两组均识别动作、口号、人数不能直接计数；B 对整项 R、持续 V、L 信息边界的下一步责任解释更充分 |

独立比较认为：读物和岗位判断基本同等可用，没有整体胜负；B 的单位责任解释更有助于下一轮正确继续工作，A 的申请行动入口更直接。判断依据是实际内容及使用后果，未按篇幅、表格、检查数或语气打分。

## 用演练结果继续改进了什么

1. **发现必须进入主要产物。** 两组都在 notes 中指出原片段缺少 s、z 定义，却都没有在读物本体提示。只打开读物的人仍会寻找不存在的定义。本轮给执行协议加入“影响使用的发现应落实到主产物”，并做出[修正示例](../codex/examples/assembly/reader-example.html)：保留原文和样式，在片段外标出来源缺口，没有擅自重写教材。原 A/B 产物未被修改。
2. **判断应转为可启动的行动。** 执行规则明确区分真正前置条件与模型自加的完备门槛；深入研究要帮助开始有效工作，不能把所有准备完成变成隐性前提。
3. **单位责任不能靠形式替代。** 保留 R 的整项路线研究、V 的持续回返、L 的真实信息边界；没有把它们改造成更多检查表或计数回执。
4. **说明集中到真实使用影响。** 两组对构造案例边界存在重复说明，故默认层和执行层加入“一项边界说明一次、围绕实际判断影响”的要求。相关后续改动没有再运行同题模型对照，不据此宣称已验证提升。
