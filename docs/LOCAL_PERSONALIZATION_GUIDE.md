# Local Personalization Guide — Plus

The deployable local file is `local-personalization/CHATGPT_LOCAL_PERSONALIZATION.txt`. It targets ChatGPT Plus-class custom-instruction capacity; Free/Go compatibility is intentionally not maintained.

The local layer is version-neutral. After leading whitespace only, exact-uppercase `DIGR` or exact `深度迭代` is a route candidate. Lower/mixed-case English is native.

## Pre-task execution firewall

Candidate capture closes a task-work firewall. Until pinned repository startup and its delegated protocol have **actually completed** every prerequisite they define before substantive work, model reasoning/tools may be used only for repository acquisition, immutable pinning, INDEX/startup acquisition and runtime/protocol setup. User-task analysis, research, editing and result generation remain blocked.

Reading, understanding, quoting or summarizing startup is not execution. An EXECUTING classification is not task-work readiness. Repository-declared helper/workspace/state/receipt operations must be actually performed through available host capabilities; they cannot be replaced by conceptual acknowledgement. If startup cannot be established, use the pinned repository failure semantics rather than silently continuing natively.

## Repository transport

Before any task-level response, make a real repository acquisition attempt. Search/crawl/indexed snapshots are not mutable-ref authority. An already-connected GitHub connector may resolve the current public `stable` branch HEAD directly. A real REST client cross-checks the branch and Git-ref endpoints and requires the same full 40-hex SHA. Public DIGR bootstrap must not require a new OAuth/connector solely to read this public repository.

After pinning, every repository read uses the same SHA. Bind manifest/VERSION first. Pinned raw content is canonical; if raw content is unavailable, Contents API is an allowed same-SHA fallback only as raw media or after decoding the normal JSON/base64 wrapper into real file bytes.

## Execute-before-interpret

The local layer teaches one additional pre-task distinction without copying versioned N/T/R/S/D/L semantics: a repository-declared operational helper is an implementation to operate, not a description for the model to imitate. Before use, identify the exact component/operation/executor, commit to direct execution now, and reject semantic-equivalent rewrite/manual receipt construction. If incomplete, apply only bounded lightweight correction; after acceptance, go directly to delivery/execution attempt or a concrete failure.

When repository access and code execution are isolated, follow the pinned manifest's runtime_distribution path when available. Exact-commit artifact transport must verify member identity against the pinned Git tree. Bridge failure never licenses model-written runtime replacement.

## Structural transparency and handoff

If `bootstrap_index` exists, load it first. When it is also `startup_slice[0]`, read it once and then continue the remaining startup paths. INDEX exposes implemented helpers, workspace/state/schema objects, truth sources and the native-intelligence boundary without defining versioned DIGR execution semantics.

Broad capture is not takeover: pinned startup may return NATIVE, HELP, INVALID or EXECUTING. NATIVE returns the original message to ordinary ChatGPT. For EXECUTING the task-work firewall remains closed until repository-defined startup/protocol readiness is actually crossed.

The fixed route-failure string is not a shortcut. No current-turn acquisition attempt means the router was not executed; it does not mean repository acquisition failed. Once P_run exists, startup/runtime failure is governed by P_run and must not be rewritten as route failure.

Local text must never copy N/T/R/S/D/L/time/stop/proof semantics.
