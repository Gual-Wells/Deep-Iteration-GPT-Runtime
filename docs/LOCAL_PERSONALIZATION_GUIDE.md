# Local Personalization Guide

The local file is deliberately thin and version-neutral. It matches only after leading whitespace: exact-uppercase `DIGR` or exact `深度迭代`.

A candidate is a routing obligation, not an invitation to guess the outcome. The local transport pins `stable`, then binds pinned manifest/VERSION and follows the manifest startup slice. Before any user-visible answer, the host must make a real repository acquisition attempt. Search results/crawled snapshots are not mutable-ref authority. A direct GitHub connector may resolve the current `stable` head; the REST path cross-checks the ref and branch endpoints. Only after a full 40-hex SHA is accepted are pinned bytes loaded.

Pinned resources use immutable SHA URLs. The compact file names a raw-content URL first and explains the Contents API fallback only enough to prevent JSON/base64 wrappers from being mistaken for file bytes.

Broad capture is not takeover: after pinned startup is acquired, NATIVE returns the original message to ordinary ChatGPT. Legacy pinned manifests without staged startup follow their own declared navigation. Local text must never copy N/T/R/S/D/L/time/proof semantics.

The fixed route-failure string is not a shortcut. No current-turn acquisition attempt means the router was not executed; it does not mean the repository acquisition failed.
