# Local Personalization Guide — Plus

The local layer is version-neutral and Plus-only. Free/Go compatibility is intentionally not maintained. It routes exact-uppercase `DIGR` / exact `深度迭代`, acquires current stable, pins one immutable SHA, loads the structural INDEX/startup, and hands control to the pinned repository protocol.

## Pre-task execution firewall
Task analysis cannot begin until repository-defined startup readiness is actually complete. Reading, understanding, quoting or summarizing startup is not execution. EXECUTING classification is not task-work readiness: repository-declared readiness operations must be actually performed before substantive task work.

## Repository transport
Connected branch HEAD or direct REST branch/ref consensus may establish stable. After pinning, use same-SHA raw content; Contents API fallback must return raw bytes or decode its JSON/base64 wrapper. Do not require a new OAuth/connector solely for public bootstrap.

## First structural lens
The manifest `bootstrap_index` is the first structural lens. It exposes implemented helpers, workspace/state/schema objects and truth sources without defining versioned DIGR execution semantics.

## Package-level implementation boundary
If pinned startup declares a package-level attestation verifier, use that single boundary. It may verify many helpers and protocol members internally, but the host must not expand it back into dozens of per-helper fetch/interrogation steps. Direct execution and implementation identity remain mandatory; manual semantic-equivalent receipts remain invalid.

Local text must never copy versioned task-parameter/time/stop/proof semantics.
