# Local Personalization Guide

The local file is deliberately thin and version-neutral. It matches only after leading whitespace: exact-uppercase `DIGR` or exact `深度迭代`.

A candidate is a routing obligation, not an invitation to guess the outcome. The local transport pins `stable`, binds pinned manifest/VERSION, then follows the manifest's **bootstrap index before the remaining startup slice**. Before any user-visible answer, the host must make a real repository acquisition attempt. Search results/crawled snapshots are not mutable-ref authority. A direct GitHub connector may resolve the current `stable` head; the REST path cross-checks ref and branch endpoints. Only after a full 40-hex SHA is accepted are pinned bytes loaded.

The pinned `bootstrap_index` is the first structural lens. It tells the host/model what protocol files, executable helpers, workspace/state objects, schemas and truth sources are already implemented and where native model intelligence begins. This prevents ordinary Agent/runtime/host conventions from being substituted for repository-defined machinery. It does **not** copy versioned DIGR execution semantics.

Pinned resources use immutable SHA URLs. Broad capture is not takeover: after pinned index/startup acquisition, NATIVE returns the original message to ordinary ChatGPT. Legacy pinned manifests without a bootstrap index follow their own declared navigation. Local text must never copy N/T/R/S/D/L/time/proof semantics.

The fixed route-failure string is not a shortcut. No current-turn acquisition attempt means the router was not executed; it does not mean repository acquisition failed.
