# Berta2 Validation Contract

Candidate-package release requires all unit tests and `tests/validate_repo.py` to pass in the source tree and again after cold ZIP extraction. The builder regenerates bundle/model/Help/personalizations/descriptor/FILE_TREE/SHA256SUMS, rejects caches/symlinks/path collisions, uses fixed ZIP timestamps and verifies cold hashes.

Mandatory code regressions cover adaptive versus explicit standard completion; B/b missing-time completion; bare-duration soft compatibility; V plus policy composition; model-native execution under missing host capabilities; attestation levels; session-only clocks; semantic V independent of viewpoint_max; exact current Candidate primary payload; delivery schema v2 terminal-state digest; terminal seal; all nine logs; and recovery.

Promotion to mutable `stable` is a separate external gate. It requires preserved fresh-chat black-box results for representative open, B=1, S(b=1), full N/T/R/B/S/D/V/L and long-document tasks on intended iOS/Web/Desktop clients. This local delivery does not claim those external runs were completed.
