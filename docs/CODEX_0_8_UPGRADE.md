# Codex 0.8：调用、任务存续与默认返回闭环

本次升级修复的是从显式调用到实际交付的断点。默认高投入责任不变；根 stable、个人知识池与论文原件不迁移。先前视觉返回仅在可选手册中，不能期待后续执行自动读取；现在 RETURN 是 manifest.core 的正式成员，随七成员执行包获取。

## 实际行为

| 情境 | 0.8的实际路径 |
| --- | --- |
| `DIGR：只问原因，别推送` | 取得真实仓库后按完整调用执行深研究；不获得推送授权。 |
| 真正未完成任务中的普通补充 | 新来源先阻断旧动作；处理后沿用原决定与P_run，不重问全部确认。 |
| 结束后普通纠错或讨论旧漏调用 | 保持结束，不创建/恢复深任务；新的显式委托另建session。 |
| 实质改变结果、依赖或投入 | 旧决定失效，不能以non_material越过；原接受内容保留。 |
| 暂停、停止、取消 | 暂停禁止继续；停止/取消终结。真实停止来源能优先越过早先pending。 |
| 重投旧同意来源 | 不重新编号；同文字的真正新来源仍可表达新的恢复决定。 |
| 旧0.7工具访问0.8会话 | session-2使旧writer明确拒绝。旧pin仍session-1，不静默升级。 |
| 返回后改了成品、来源或选定工具文件 | 旧返回为STALE，不能据此正常close；重核、seal后才可结束。 |

任务状态、当前来源与foundation共用受管理入口。原文按实际UTF-8字节解码，保留Windows CRLF；消息引用和散列是本地一致性依据，不认证自然语言同意。STOP先落终态，再写历史/清理，历史失败不能留下继续资格。end/recover始终可用。

## 返回怎样使用

先给完整结果和一个当前入口，再直接说明关键所得、决定、实际后果与未落实事项。默认给时间×工作标识总图，细读在图后独立展开：行标题可用键盘/触控进入，重叠处先明确选项，详情分别显示执行者、版本、时间、依据与直接关系。毫秒/秒/分钟随跨度变化。资料缺时或不可比就保持未知，纯文字成果无需另造软件。

源与静态图/互动详情来自同一选定输入。选中偏好绑定数据指纹；旧候选状态不套用新版，状态回声不丢近邻选择。没有把收到、决定、落实合成完成，也没有把材料相关画成执行因果。原生选择和“返回图中”保留上下文；图后详情离部分工作行仍有距离。

从统一工具的task、foundation、clock、timeline与return命令进入，具体最短路径见[WORKBENCH](../codex/WORKBENCH.md)。每个任务CURRENT_RETURN.md指向当前返回。无需常驻服务、外部模型API或新数据库。

## 验证及证据范围

已经用实际API/CLI核对：完整只读调用、普通纠错拒启动、当前答复匹配、未处理消息/暂停/停止、真实续做、旧来源重放、CRLF、旧writer隔离、当前返回失效、同字节目录入口重定向及旧pin兼容。相关回归在test_codex_profile、foundation、session、lifecycle、return、timeline中。浏览器检查覆盖320/736及更窄内容区的密集事件、外域区间、跨M折叠、旧展示状态、短轴与无时钟出口。

当前合并候选完整套件实跑401项通过、2项既有跳过；关键调用/生命周期/返回/时间图另过57项定向检查。独立阅读复核实际发现并修复了连续方向键被抢焦点：候选与完整选择都能连续浏览且保留焦点；原说明移至标题后，元数据不删。静态及互动共享首行间距，实物检查没有轴刻度交叠。测试与浏览器事实分别看待，不由通过数量推断用户理解改善。

发布核对实际发现实验分支同时加入了独立Voice附属设施。先拒绝覆盖，再基于其提交保留原文件与统一入口的voice命令，解决voice/return并存冲突后重跑完整套件。该设施仍有自己的版本和启用条件，不改变本轮冻结P_run，也不把普通文本任务切入陪练。

独立研究改变了实现：放弃依赖手填宿主活跃标记；拒绝长行内详情替代全图；加入优先停止、来源去重与session-2；把源码承诺限定为磁盘文件与解析位置。完整旧用户对话和私人学习记录未进入公共交付。

## 保留的限制

本地入口约束不等于宿主全局工具拦截，也不能知道没有传入的消息/最终事件。模型仍须依据实际对话解释意图，执行停止并调用收口；正确原文字节也可能被误解为同意。快照不认证运行字节码、内容质量、责任数量或有效时长。一次性CLI缩小源码热变窗口，未建设执行器认证平台。

模式归因以实际执行片段为单位，区分DIGR、轻量、原生Goal、模拟/引用和请求但未履行；旧跨项目审计尚不完整，不能据此宣称全面收益或失败率。Chat适配本次只落实共同意图/来源/停止/返回及能力诚实边界；没有将单模型角色扮演计成L3，也没有另建未选定的Chat通道。

官方资料说明[活跃turn的steer与终结事件](https://learn.chatgpt.com/docs/app-server)及[Queue/Steer的区别](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)；本机实际schema另提示turn/start可把输入加到已有活跃turn。因而不能仅凭方法名或手填expectedTurnId证明接续。本次采用任务生命周期，而非另建宿主事件平台。
