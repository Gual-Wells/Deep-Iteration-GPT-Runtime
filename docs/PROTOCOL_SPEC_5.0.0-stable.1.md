# DIGR 5.0.0-Berta2 Protocol Specification Index

Pinned `manifest.json` is navigation authority. Its version must equal pinned `VERSION`, then its sole self-contained `entry/STARTUP.md` slice classifies the original broad-captured message and directs HELP or EXECUTING loading. `runtime-descriptor.json` is a manifest-navigated execution/release description for generated `dist/` artifacts.

Compact release/advisory model guidance is authored once in `entry/MODEL_PROTOCOL_SOURCE.md` and deterministically rendered to `dist/MODEL_PROTOCOL.md`; runtime loading is not implied. `dist/EXECUTION_PROTOCOL.json` retains the entry/core execution set in order with exact byte lengths and SHA-256 digests for host verification. `dist/HELP.zh-CN.md` mirrors canonical `entry/HELP.md` and does not start a task run.

Berta2 preserves the validated pre-stable authority/clock/state foundation and closes these release boundaries:

- broad candidate acquisition followed by pinned manifest/VERSION and STARTUP authority;
- explicit `D(0)` zero-minimum, never-disabled semantics;
- `DELIVERED`/`INCOMPLETE` terminal delivery distinction;
- deterministic dist and personalization generation;
- reproducible packaging with Python/test caches excluded.

Routing and transport are documented in `docs/ROUTING_CONTRACT.md` and `docs/REPOSITORY_TRANSPORT.md`; migration is documented in `docs/MIGRATION_FROM_4.1.1.md`.
