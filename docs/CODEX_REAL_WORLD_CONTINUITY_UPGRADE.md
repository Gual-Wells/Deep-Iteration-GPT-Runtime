# Codex 0.8.2：现实决策与未完成任务接续

本次更新作用于Codex候选通道的通用执行规则，对该通道后续各类任务适用。基线为0.8.1的`f0c532b2cccb7b89075ca108a5173330e4661789`；当前运行的P_run仍冻结在原版本，新版本不改写正在进行的任务、原记录或已初始化参数。根stable Alpha5有独立manifest、entry/core和时钟语义，不是本通道的执行来源。

## 现实信息不完备时仍完成工作

必读PROTOCOL、FOUNDATION、PERMISSIONS共同明确：有据中心判断与不确定性分开；未知不自动当成不利事实；可逆行动的证据要求匹配其实际后果。模型先查已有上下文和可得来源，只问确实改变当前决定且不能合理替代的有限信息。理想日志、全部标签、观察窗、单变量规则和额外确认不能自行变成行动资格。

这不要求乐观估计或撤掉真实安全、权限、费用与原件边界。它要求把限制落在真正受影响的决定上，并把等待、信息获取和执行成本也放进路线比较。用户已明确选择的速度、品质、成本或使用负担不能被代理偷偷换成别的目标。

构造情境：用户要尽快改善一个已有流程，只能描述常见使用情况，没有全量性能日志。合理做法是查现有代码/材料、用典型路径形成有据方案，先做可撤销的关键改动，再以实际使用更新。不能把“尚未证明长期因果效果”改写成“必须等齐完整日志才能做任何事”；也不能把典型测算说成已经测得的收益。

## 生命周期由任务状态决定

未依RETURN明确结束并收口、且用户未明令停止/取消前，后续用户消息都沿同一DIGR任务处理。追问、纠正、普通消息表面、宿主NEW_TURN、压缩与技术中断不重建前置、不清空责任、不重置时钟、不悄悄降为普通任务。再次命中候选前缀仍先真实获取；新取得的HEAD不覆盖原P_run。

明确暂停停止相应活动但保留未完成任务；普通补充不自动恢复。明确停止/取消按范围立即生效。技术中断只要求停止/核对当前活动与真实进程，不伪造用户终止，也不把计时缺口拼成连续工作。已终结任务的普通讨论不复活DIGR。

工具行为随之修正：

- `ActiveContext`必须显式传入真实`lifecycle_status`，不能从旧turn_id或缺省ACTIVE推断未完成。`NEW_TURN`保留ACTIVE的DEEP任务；PAUSED保持暂停；终结上下文不继承深执行。
- `COMPACTION`恢复实际状态；`INTERRUPT`只表示当前活动被中断。显式终结状态返回`PRESERVE_TERMINAL_STATE`，不产生DEEP恢复动作。
- `ordinary`是消息处置。在ACTIVE中保留状态、活动和Foundation，并更新任务输入锚点，使新的补充不能被旧封存返回绕过；PAUSED不因ordinary恢复，终结任务不因它重开。
- 已完成上游获取的NATIVE/HELP/INVALID表面可以在未完成任务中作为补充处理。表面分类决定能否独立创建新调用，不决定旧任务结束。
- `close_session(CLOSED)`复用既有`return_status`，要求当前可关闭RETURN及完全匹配的receipt；裸CLOSED和任意draft不能代替协议结束返回。STOPPED/CANCELLED继续优先，不要求先包装返回。

边界预览示例（状态必须来自实际任务，不是本JSON替它作证）：

```json
{
  "event": "NEW_TURN",
  "message": "补充一个要求，原任务继续",
  "active": {
    "turn_id": "host-turn-reference",
    "mode": "DEEP",
    "lifecycle_status": "ACTIVE"
  }
}
```

调用`tools/codex_profile.py boundary --input ...`仍只是预览，不联网、不认证自然语言意图，也不拦截宿主全部工具。需要迁移旧边界调用时，从现有lifecycle读取状态补入API输入；无需让用户重新确认任务。旧pin保持原工具链，当前任务不热换执行语义。

## 验证范围

行为测试覆盖跨NEW_TURN接续、明确暂停/终结、前缀获取义务、所有已获取表面、ordinary保留活动/决定/原pin、补充使旧返回失效及禁止裸关闭；继续覆盖真实STOP优先和结束后不复活。分发检查核对manifest/VERSION、完整执行包和散列。

这些测试验证工具的具体行为与分发一致性，不宣称提示词已经在所有未来模型任务中产生持续效果，也不发布任何个人任务资料。模型仍负责理解消息、落实补充和判断任务结果。
