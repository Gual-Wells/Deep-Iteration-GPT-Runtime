2026-11-08后续更新准备：另一段对话研究后，Main提出了D竞争生产、V自主建设领域能力、Main主动竞争与主线迁移的候选设计，以下相关段落已同步。用户随后明确指出，“保守”的批评针对语言、行为与策略气质的温度，并非要求继续改机制；因此这些机制提案保留为候选，不冒称该批评已被解决或新提案已获接受。当前研究焦点及官方、社区依据见[下一版更新准备](DV_AUTONOMY_UPDATE_PREPARATION.md)开头。现版0.5.1未改变。

## 已明确的设计决定

用户提出M默认1，以数值表示独立主进度数量；随后明确选择：**每条M承担完整责任，并且各自动态参数初始化、动态推进与收敛。** 全局共享一套N/R/D/V的方案不再是待选默认。

建议将M命名为**独立主进度中心数**。一个中心既负责内容判断与推进，也负责本线分工、反馈处理、进度和时钟。公共交流是共同职责面，不需要默认再增加一个只报时或转发的模型管理员。

## 1M究竟承担什么

1M是一条真实独立、可恢复的完整推进线。它面对同一个用户目标与已定要求，拥有自己的问题理解、参数初始化、资料策略、可评价的整体候选、N/R推进及S/D/V安排；实际处理返回，修改或有据保留候选，并把所得带回最终综合。

M的单位是持续主进度，不是消息数、阶段数、代理数或同时活跃的进程数。阶段空闲、内容定型和恢复不新增M；落选路线只要产生真实的整体方案或有依据的排除结论，也可形成有效贡献。只派出名字而没有实质推进，不计有效M。

V与D本来就能提出全局替代。M的新增性是对整条候选长期拥有推进、重新开题、资源安排与综合责任，不能仅用“更有异见”定义。把找资料、写代码、检查各设一组，仍可能只是同一主线的工种分工。

## 各M的自主参数与收敛

- M=1沿用现有Main；M=2是两条各自完整承担责任的主进度，不把N12分成两份N6。
- 各M沿同一P_run，得到原始用户问题、已定决定及必要原件事实，分别初始化N/T/R/B/S/D/V/L。未显式部分根据本线研究自行选择，总层不复制套餐或预编轮题。顶层显式参数和用户约束对各线有效，沿现有规则加深时说明变化。
- 当前N12/R4/D3/V3下限及Codex真实L3继续有效；不同线可有不同的更高投入、方法、T/t目标和节奏。M不递归复制给普通工人或D/V。
- 各M自己选关键问题、接受或拒绝本线返回、重开整体候选、调整方法和安排下一项工作。公共层可以指出冲突和新要求，不代替这些判断。
- 各M内部的D可以独立侦察并发现突破口，V经真实领域讨论后形成各自的持续研究线路。公共层不替所有M预选相同的反叛题目与领域；公开材料可以共享，研究责任不分摊成全任务一套D/V。具体权责采用后续更新准备稿，而非现版“V永不通信”的旧约束。
- 各M为领域研究安排实际可工作的资源与阶段，支持D/V自主发展材料、方法、工具及竞争成果。更强路线可以成为本线当前候选，由掌握路线的作者带动关键生产；面向用户的综合责任继续由本线承担。临时生产主导迁移不自动增加M，也不改写已经发生的工作、计数与时钟事实。
- **候选定型与本线承诺完成分开报告。** 定型可以结束当前活动并保留候选；若硬下限尚未由可信事实验证，执行责任仍标未完成。软目标未达照实说明，不靠等待填时间，也不把未知说成完成。
- 各线不必同参数、同轮次或同时结束。已定型线只在相关新事实会改变其结论时再入；等待另一组不延长有效时间。恢复接续已有成果、计数和可靠时间记录，不重新清零。

M增加的是完整推进能力与责任。共享原件、已获取资料和确定性工具可以减少重复；不能把一次D报告、一项共同综合或同一成果复制记入多组。费用上限、用户停止、正式发布权属于同一个委托，不按M复制。

## 公共交互面负责什么

使用已有原生消息、分线候选与一份公共当前摘要即可开始。需要保留的是会改变下一行动的信息：

| 信息 | 实际处理 |
| --- | --- |
| 用户纠正、确认原件事实、资源冲突 | 及时送给受影响M，不等议会；接收方处理已产生后果及下一动作 |
| 本线参数、当前问题、公开进度 | 按实际状态发布，区分已发出、已返回、已处理和已落实 |
| 未定方案与初步结论 | 先有独立判断/可检验样本，再按真实分歧发布；不从开头广播答案 |
| V的研究与质疑 | 分域后保持独立判断；经所属M保留原主张地转交必要问题、事实、候选及跨领域交流，不交换全体私有笔记，不因Main当前不理解某领域就默默过滤其中心问题 |
| 最终内容取舍与主线迁移 | 比较中心主张与真实整体成果；选择更强路线时改变下一阶段的生产方法与主导者，综合者继续负责实际交付 |

公共层不假称看见全部私有过程或能强制取消在途工具。发送纠正、暂停或停止请求，不代表已经生效；已产生的错误结果仍要处理。记录公开摘要、原件位置与实际后果，不记录隐藏思维链，也不建立全量聊天审计平台。

各M只写自己的候选/笔记，原件只读共享。共同摘要和正式成品由明确发布者落实，避免多个M抢写同一文件。用户得到一个当前结果入口。

## 议会怎样产生结果

基本过程是：**独立开题与关键样本 → 公开可比较候选 → 针对决定结果的分歧质疑 → 必要补查或试作 → 各自修订/保留 → 整体选择或兼容整合 → 明确落实。**

最终有汇合，但不要求等每组做完全部正式生产才第一次交流。当一项具体分歧可能改变路线时，可以有限交流；不是常态全员同步。用户纠正和共同事实始终及时共享。

三种分歧用不同办法：事实/行为争议回原件、反例或实际结果；完整构形差异比较代表性内容与用途；尚缺用户偏好的价值冲突保留清楚的备选。多数票、代理声望和意见一致不替代这些工作。

可以保留少数路线，可以选择一套完整基础，也可以借用兼容贡献。借用后仍要看当前整体：两段各自有来源，拼在一起却可能改变目标、指代和前提。新综合稿不能自动获得旧候选的认可或R记录背书。最终综合者要实际看决定性的材料、回应中心反证，并对成品负责。

有力量的整体构形拥有被整套采用的机会。融合会削弱其声音、结构或技术优势时，采用更有价值的整体，让掌握路线的工作线继续推动关键生产。公共综合者组织比较、落实和交付，不能把所有竞争成果都先压成旧方案的补丁；同样，各M内部D/V的强成果也能真正带动主线迁移。

对有实质突破潜力却暂未采纳的成果，在用户当前入口保留完整作品或路线及作者中心主张，连同综合者的取舍理由。独立成果能够直接被看见，避免只剩经过主线尺度过滤的摘要；展示集中于核心分歧，不向用户堆叠全部过程笔记。

异步收敛时，一组的稳定原件处理可以供另一组使用；另一组可继续重开，不要求稳定组补同样轮数。已确定的制作可先推进。最终仍比较整体方案，并分别说明每线承诺状态，不能用“已有成品”豁免未完成责任。

## 当前宿主下怎样放置M

公共职责可以兼任，不另加一个C参数。具体配置取决于初期独立输入与实际协调负荷：

| 情景 | 建议安排 | 当前4槽中的支持余量 |
| --- | --- | --- |
| 默认M=1 | root兼主线与必要公共协调 | 最多3槽 |
| 从头并行自举M=2 | root公共交互/最终综合；M01、M02为独立上下文 | 最多1槽 |
| 已有根实质初期候选后扩M=2 | root可继续兼M01，另开受控输入的M02 | 最多2槽 |
| 公共root与M=3均活跃 | 按阶段返回/空闲、恢复和轮换支持者 | 当时无支持余槽，不能宣称完整团队同时满编 |

子代理实质进度会自动进入root。root若也是尚未形成初期候选的竞争作者，不能看过返回后假称没受影响。已有真实候选时可保留其初期独立身份；之后修订如实说明受到交流影响。若确能在不削弱公开进度的前提下控制初期返回，兼任也可成立；不能只给角色改名。

从头多线时让root负责公共综合，是适应当前输出/注入条件的建议，不证明它普遍更快、更客观。该角色不另计M，也不免费；它须做实质内容综合，不能只收摘要。完整主进度是跨阶段责任，不等于每组固定人数或始终同时运行。纸面“暂停”不表示槽位已释放，以实际工具状态为准。

## T/t由谁记录，怎样汇总

每M判断并声明自己当前的MAIN/SOURCE/等待等活动。可信时间来源提供真实边界，工具保存区间、做算术；不由模型回忆分钟，也不由管理员从“agent running”猜活动。

先兼容当前范围：每线计其实际负责者的前台活动；T计MAIN+SOURCE，t计SOURCE。不因V读资料就给M转入相同时间。独占D/V、等待与纯运行协议维护排除；实质研究和返回综合按实际工作计入。

分别报告各M的目标、已知T/t、记录完整性与缺口；全任务有效经过时间取**各M及共同实质综合COMMON的区间并集**，COMMON只入全局一次，不反填各线。全局达到某个数值，不替任一M达到其目标。总代理劳动量若需要报告，另列为资源事实。

共用明确时基、保存可取回的原始边界即可；分线保存后正确归并同样成立，无须多人热写一个总文件。只有最终累计无法恢复重叠。迟到报告沿用当时真实留下的边界，不能按收到消息时间延长活动。中断缺口不补猜，可靠小计可保留；未知不是零，也不是已工作。恢复只开启新的真实活动段。

本轮构造示演含并行、断段、恢复、迟到和共同综合：M01已知22/8分钟，M02已知17/11分钟；全局已知并集28/14且不完整，错误相加为43/19。它支持计算与缺口处理，不是本轮真实M工作时长。另有本轮单主线UTC状态分段的实际观测，未声称自动检测中断或多M运行已接入。

## 调用与可见输出草案

以下为未来格式示例，不是本轮已运行M：

```text
DIGR(M=2)：任务

[DIGR INIT OK] DIGR（M（2））
责任作用域=各M完整承担并独立初始化；同一P_run。

[M01 INIT OK]
DIGR（N（12），T（45min），R（4），B（0），S（n（3），t（20min），r（1），b（0）），D（3），V（3），L（3））

[M02 INIT OK]
DIGR（N（16），T（60min），R（5），B（0），S（n（4），t（25min），r（1），b（0）），D（4），V（3），L（3））
```

两组值只示范可以不同，不是预编套餐。各组自行初始化后分别回传，公共入口公开该组真实生效值，随即继续该组实质工作；不等齐全部组，也不增加路线审批。等待公开初始化不算有效工作。未初始化的组不填猜测值，M目标不冒充实际启动或完成数。

中途保留既定色块、身份与分层过程，加M归属，例如**M02·N04**、**M01·R02**、**M02·D01**、**M01·V03.2**。各组实际调整时显示旧值→新值、理由、对当前问题/产物/下一步的后果；上调本身不算一次N。转发标明实际发生/采样时间，不把早先采样当新动作的精确结束。

返回先给用户结果，再给M（目标/有效运作主进度数），逐M展示符号（目标/实际）、时间完整性及内容定型/责任完成状态。不能用跨组总和掩盖弱线。有效运作数量也不等于所有线承诺均完成，须按线明示。默认M1保留现有返回格式并增加归属，不额外常设管理员。

## 放回之前的资料任务

上海端侧AI/推理优化、完整知识供给、原文剪拼、实践单列、英文先交与同选段中文，都是各M共同继承的已定要求。自主性不能把它们重新开放投票，更不能拿重写教材当不同路线。

若确需多M，它们应各自形成可评价的整套合法组织与关键原文样本，而非一组只找资料、一组只排版。相同原件可共享，问题表征与取舍独立；有相同结论也不强造差异。选定后由明确落实者生产一个成品，不把完整责任等同于把整本书翻译多遍。

对于已明确的下一批原文装配，M1可以直接推进并处理有价值的D/V返回。扩大M应当有真实的路线分歧或独立求解用途。参数数量不要求把已经明确的任务重新制造成开放研究。

## 实施范围与本轮所得

本轮已做：取得并固定运行协议；三条真实独立V及三项D研究；两种中心拓扑的同题构造试演、两种原文构形与交流修订样本、一次性多线计时算术/缺口示演；三线复看C7；形成这份当前设计。模型API调用、购买、持续服务和学习读物生产均为0。

本轮未做：发布M语义、修改manifest/VERSION/生效参数、部署真实M2群体、接入全部实时状态或自动中断恢复。设计可行性和构造示演不等于已观察到交付质量提升。

若实施，改动集中在Codex profile：PARAMETERS中的M单位与逐线作用域、PROTOCOL中的拥有/交互/汇合、HELP的调用和输出、WORKBENCH的分线空间及真实时钟接入，再更新版本与manifest。根stable/main入口不混入；不能只改说明就宣布计时可用。沿现有原生消息和轻量记录接入，不先建设通用总线服务或审计平台。

## 研究依据与限度

- [OpenAI Docs：原生多代理](https://developers.openai.com/api/docs/guides/responses-multi-agent)：提供独立上下文、协调动作和树内并发限制；M的责任与议会是DIGR拟新增语义。
- [OpenAI Docs：编排与所有权](https://developers.openai.com/api/docs/guides/agents/orchestration)：经理保留回复所有权与handoff是不同模式；不能只凭称号推断谁负责成品。
- [MAST](https://arxiv.org/html/2503.13657v3)：忽略返回、推理与行动不符等失败帮助定位真实反馈责任；不据此导入全套保障工程。
- [Smit等，ICML2024](https://proceedings.mlr.press/v235/smit24a.html)、[Wynn等，2025](https://arxiv.org/abs/2509.05396)：辩论收益有条件，也可能有害；不能把一致当正确。
- [Kim等，2026](https://arxiv.org/abs/2512.08296)：受控预算下架构效果依任务而变；不把其结果当DIGR组数/参数的普适最优证明。
