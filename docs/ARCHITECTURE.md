# DIGR 5.0.0-Berta1 Architecture

Berta1 separates five planes:

1. **Local candidate router:** lstrip plus exact-uppercase `DIGR`/`深度迭代` prefix capture only; no invocation semantics.
2. **Transport/navigation:** connector current stable HEAD, or same-attempt direct branch+Git-ref consensus → pinned manifest/VERSION agreement → sole pinned STARTUP slice.
3. **Host execution:** pinned STARTUP classification/parameter resolution, descriptor artifact verification, Clock Genesis, exact U0 binding, immutable contract, lifecycle and persisted evidence.
4. **Native intelligence:** StrategyState, Candidate, substantive N/R, source=auto decisions and optional quality-driven D.
5. **Recoverable delivery commit:** exact final bytes + media type + current Candidate binding are prepared and verified before `DELIVERED`; interruption stays non-success and recoverable.

`manifest.json` is navigation authority and `VERSION` is its pinned version check. `runtime-descriptor.json` describes generated execution/release artifacts after startup navigation. `dist/MODEL_PROTOCOL.md` is a compact release/advisory artifact, not a promised runtime fetch; manifest entry/core and their verified bundle remain execution sources. Deterministic runtime is an exoskeleton, not an intellectual planner.
